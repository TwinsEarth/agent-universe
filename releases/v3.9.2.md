# v3.9.2 — 比特币/以太坊 Agent 经济体（3/9）：EVM x402 / USDC 纯协议内核（402 challenge 校验 + EIP-3009 transferWithAuthorization 的 EIP-712 授权载荷构造 + facilitator 精确金额守恒校验；无依赖自实现 Keccak-256，只构造不签名，生产默认 X402_EVM_SIGNER_NOT_CONFIGURED fail-closed，不连 RPC / 不广播 / 不划转）

## 一、交付了什么

v3.9.0 决定「EVM 小额稳定币走 x402 轨道」，v3.9.1 立好「签名是宿主能力」的边界。
v3.9.2 把这条轨道上**沙盒可以安全做的纯协议部分**落地：校验 x402 的 HTTP 402
challenge、构造 EIP-3009 `transferWithAuthorization` 的 EIP-712 待签授权（给宿主签名服务
用）、以及对 facilitator 回执做精确金额守恒校验。本版本**不引入任何第三方 crate**
（仓内无 tiny-keccak/sha3/secp256k1/k256/alloy/ethers），Keccak-256 为零 unsafe 纯 Rust
自实现；不连 RPC、不广播、不划转、不兑换、不持久化，内核不读系统时钟（过期判定的
`now_unix` 由调用方显式传入）。

新增文件 `gsn-core/src/economy/payment/x402.rs`，并扩展 `payment/mod.rs`、`economy/mod.rs`、
`plugin/system/mod.rs`。复用 v3.9.0 已发版的 `PaymentTrack::EvmX402` 轨道枚举，不改
router.rs；复用 v3.9.1 的宿主签名闸门，不改 signer.rs。

1. **无依赖 Keccak-256**：纯 Rust 实现 Keccak-f[1600]（rate=136，Keccak 填充域 0x01/0x80，
   区别于 NIST SHA3-256 的 0x06），零 `unsafe`、无 panic。空串/`abc` 标准向量通过，另加
   一个 200 字节（>rate，多块吸收）向量，与独立实现 pycryptodome `Crypto.Hash.keccak`
   的输出交叉锚定。

2. **地址/nonce 值类型**：`EvmAddress([u8;20])` 与 `Nonce32([u8;32])`，带 `0x` 小写 hex
   序列化/反序列化与 `ZERO` 判定；反序列化严格校验长度与 hex 字符，坏输入类型化拒绝。

3. **x402 错误枚举 `X402Error`（14 变体）**：全部实现 `Display`（稳定 `X402_*` 前缀码）
   与 `std::error::Error`，生产路径无 panic。

4. **402 challenge 校验 `X402Challenge`**：字段 `scheme`（本版本只接受 `exact`）、
   `network`/`resource`（不得空白）、`pay_to`（EVM 收款地址）、
   `max_amount_required_raw`（u128，>0）、`asset`（合约地址 + decimals + symbol，
   decimals ≤ 36）、`deadline_unix`、`max_timeout_seconds`（>0）。
   `validate(now_unix)` 具名拒绝非 exact 方案、空白网络/资源/币种、零/负金额、非法精度、
   非正超时与已过期 challenge（`X402_CHALLENGE_EXPIRED`）。金额全程为整数 raw units
   （USDC 主网 6 decimals），零浮点。

5. **EIP-3009 授权构造 `X402Domain` + `TransferAuthorization`**：
   - `X402Domain{name,version,chain_id,verifying_contract}` 的 `separator()` 按 EIP-712
     对 `EIP712Domain(string name,string version,uint256 chainId,address verifyingContract)`
     求域分隔符（address → 32 字节左填 0，u256 → 32 字节大端）。
   - `build_authorization` 先 `challenge.validate(now)`，再按
     `TransferWithAuthorization(address from,address to,uint256 value,uint256 validAfter,uint256 validBefore,bytes32 nonce)`
     的 ABI 编码求 structHash，最终
     `digest = keccak256(0x1901 ‖ domainSeparator ‖ structHash)`，输出
     `TransferAuthorization{…, digest_hex, signature_hex: None}`——**只给待签 digest，
     不给签名**。
   - 两个 typehash 以**编译期 `[u8;32]` 常量**固化（避免任何运行期 hex 解析/panic），并保留
     等价 hex 常量；TRANSFER 常量经 EIP-3009 官方规范
     （eips.ethereum.org/EIPS/eip-3009）与双独立 Keccak 实现核定为
     `0x7c7c6cdb…1c1a2267`。

6. **facilitator 结算守恒 `verify_settlement(required_raw, paid_raw)`**：仅当实付金额
   **精确等于**应付金额才通过，多付/少付一律 `X402_SETTLEMENT_MISMATCH`，不静默接受差额。

7. **EVM 签发 fail-closed**：本版本无 secp256k1 宿主签名后端，`x402_sign` 对任何请求
   （含空/坏负载）一律返回 `X402_EVM_SIGNER_NOT_CONFIGURED` 具名拒绝，**绝不解析私钥、
   绝不伪造链上签名**。真正的 EVM 链上签发留待宿主注入 secp256k1 密钥后端（独立能力闸门，
   与 v3.9.1 同一隔离原则）。

8. **PMB 字节桥**（同一 T0 系统插件 `com.twinsearth.sys.payment-router`）：新注册
   `x402_challenge_validate` / `x402_authorize_preview` / `x402_settlement_verify`
   （只读）与 `x402_sign`（fail-closed），连原 v3.9.0/v3.9.1 共 7 个 handler；空/坏 JSON
   经统一 `parse_json::<T>` 助手类型化拒绝，不 panic。`payment_router_status` 增
   `x402_introduced_in=v3.9.2` 与 `x402` 诚实块（`produces_onchain_signature=false`、
   `evm_signer_configured_by_default=false`、`live_settlement=false`、
   `evm_rpc_connection=false`、`clock_read_in_kernel=false`、
   `exact_settlement_conservation=true`），`enforceable` 增
   `fail_closed_when_evm_signer_unconfigured=true`、`x402_exact_amount_conservation=true`，
   `provided` 增四个 x402 位；`capabilities_declared` 由 2 增至 3
   （加 `x402:protocol:read`）。

内核仍零浮点、零 syscall、零 unsafe、无生产 panic；不连任何链/RPC、不广播、不划转、
不兑换、不持久化、内核不读时钟。

版本映射：npm `@twinsearth/agent-universe` 3.9.2 ↔ Rust `gsn-core`/`gsn-daemon` 0.3.92。

## 三、诚实边界（做不到的具名拒绝）

- 本版本交付的是 **x402 纯协议内核（校验/构造/守恒）**，不是真网资金面：不连 EVM RPC、
  不广播交易、不划转 USDC、不做链上查询、不持久化 nonce/授权；`x402_sign` 因无 secp256k1
  宿主后端一律具名拒签，绝不伪造链上签名。要真实签发，宿主须在装配处注入 secp256k1
  密钥后端（独立能力闸门），与 v3.9.1 的 Ed25519 闸门同一隔离原则。
- facilitator 校验仅做**本地精确金额守恒判定**，不代表链上交易已确认；本版本不做链上
  回执查询/确认数跟踪。
- EIP-3009 授权的**链下重放/双花拦截**仍需有状态 nonce 账本（持久化），本版本只把
  nonce 纳入被签结构，不声称已完成重放拦截。
- typehash 与编码严格对应 USDC（FiatToken）EIP-3009 `transferWithAuthorization`；其他
  代币/方案（如 ERC-8335、ReceiveWithAuthorization 的不同类型串）不在本版本承诺范围。
- 闪电 L402 适配在 **v3.9.3**；ERC-8004 三注册表在 **v3.9.4**；ERC-4337 Paymaster 在
  **v3.9.5**；BTC HTLC/RGB 纯校验在 **v3.9.6**；链上锚定/跨链桥风控在 **v3.9.7**；
  ZK 支付意图/OWS/合规接口在 **v3.9.8**。在对应版本落地前这些方法不注册（NotFound）或
  只提供决策/校验面，不伪造真网可用。
- 文档中涉及的外部协议采用量/性能数字（x402 交易量、USDC 市值、Base 网络采用、BlackRock
  模型占比等）均为**第三方报道口径，非本仓复测**，内核不内置这些数字作为事实。
