# v3.1.0 — 业务插件化：官方插件真正承载业务逻辑（entry 模块 + 随内核自动装配）

v3.1.0 是 v3.0.0 一切插件化架构之后的**第一个中版本**。按版本语义，中版本是**新功能**：
本版不修改插件内核，而是让官方插件从“通用 exec 容器”升级为**真正承载业务逻辑**——
manifest 的 entry 字段被加载，信誉计算与市场匹配的真实算法以插件 entry 模块运行，且
9 个官方插件随内核自动装配。

## 一、要解决的问题（根因）

v3.0.0 虽建立了完整的插件框架，但存在一个“有壳无业务”的缺口：

- 官方插件在 process runtime 中只是通用的 `exec` 容器，manifest 的 `entry` 字段**从未被
  加载**；
- 真实业务算法（`overall` 信誉计算、`match_task` 市场匹配）仍留在单体 `marketplace/`
  模块里，插件并未承载业务；
- 且 `boot_system` 只注册 4 个 T0 系统插件，9 个官方插件**未在 boot 时自动装配**，
  首次 GET 只有 4 个系统插件，调用官方插件返回「插件未找到」。

v3.1.0 同时闭合这两处。

## 二、内嵌 entry 业务模块（plugin/official/mod.rs）

新增 `EntrySource { language, filename, source }` 与 `official_entry_source(name)` 查询，
把单体真实算法移植为插件内嵌 Python 模块：

| 插件 | entry 方法 | 移植来源 | 逻辑 |
|---|---|---|---|
| `com.twinsearth.official.economy-reputation` | `overall` | `marketplace/reputation.rs::MarketReputation::overall` | `overall = quality*0.35 + speed*0.20 + honesty*0.30 + availability*0.15` |
| `com.twinsearth.official.market-match` | `match` | `marketplace/mod.rs::Market::match_task` | 跳过 price≤0；`cost=reputation/price`；`latency_penalty=1/(1+latency_ms/1000)`；`score=cost*latency_penalty` 取最高 |

`market-match` 的边界返回：

- 空 bids → `{"winner": None, "reason": "no_bids"}`；
- 无有效 bid（全部 price≤0）→ `reason = "no_valid_bid"`；
- 命中 → `{"winner": <id>, "score": <分>}`。

其余 7 个官方插件暂为通用 exec 承载，`official_entry_source` 返回 `None`。

## 三、process runtime 加载与调用 entry（runtime/process.rs）

- `ProcessInstance` 增加 `has_entry: bool`；
- `spawn`：创建并启动后调用 `official_entry_source`，若存在则把 entry 模块写入隔离工作
  目录的 `plugin.py`，置 `has_entry = true`；
- 新增 `invoke_entry(method, payload)`：在隔离进程中生成引导——`import plugin` →
  `data = json.loads(<payload 字面量>)` → `getattr(plugin, method)(data)` → stdout 输出
  `json.dumps(out)`；exit 0 返回 stdout，非 0（如方法不存在，exit 2）返回类型化错误
  （含 stderr 末行）；
- `call` 分派：`exec` 保留通用代码执行；其他方法在 `has_entry` 时走 `invoke_entry`，
  否则返回 NotFound。

**注入防护**：

- 方法名必须是合法 Python 标识符（ASCII 字母/数字/下划线），否则拒绝，防止引导注入；
- payload 必须是合法 JSON；
- payload 用 `serde_json` 双层包裹成 Python 字符串字面量，方法名同样经 `serde_json`
  转义，杜绝引号/换行逃逸。

## 四、官方插件随内核自动装配（host.rs + node.rs）

新增 `PluginHost::boot_official()`，在 `boot_system()` 之后遍历
`official::bundled_manifests(version)`：

- 官方插件随内核构建、构建链路可信，故**跳过发布者签名校验**（与 T0 系统插件同一信任
  来源）；
- 但仍走 **process 进程隔离**与 **能力矩阵**：先 `arbiter.resolve_granted(manifest,
  Tier::Official)` 解析能力（越权提前失败），构造 `CapabilityToken`，再 `process.spawn`
  （写 entry）、注册 registry/bus、置 Running。

node.rs 在 `boot_system()` 后、`Arc::new(Mutex)` 前调用 `boot_official()`，成功打印
「官方插件已启动：9 个 T1」。

## 五、测试并行修复

- 工作目录命名为 `au-sandbox-{plugin_id}`，相同插件 id 的多个测试并行时会共享目录、
  互相 destroy（表现为 `python3: can't open file 'main.py'`）；
- 新增 `unique_rt()` helper（进程 id + 原子计数器，每个测试独立 base 目录
  `$TMPDIR/au-entry-test-{pid}-{n}`），全部 runtime 构造替换为 `unique_rt()`。

## 验证

- **全量测试**：`cargo test` **786 passed / 0 failed**（lib 251 + 集成 535）。
- **process runtime**：11 单测通过——reputation overall 精确值（1.0/0.8/0.6/0.4 →
  0.75，容差 1e-9）、market match 选中高信誉者（同价同延迟 rep0.5 vs 0.9 →
  winner=b）、空 bids winner=null、status、entry 方法缺失失败（exit 2）、非法方法名
  （`a;import os`）被拒，以及旧 exec/supports/third_party。
- **official 模块**：entry 来源函数测试（REPUTATION/MATCH 为 Some，其余 None）。
- **编译**：`cargo build` 零错误零警告；`cargo fmt` 已通过。
- **真实端到端**（临时 data-dir、API 4131、Bearer 认证）：
  - boot 打印「4 个 T0 系统插件 + 9 个 T1 官方插件」；
  - `call economy-reputation overall` → `{"overall": 0.75}`；
  - `call market-match match` → `{"winner": "b", "score": 0.008181818181818182}`；
  - 空 bids → `{"winner": null, "reason": "no_bids"}`；
  - `status` → `{"methods": ["status", "overall"], "tier": "official"}`。

## 边界说明（诚实，不夸大）

- 仅 **economy-reputation** 与 **market-match** 两个业务插件完成 entry 化，其余 7 个
  官方插件（agent-card、agent-skill、swarm-emergence、market-settle、scheduler-task、
  chain-anchor、chain-bridge）仍为通用 exec 承载，业务迁移在后续版本继续。
- entry 当前为 **Python**，跨平台依赖运行环境的 Python3；尚未以 WASM 原生承载。
- 已知未修项（沿用，不在本版范围）：node.rs/api.rs 仍有 `let _ = node.persist();`
  丢弃持久化错误；结算仍按托管总额付款而非中标价。
