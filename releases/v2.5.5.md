# Agent Universe v2.5.5 — Relay 节点池管理 + 多通道智能切换

发布日期：2026-09-26

## 概述

v2.5.5 在 v2.5.4（Circuit Relay v2 + AutoNAT + DCUtR + Ping，Mac↔Windows 跨网中继已验证）
基础上，解决**中继节点的长期可用性与多通道冗余**两大问题：

1. **Relay 节点池管理**：自动轮巡、发现、扩充、清理中继节点，容量随运行时间增长；
2. **方案 2 / 3 / 4 全部支持、任一失败自动切换**：改 NAT 环境、QUIC/UDP、多 relay 多通道。

## 新模块一：Relay 节点池管理

### 容量策略

| 项目 | 规则 |
| :--- | :--- |
| 初始上限 | **10,000** |
| 每月自动扩容 | **+10,000** |
| 硬上限 | **运行年限 × 100,000** |
| 手动扩容 | 支持（`manual_bonus`，可增可减） |

硬上限示例：

- 运行 10 年 → 100 万
- 运行 100 年 → 1000 万
- 运行 1000 年 → 1 亿

### Relay 四类分类（选择优先级）

| 分类 | 标识 | 优先级 |
| :--- | :--- | :--- |
| 专用 | `dedicated` | 0（最高） |
| 自有 | `self_hosted` | 1 |
| 第三方 | `third_party` | 2 |
| 通用 | `general` | 3（兜底） |

### 自动维护

- **每小时巡检一轮**：DHT 随机发现 → probe 不健康候选 → 补齐多通道 → 清理 dead 节点；
- 启动后 8s 执行首轮维护；
- Identify 发现支持 hop 的公网节点**自动入池**（池=候选库广泛收集，active=实际仅 3 条 reservation）；
- 节点连续失败 3 次标记 `dead`，dead 节点在巡检中被删除；
- 失效时按 DHT 候选与分类优先级**自动重新分配** relay。

## 新模块二：方案 2 / 3 / 4 与自动切换

| 方案 | 内容 | 状态 |
| :--- | :--- | :--- |
| 方案 2 | 改 NAT 环境（端口转发 / DMZ / 锥形 NAT），代码提供检测 + 引导 | 检测/引导持续完善 |
| 方案 3 | QUIC / UDP（UDP 打洞直连） | ✅ 真机验证 |
| 方案 4 | 多 relay 多通道同时在线同时通讯、智能切换（默认 3 条） | ✅ 真机验证 active=3 |

任一通道掉线/连接失败，`ensure_channels` 自动从健康池选节点补全到目标通道数
（常量 `DEFAULT_PARALLEL_RELAYS = 3`）。

## 真机验证结果

- 3 条 active relay 通道同时持有 reservation；
- QUIC 监听（`/udp/4001/quic-v1`）与 TCP 共存；
- relay 池 `current_size = 222`，容量快照正确（初始 auto_cap = 10,000）；
- 80s 多 relay **同时续期**，不断档、不累积；
- 移除一条通道后 **8s 内自动恢复** 3 条。

## 新增网络 API（前缀 `/api/v1/network`）

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET | `/relays` | relay 池报告（列表 + 容量快照 + 活跃通道） |
| POST | `/relays/add` | 手动加入 relay（`addr`, `class`） |
| POST | `/relays/remove` | 移除 relay 并关闭通道（`target`） |
| POST | `/relays/expand` | 手动扩容（`amount`） |
| POST | `/relays/discover` | 触发 DHT relay 候选发现 |
| POST | `/relays/ensure` | 立即补齐多通道 |

## 已知边界

- DCUtR 对**对称型 NAT** TCP 打洞成功率低（Windows 实测 3 轮失败，属网络拓扑限制、非代码缺陷）；
- 社区 relay（第三方）不保证长期在线，故由节点池自动发现与替换；
- 方案 2 的 NAT 类型精确判定与端口转发引导文本持续完善。
