# v2.7.5 — DCUtR 直连升级 + 多 relay 多通道同时在线

P2P 网络层增强：承接 v2.5.x–v2.7.4 的跨网组网工作（Mac Mini + Windows + 云电脑三端），把 relay 从"单通道被动中继"升级为"多通道同时在线 + 直连自动升级"。

## 新增功能

### 1. DCUtR 直连升级跟踪

经 relay 与对端建立连接后，libp2p 自动尝试 holepunching（DCUtR）打洞升级为直连。本版本把这个过程纳入可观测：

- `P2pPeer.direct_peers: HashSet<PeerId>`：记录已 DCUtR 升级成功的对端 peer。
- `P2pPeer.note_dcutr_event(&dcutr::Event)`：`result.is_ok()` 时插入直连集合，新插入返回 true 用于日志。
- `P2pPeer.direct_peer_ids() -> Vec<String>`：暴露已直连 peer 列表。
- `process_swarm_event` 的 `Dcutr` 分支：成功打 `⛏️ DCUtR 直连升级成功`，失败打 `⛏️ DCUtR 直连失败（继续走 relay）`，不影响现有 relay 中继。

直连成功后，该对端流量不再经过 relay 中继，延迟更低、吞吐更高；打洞失败时自动回退 relay，无感知。

### 2. 多 relay 多通道同时在线（方案 4）

v2.5.5 已实现 `relay_listeners: HashMap<String, ListenerId>` 与 `ensure_channels`，本版本把它正式作为网络默认：

- `DEFAULT_PARALLEL_RELAYS = 3`：默认同时持有 3 条 relay 通道。
- `relay_pool::select_parallel(&relays, n)`：按分类优先级（专用 > 自有 > 第三方 > 通用）+ fail_count 排序选至多 n 个健康 relay。
- `ensure_channels`：活跃通道 < 3 时自动补齐；relay 掉线（`ConnectionClosed` / `OutgoingConnectionError`）自动 `need_ensure = true` 触发切换。
- `/relays` 端点响应新增 `direct_peers` 字段，可同时查看活跃 relay 通道与已直连对端。

## 容量策略（沿用 v2.5.5，不回退）

- 初始 relay 池上限 1 万；
- 每月自动 +1 万；
- 硬上限 = 运行年限 × 10 万（10 年 100 万 / 100 年 1000 万 / 1000 年 1 亿）；
- 支持手动扩容。
