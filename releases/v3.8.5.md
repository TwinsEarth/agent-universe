# v3.8.5 — 面向 Agent 的资源市场（6/10）：托管结算守恒账本（EscrowLedger 五桶分账，整数千分点费率，罚没只出供给方应得，结算边界再守恒）

## 一、交付了什么

v3.8.2 的计量账本只**算出**每笔订单的整数结算视图 `MeterSettlement`
（`reserved_cost = consumed_cost + refund`），但一分钱不动；v3.8.4 的质押账本表达了
保证金的冻结/罚没，却没有定义罚没资金在一笔订单结算里的**去向**，也没有消费者锁定
的托管预留额如何在供给方/版税方/治理池/消费者之间穷尽分账。v3.8.5 新增**托管结算
守恒账本 `EscrowLedger`**：消费者下单时把预留总额锁进托管，结算时把这笔钱确定性地
穷尽分到五个互斥终局桶，并在结算边界强守恒。零浮点、零 syscall、零 unsafe、无 panic
路径，金额全 `u128` checked 运算，费率用整数千分点（permyriad，1000 = 100%）。

新增文件 `gsn-core/src/economy/resource/escrow.rs`。一笔订单锁定的
`EscrowOrder.locked_micro`（= 计量预留总额 `reserved_cost`）在 `Locked → Settled` 后
必被穷尽分到五桶（`EscrowSplit`）：

- `payout_provider_micro`：实耗中**归供给方**（扣版税、治理费、罚没后）；
- `royalty_micro`：实耗中按千分点抽给环境快照/技能创建者的**版税**（v3.8.6 消费快照）；
- `governance_fee_micro`：实耗中按千分点抽给治理池的**平台治理费**；
- `refund_buyer_micro`：实耗少于预留时**退回消费者**（= `MeterSettlement.refund_micro`）；
- `slashed_micro`：争议判罚中从供给方应得出账里**罚没截留**的终局部分（既不付供给方
  也不退买方，表达 v3.8.4 所言「罚没资金在分账桶中的归属」）。

核心守恒恒等式（每笔已结算订单恒成立，`EscrowSplit::conserves(locked)`）：

```text
locked == payout_provider + royalty + governance_fee + refund_buyer + slashed
```

分账口径（纯函数 `split_for_settlement(&MeterSettlement, FeeSchedule, slash)`，可独立
单测，不落账）：

1. 先在结算边界复核计量侧守恒 `consumed_cost + refund == reserved_cost`，不满足
   （探针/上游被污染）报 `RESOURCE_ESCROW_SPLIT_NOT_CONSERVED`，**绝不带错账分钱**。
2. 费率 `FeeSchedule{royalty_permyriad, governance_permyriad}` 构造时强校验两者之和
   `≤ 1000`，否则 `RESOURCE_FEE_RATES_EXCEED_TOTAL{sum}`；恰好 1000 合法（供给方候选
   应得可为 0）。费额按 `gross × permyriad / 1000` **整数向下取整**，取整余数留供给方，
   不凭空造出第 6 桶钱。
3. 供给方候选应得 `payout_gross = gross − royalty − governance`（checked）。
4. **罚没只能来自 `payout_gross`**（`slash ≤ payout_gross`），超出报
   `RESOURCE_SLASH_EXCEEDS_PROVIDER_PAYOUT{attempted,payout}`；消费者待退款 `refund`
   不参与罚没，不能拿待退款填罚没。终局 `payout_provider = payout_gross − slash`。
5. 账本 `EscrowLedger`：`lock(order, locked)` 开 `Locked` 记录（空 id/零额/重复具名
   拒绝），`settle(order, &ms, fees, slash)` 仅 `Locked → Settled`，且强校验
   `locked == ms.reserved_cost`（不一致 `RESOURCE_ESCROW_LOCKED_RESERVED_MISMATCH`）、
   重复结算 `RESOURCE_ESCROW_ALREADY_SETTLED`、未知单 `RESOURCE_ESCROW_ORDER_NOT_FOUND`；
   **先在纯函数里完成全部可能失败的分账，成功后才推进状态落账，任何失败仍停 Locked**。
6. `ResourceError` 新增 7 变体并补齐 `RESOURCE_*` Display；PMB
   `resource_market_status` 诚实位置 `enforceable.escrow_settlement=true`、
   `provided.escrow_ledger_persistence=false`，`stake_slash/onchain_payment` 仍 false。

   费/payout 全 0、全额 1000 退买方。

   slashed300、refund200 不动；罚 801 > 候选 800 拒绝；有费率（候选 720）时罚 721 拒绝、

## 三、诚实边界

- 托管账本是**确定性内存记账面**：不持久化、不跨进程/跨节点、不是全局单例；宿主市场
  门面持有它。本版只**算出**给定计量视图/费率/罚没额下唯一且守恒的五桶分钱结果，
  **不做任何真实资金划转、不托管真实代币、不连链、不经 PMB 受理外部写、不新增能力令牌**。
- **决策/资金分离**：账本不判定谁违规、不决定费率高低——费率由治理配置给入，是否罚没/
  罚多少由后续 BFT-lite QA（v3.8.8）/Agent 审判裁决给入；账本只保证守恒与「罚没只能
  出供给方候选应得、不罚消费者待退款」。
- `slashed` 在本版只表达分账桶归属（终局离开供给方、不退买方），**不做罚没资金的再
  分配落地**（进治理池/补偿买方/销毁的真实划转）与 v3.8.4 StakeLedger 的保证金罚没
  联动也在后续小版本；两者键不同（escrow 是订单维度、stake 是供给方维度），本版不强行对账。
- `royalty` 桶为 v3.8.6「快照商品化版税」预留金额出口，本版只按费率算钱，不接快照
  创建者身份与版税派发。真实 BTC（闪电/L402/RGB）、ETH/稳定币（x402/ERC-8004）结算、
  私钥隔离在 v3.9.x，本版一律不做。
- 外部数字（90% 沙盒 CPU<5%、超卖 50×、镜像访问 4.2–13.3%、x402/BlackRock/A402 等）
  仍为第三方报道、非本仓复测，仅作机制动机，不写进代码或作为已验证结论。
