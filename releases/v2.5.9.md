# Release v2.5.9 — 认证式 BFT、可失败独立审计、重放保护

**发布日期**：2026-09-27
**主题**：把 QA 验收闸门从"调用方合成委员与票"改为固定委员集的 Ed25519 签名投票；把审计从"与守恒同算法、零调用点"的自指检查升级为只信任只追加流水、独立重放的一等 API；为所有投票加入一次性 nonce 与时间窗，根治重放。三端（Rust / JS / Python）同步并以跨实现测试证明。

## 背景

v2.5.6 审计（GAP）暴露三类结算闸门缺陷：

1. **BFT 闸门可被调用方控制（GAP §3.1）**：旧 `POST /tasks/{id}/verify?approvals=3&committee_size=4` 由调用方传阈值，服务端据此合成 `qa-0..n` 委员并替它们投赞成票——调用方可以任意自我批准验收，委员会、签名、固定成员集都不存在。
2. **审计自指且零调用（GAP §2.4）**：旧 `audit_full_scan` 内部直接调用 `conservation_check`，两者同算法、同数据源，审计不可能发现守恒看不到的问题；且该函数在全仓没有任何调用点。
3. **变更接口无主体、无 nonce、可重放（GAP §2.5/§4.7）**：旧投票 / 验收不绑定认证主体，也没有 nonce 与时间窗，同一请求可被无限重放（可用于刷信誉）。

此外，充值 / 质押 / 托管在旧账本中直接修改余额、不留任何记录，无法仅从流水完整重放账目。

## 新增

### 1. 认证式 BFT-lite（签名投票 + 固定委员集）

- 新增 `SignedQaVote`（`gsn-core/src/marketplace/qa_committee.rs`）：
  - 字段 `task_id / round / voter / vote / nonce / issued_at / expires_at / signature`。
  - `signing_bytes()` 为固定多行格式（前缀 `AU-QA-VOTE`，投票以大写 `STOP/CONTINUE/SILENT`），不依赖 JSON 键序。
  - `sign(...)` 由委员 `Keypair` 用 Ed25519 签名后 hex 编码。
- `QaCommittee`：
  - `with_fixed_members(task_id, round, Vec<(did, [u8;32])>)`：绑定固定委员集，计算 `n`、`f=(n-1)/3`，登记每个委员公钥。
  - `cast_signed_vote(sv, now)` 顺序：委员在固定集 → 任务绑定 → 轮次匹配 → 时间窗 → 拒绝 Silent → **Ed25519 验签** → nonce 去重 → 计票；同一委员投出不同票（equivocation）整轮作废。
  - `advance_view()`：重置投票、轮次 +1，用于 NoQuorum / equivocation 后换轮恢复。
- `verify_result_authenticated(...)`（`mod.rs`）：固定委员集逐票验签后计票，按 Stop / Continue / NoQuorum 更新任务状态。

### 2. 可失败的独立审计一等 API

- 新增 `AuditReport` 与 `AccountMismatch`（`settlement.rs`，均序列化输出）：
  - `AuditReport { passed, replayed_records, replayed_deposits, replayed_slashed, expected_total, actual_total, aggregate_matches, mismatches }`。
  - `AccountMismatch { account, expected, actual }`。
- `independent_audit()`：
  - **只信任 `records`**，用有符号增量逐笔重放出每个账户的期望余额（checked 溢出即失败）。
  - 取重放账户与当前余额的**并集**逐户比对，覆盖幽灵账户 / 缺失账户 / 余额篡改 / 拆账。
  - 独立统计充值 / 罚没聚合，与引擎 `total_deposits / total_slashed` 及总额交叉核对。
  - 保留 `conservation_check` 作为快速自检，但审计结论独立于它。
- 暴露为一等 API：REST `GET /api/v1/audit`、MCP `market_audit`、CLI `gsn audit`、actor `audit()`。

### 3. 重放保护（nonce + 时间戳 + 过期）

- 每张签名票携带一次性 `nonce`，委员会用 `seen_nonces` 去重，重放即拒。
- 时间窗：`expires_at > issued_at` 且 `issued_at ≤ now ≤ expires_at`，过期票拒绝。
- 验签先于 nonce 登记，避免无效票 / 伪造票污染 nonce 集合。

### 4. 只追加结算流水

- `SettlementReason` 新增 `Deposited / Staked / Escrowed`；`deposit` 补流水，新增 `lock(...)` 在质押 / 托管转账时留痕。
- 结算支付（Completed）、退款（Refunded）、罚没（Slashed）全部记录；流水只追加、不可变，是独立审计的唯一信任源。

### 5. 三端同步

- **Rust**：`qa_committee.rs / settlement.rs / mod.rs / api/rest.rs / api/market_actor.rs / mcp/market_tools.rs / bin/gsn.rs`。
- **JS**（`js/lib/market.js`）：`verifyResultAuthenticated(...)`、`independentAudit()`、静态 `_voteSigningBytes` / `_verifyEd25519`（node:crypto）；constructor 增加 `records / totalDeposits / _seenNonces`，各记账点补流水。无 crypto 的 WKWebView 调验签时**抛明确错误而非静默通过**。
- **Python**（`aip/market_client.py`）：`verify_result(task_id, members, signed_votes, round)` 改为认证式 body（删除 query 阈值），新增 `audit()`。

关键反例测试：

- **守恒盲区**：把某一账户 100 拆成两个账户各 50（总额不变），`conservation_check` 仍判 `conserved=true`（被蒙蔽），`independent_audit` 判 `passed=false` 并列出两户 `expected/actual`。
- **伪造签名**：非委员密钥签的票、或签后篡改 voter，验签失败。
- **重放**：同一 nonce 在新一轮重复提交被拒；过期时间窗票被拒；非固定委员投票被拒。

## 说明 / 边界

- 认证式 BFT 要求调用方自行收集委员签名（客户端可用 `Keypair` / `SignedQaVote::sign` 构造）；服务端不再替调用方合成任何委员或票。
- JS 验签依赖 node:crypto；在无该能力的 WebView 中，签名验证必须经由 Rust Tauri command 或服务端完成，客户端不会静默判定通过。
- `swarm/collective.rs` / `swarm/consensus.rs` 的内部加权投票不在市场结算闸门路径，本次未改，留待后续评估。

## 兼容性

- 旧的 `?approvals=&committee_size=` 验收调用不再被接受（接口口径收紧，返回明确错误而非自我批准）。
- v2.5.7 / v2.5.8 的 DID、签名、整数金额、托管账户命名与结算语义保持不变；新身份仍用 `did:nau:`，上游 `did:aip:` 仍可解析验证。
