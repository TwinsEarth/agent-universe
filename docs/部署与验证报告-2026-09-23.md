## 六、Bug 诊断与修复

### 缺陷（真机可复现）

- **现象**：`gsn-daemon` 在命令行末尾接一个「需要值的选项」但缺值时直接崩溃。
- **复现**：
  ```
  $ gsn-daemon --data-dir /tmp/gsn-demo-data --listen
  thread 'main' panicked at src/bin/gsn-daemon.rs:31:46:
  index out of bounds: the len is 4 but the index is 4
  EXIT=101
  ```
- **根因**：`Args::parse()` 中 `--listen / --port / --api-port / --data-dir / --mode` 五个分支直接索引 `args[i+1]`，未校验 `i+1 < args.len()`；当选项位于参数末尾时越界 panic。
- **影响**：用户少打一个端口/路径就触发 Rust panic（退出码 101），报错对终端用户不友好。

### 修复（已落盘）

文件：`gsn-core/src/bin/gsn-daemon.rs`

- 新增辅助函数 `require_value(args, i, flag)`：当 `i+1 >= args.len()` 时，`eprintln!` 明确错误、打印用法并以 **exit(1)** 正常退出；
- 五个分支由裸 `args[i+1]` 改为 `require_value(...)`。

### 修复验证

| 场景 | 修复前 | 修复后 |
|---|---|---|
| `--listen`（末尾缺值） | panic, exit 101 | `错误: 选项 --listen 需要一个参数值…` + 用法, exit **1** |
| `--mode`（末尾缺值） | panic | 友好错误, exit **1** |
| `--help`（正常路径） | exit 0 | exit **0**（回归无破坏） |
| `cargo test` 全量 | — | **144 passed / 0 failed**（无回归） |
