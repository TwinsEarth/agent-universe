# v3.8.6 — 面向 Agent 的资源市场（7/10）：快照商品化版税账本（pack_diff 快照注册为商品，按次/复用版税三维累计，与托管 royalty 桶逐单对账）

## 一、交付了什么

v3.8.5 的托管五桶里预留了 `royalty` 桶，但它只按订单上一个聚合费率算出一笔版税额：
不知道这笔钱该付给**哪个环境快照的创建者**，也无法在同一 `pack_diff` 增量快照被
多次复用时累计版税。v3.8.6 把 AUSec 的增量快照（`pack_diff`/`snapshot_ref`）正式
变成可挂单商品，新增**快照商品化版税账本**：

- `SnapshotRegistry` 快照商品目录：`snapshot_ref → 创建者 DID + 版税千分点费率`；
- `RoyaltyLedger` 版税账本：每笔已结算订单按其恢复的快照记一次版税，按**快照维度、
  创建者维度、全表维度**累计，并与 v3.8.5 `EscrowSplit` 的 `royalty` 桶**逐单对账**。

新增文件 `gsn-core/src/economy/resource/royalty.rs`。纯确定性内存记账面：零浮点、
零 syscall、零 unsafe、无 panic 路径，金额全 `u128` checked，费率整数千分点
（`PERMYRIAD=1000`，1000=100%）。取整口径与 v3.8.5 完全一致：
`royalty = gross × permyriad / 1000` 整数向下取整，余数留供给方，不另造桶。

核心机制与守恒：

1. **快照注册** `register_snapshot(snapshot_ref, creator_did, permyriad)`：空引用
   `EmptySnapshotRef`、空创建者（复用 `EmptyProviderDid`）、费率 >1000‰
   `SnapshotRoyaltyRateExceedsTotal`、重复引用 `DuplicateSnapshotRef`，全部 fail-closed。
2. **按次版税** `accrue(order_id, Option<snapshot_ref>, gross, escrow_royalty)`：
   - 一笔订单只能记一次（`order_id` 全表唯一，重复 `RoyaltyAlreadyAccrued`），空 id
     复用 `EmptyOrderId`；
   - `Some(ref)`：快照必须已注册（否则 `SnapshotRefNotFound`），按其费率与 gross 算
     版税；算出值必须**等于**外部传入的托管 royalty 桶 `escrow_royalty`，不一致
     `RoyaltyEscrowMismatch{escrow,accrued}` 且**不落任何记录**；
   - `None`（订单未恢复任何商品化快照）：版税 0，此时托管 royalty 桶也必须为 0；
     若托管侧却记了非零版税（扣了版税却找不到受款快照），同样按对账不符拒绝。
3. **三维守恒**（`invariant_holds`）：
   `全表版税总额 == Σ 每个快照累计版税 == Σ 每个创建者累计版税`（三条独立求和路径
   必须相等）；每条引用快照的版税记录，其受款创建者必须与当前目录一致。
4. 查询：`total_royalty` / `total_for_snapshot` / `total_for_creator` /
   `restore_count`（快照被恢复计费次数，用于后续按复用率给创建者持续收益）。
5. `ResourceError` 新增 6 变体并补齐 `RESOURCE_*` Display；PMB
   `resource_market_status` 诚实位置 `enforceable.snapshot_royalty=true`、
   `provided.snapshot_royalty_persistence=false`，`stake_slash/onchain_payment` 仍 false
   （同步系统插件 status 快照测试）。

## 二、测试（旧实现无法表达的断言，8 新增）

`economy/resource/royalty.rs` 8 个，全部针对「此前托管 royalty 桶只有一笔聚合金额，
没有快照商品目录、没有受款创建者、无法按复用累计、无法保证『扣的版税==该付给快照
创建者的钱』」：

1. `register_and_basic_restore_accrues_creator_royalty`：注册 50‰ 快照，gross800 →
   版税40，快照/创建者/全表三维都=40，恢复次数1，不变量成立。
2. `floor_division_keeps_remainder_consistent_with_escrow`：gross100、33‰ 取整=3（余数
   留供给方），与 escrow 同口径；托管侧错记 4 触发 `ROYALTY_ESCROW_MISMATCH` 且不落账。
3. `duplicate_snapshot_ref_and_empty_ref_did_rejected`：重复引用、空引用、空创建者
   三类注册拒绝。
4. `royalty_rate_over_thousand_rejected_boundary`：1001‰ 拒绝并带 permyriad=1001；
   恰好 1000‰ 合法（gross100 版税100、供给方候选0）。
5. `unknown_snapshot_restore_not_found`：恢复未注册快照 `SNAPSHOT_REF_NOT_FOUND`，
   失败不污染账本。
6. `duplicate_order_accrued_only_once_and_empty_order_rejected`：同一订单重复累计
   `ROYALTY_ALREADY_ACCRUED`、空订单 id 拒绝。
7. `no_snapshot_order_requires_zero_escrow_royalty_else_mismatch`：无快照订单版税0 且
   托管桶必须0；托管侧扣了非零版税却无快照受款 → mismatch 拒绝，全表仍0。
8. `multiple_snapshots_and_creators_three_way_conservation`：两创建者三快照四订单
   （a1→40、a2→40、b1→25、无快照单0），全表105=Σ快照(40+40+25)=Σ创建者(80+25)，
   恢复次数/各维累计正确，不变量成立。

## 三、诚实边界

- 版税账本是**确定性内存记账面**：不持久化、不跨进程/跨节点、不是全局单例；宿主市场
  门面持有它。本版只**算出并累计**「某订单恢复某快照、按该快照费率该付创建者多少
  版税」，并保证该值与托管 royalty 桶逐单相等，**不做任何真实版税派发、不托管真实
  代币、不真实读取/校验 pack_diff 快照内容、不连 UDOS 分布式存储、不连链、不经 PMB
  受理外部写、不新增能力令牌**。
- `snapshot_ref` 在本版是**不透明字符串标识**：账本不假定真实 pack_diff 的存储格式、
  不做快照存在性/完整性/签名校验（镜像块 Ed25519 签名在 v3.7.x 已有独立面），只负责
  「引用 → 目录条目」的确定性解析与记账；真实快照存储、从快照恢复、轨迹分叉在
  AUSec/委员会侧，本版不接线。
- 版税只**记账不划转**：创建者累计版税表达「应得」，真实打款（稳定币/BTC/环境快照
  交易结算）、与 v3.8.4 StakeLedger 保证金/v3.8.5 EscrowLedger 的自动联动在后续；本版
  提供的是两账之间可单测的**金额对账**（royalty 桶==快照版税），不做自动资金搬运。
- 定价仅用快照注册时声明的固定千分点费率 + 按次累计；动态定价、稀缺度/信誉溢价、
  版税阶梯在 v3.8.9；四维信誉在 v3.8.7，BFT-lite QA 抽样验证在 v3.8.8。真实
  BTC（闪电/L402/RGB）、ETH/稳定币（x402/ERC-8004）结算与私钥隔离在 v3.9.x，本版不做。
- 外部数字（90% 沙盒 CPU<5%、超卖 50×、镜像访问 4.2–13.3%、x402/BlackRock/A402 等）
  仍为第三方报道、非本仓复测，仅作机制动机，不写进代码或作为已验证结论。
