# v3.8.9 — 面向 Agent 的资源市场（10/10，收尾）：动态定价 + 订单聚合 + 冷启动开关（整数千分点三因子定价永不破买方限价、同键同价小单 FIFO 聚批守恒、供给/容量不足确定性进自举期）

## 一、交付了什么

到 v3.8.8，资源市场已有「容量→计量→撮合→质押→托管结算→快照版税→四维信誉→
BFT-lite QA」的确定性记账/裁决链，但成交价在 v3.8.0 起就是挂单**静态单价**
（`unit_price_micro`），不随供需松紧、供给方信誉或任务时延敏感度变化；零散小单逐单
撮合也吃不到批量成本优势；网络早期没有足够供给/需求时更没有一个诚实的「自举」状态。
v3.8.9 作为资源市场 10/10 收尾，补三块**纯确定性决策面**（不动资金、不撮合、不连链）。

新增文件 `gsn-core/src/economy/resource/pricing.rs`。零浮点、零 syscall、零 unsafe、
无 panic 路径，金额 `u128` micro、率/倍率/压力比全用整数**千分点**（PERMILLE=1000，
1000=100%；信誉沿用 reputation 的 0..100000，100000=100.0），乘除全部 checked。

1. **动态定价 `DynamicPricer`**：在基准单价上叠加三个整数因子——
   - 稀缺度：`pressure = demand*1000/supply`（向下取整）。≥1000 按超出比例线性映射到
     `scarcity_max_up`（默认 +300‰，封顶）；<1000 按缺口比例映射到 `scarcity_max_down`
     （默认 −200‰）。`supply=0 且 demand>0` 具名拒绝 `ScarcityZeroSupply`（绝对稀缺不能
     伪造成封顶价）；都为 0 的空市场不调整，交冷启动开关决定。
   - 信誉溢价：读 v3.8.7 四维复合分 0..100000。≥50 分（REP_NEUTRAL）线性溢价至满分
     `reputation_max_up`（默认 +150‰），<50 线性折价至零分 `reputation_max_down`
     （默认 −200‰）；中性 50 分不调整。
   - 时延敏感度：`Sensitive` +100‰（交互/核心路径优先）、`Neutral` 0、`Tolerant`
     −150‰（批处理吃闲置算力）。
   - 三因子与基准 1000‰ 合成后 clamp 到有界区间（默认 floor=500‰、ceil=2000‰），再
     `base*mult/1000` 确定性向下取整。`quote_within_cap` 强制**永不静默突破买方限价**：
     建议价 > cap 返回 `PriceExceedsBuyerCap{computed,cap}`，由调用方显式改档/不成交，
     绝不压到 cap（压价会改供给方应得）。`quote_bootstrap` 在自举期只用一个更小倍率
     （默认 900‰，只许降价），**不铸造/不垫付任何资金**。

2. **订单聚合 `OrderBatcher`/`OrderBatch`**：把同资源键（provider/kind/unit）、同单价带
   的小单 FIFO 聚成批。首行定键，后续行异键或异价 `BatchKeyMismatch`；空 order_id /
   空 provider / 零量 / 零价 fail-closed；同 order_id 重复并入 `DuplicateBatchOrder`；
   并入后超 `max_batch_quantity` `BatchExceedsMaxSize` 且不改写；`new(max,target)` 要求
   max>0 且 1≤target≤max（否则 `BatchConfigInvalid`）。`seal()` 封批前做守恒自检：
   **Σ 行量 == 批量、Σ 行金额 == 总量×统一单价**，不符 `ArithmeticOverflow` fail-closed；
   对空批 seal 报 `EmptyBatchSeal`。`invariant_holds` 对全部已封批逐批复核。

3. **冷启动开关 `BootstrapGate`**：给定 `BootstrapConfig{min_providers,
   min_available_quantity}` 与正常聚合目标量，`observe(providers, available)` 确定性给出
   状态——任一维度（阈值为 0 的维度不参与）低于阈值即 `active`，并返回
   `batch_target_hint`（active→1，否则 normal_target）供调用方 `set_target`，同时定价切
   `quote_bootstrap` 补贴倍率。越过阈值确定性自动关闭。`normal_target=0` 报
   `BootstrapConfigInvalid`。

`ResourceError` 新增 12 个变体（NonPositiveBasePrice / ReputationCompositeOutOfRange{value}
/ ScarcityZeroSupply{demand} / PriceExceedsBuyerCap{computed_micro,cap_micro} /
EmptyBatchOrderId / BatchLineZeroQuantity / BatchKeyMismatch /
BatchExceedsMaxSize{requested,max} / DuplicateBatchOrder{order_id} /
BatchConfigInvalid{max,target} / EmptyBatchSeal / BootstrapConfigInvalid），复用既有
ArithmeticOverflow（不新增溢出变体），并在手写 `fmt::Display` 中补对应 `RESOURCE_*` 文案。

系统插件状态 `resource_market_status` 增加诚实位：`enforceable.dynamic_pricing` /
`order_batching` / `bootstrap_gate` 三个 `true`，`provided.pricing_persistence=false`；
`note` 顶部置 v3.8.9 边界说明，`stake_slash`/`onchain_payment` 保持 false。不新增能力
令牌、不经 PMB 受理外部写。`plugin/system/mod.rs` 快照测试断言三个新位为 true。

## 三、诚实边界（做不到的具名拒绝）

- **只产出建议价/批/开关，不改任何账**：本轮不修改 EscrowLedger/MeteringLedger/
  StakeLedger，不提交订单、不真实聚合执行、不联动撮合状态机；定价结果不回写成交价，
  是否采用由后续版本的撮合接线显式决定。
- **供需量与信誉分都是调用方入参，内核不采集**：不感知真实在线节点数、真实供需队列或
  信誉账本，不做节点发现（根种子/DHT 属网络层）；喂什么算什么，不担保入参真实。
- **「补贴」不发现金**：bootstrap 期只是一个更小的确定性倍率（默认 0.9×），没有任何
  铸币、垫付、空投或资金池；冷启动四阶段激励（内部需求自举/开发者奖励/外部消费者/
  治理去中心化）属经济层设计，不在本内核。
- **不持久化、不连链、不经 PMB 受理外部写、不新增能力令牌**：定价/批/开关纯内存函数；
  动态定价结果不入库、不上链；批不代表真实成交批次。
- 定价策略上下限/因子强度是宿主受控常量，本轮不做自适应学习、不做链上报价喂价。
- 真实 BTC/ETH/稳定币结算、支付路由、私钥隔离、ERC-8004 信誉锚定在 **v3.9.x**；
  本版所有数字（如愿景中的超卖 50×、延迟 45.2%→17.3% 等）均为第三方报道口径，非本仓复测。
