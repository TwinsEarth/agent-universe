# v2.6.9 — 文档与测试一致性 / 诚实标注

**范围**：本版不改运行时行为，只消除 GAP-ANALYSIS §5.1 / §7.6 / §8.6 / §9.6 / §9.7 指出的「文档/测试承诺 > 代码事实」问题，把尚未实现的能力显式标注出来，避免重演上游的过度承诺。

## 改动

- **§8.6 SSE 假流**：`gsn-core/src/mcp/sse.rs` 模块头不再宣称「SSE 长连接 / 服务端推送」。诚实说明 `handle_get` 当前只发送一帧 `event: ready` 后即关闭，真长连接（事件 id、重连续传、服务端推送）尚未实现；客户端应优先用 POST 无状态模式。
- **§7.6 假网络分区**：`gsn-core/src/llm/network.rs::probe_all` 注释诚实标注——它不做任何真实 I/O，只按 `reachable_from(region)` 静态谓词打标记；`EndpointHealth::{Failover, BlockedNoProxy}` 暂无触发路径，真实连通探测留给调用方注入。
- **§9.7 回归套件误导**：`test/regression.js` 头部加说明——REG-020/021/022/030/031 等断言跑在 `js/lib/market.js`（JS 参考实现）上，与 Rust 守护进程在负数存款、重复注册、托管上行为不完全一致；JS 全绿不构成 Rust 守护进程行为的保证。
- **§9.6 文档与实现不符**：`js/test/test.js` 头部注释从「14 项」改为实际的「20 项」。
- **§5.1 复核**：`src/net/memory_dht.rs` / `memory_gossip.rs` / `memory_node.rs` 三个内存替身此前已重命名并加「非真实 libp2p」模块头，本版确认无需再改。

## 不做（明确范围）

- 不实现真正的 SSE 长连接 / 应用层 GossipSub 数据面 / Kademlia bootstrap / DCUtR 驱动 / relay hop——这些是 GAP §5.1 的大工程，留待后续版本，本版只停止对外宣称。
