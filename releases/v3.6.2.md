# v3.6.2 — 修复自动更新对域名不可用（DNS 解析 critical）

v3.6.2 是 v3.6.1 之后的**补丁版本（patch）**，只修复一个在 v3.6.1 **发布后真实联网复测**中
发现的 critical 缺陷，不改动任何资金 / 共识 / 持久化 / 通道策略语义。

## 一、缺陷（v3.6.1 自身）

v3.6.1 的最小 HTTPS 客户端 `gsn-core/src/update/https.rs::get_once` 用

```rust
format!("{host}:{port}").parse::<std::net::SocketAddr>()
```

得到连接地址，再交给 `TcpStream::connect_timeout`。但 `SocketAddr::from_str`
**只接受 IP 字面量**（如 `104.16.0.1:443`），对任何**域名**（`registry.npmjs.org`、
`github.com`、对象存储域名）都必然返回错误。于是：

- `gsn update --check` / `gsn version --check` 与 daemon 启动后的后台检查，
  在真实环境一律报 `HTTP 错误: 无法解析地址 registry.npmjs.org:443`；
- 即 **v3.6.1 的自动更新对任何真实域名都连不上**，daemon 二进制下载同样不可用。

为什么本地关卡没发现：v3.6.1 的单测只覆盖了 URL 切分（`split_url`）与 HTTP 响应解码
（`decode_response`），**没有任何 DNS 解析 / 真实连接的回归测试**。这正重复了本项目对上游
审计时反复强调的那一类问题——「在修复前的代码上也能通过的测试，什么也没证明」。该缺陷只能
在发布后用真实域名联网时暴露。

## 二、修复

`gsn-core/src/update/https.rs`：

- 新增 `resolve_addrs(host, port)`：通过 `std::net::ToSocketAddrs::to_socket_addrs()`
  走系统 **DNS 解析**得到候选地址；解析失败或返回空地址列表都显式报错（不静默）。
- 新增 `connect_addrs(addrs, timeout)`：依次尝试解析到的 **IPv4/IPv6 多个地址**
  （Happy Eyeballs 的简化串行版），首个连通即用；全部失败时报最后一个错误。
- `get_once` 改为「先 DNS 解析、再多地址连接」，删除把 `host:port` 当 IP 字面量的 parse。
  SNI、TLS（rustls + webpki-roots）、跳转、响应体上限、读超时等既有逻辑保持不变。
- 新增回归测试 `resolves_hostname_via_dns_not_ip_literal_parse`：
  先断言旧写法 `"localhost:1".parse::<SocketAddr>()` **必然失败**（锚定缺陷确实存在），
  再断言新实现能把 `localhost` 解析出环回地址、IP 字面量仍可解析。**该测试在旧实现上失败。**

  `gsn update --check` 成功拉取 packument，输出
  `当前版本: v3.6.2（通道: Minor）` 并正确计算通道目标（不再报解析错误）。
- `cargo test`：**657 passed / 0 failed**（v3.6.1 为 656，净增 1 个 DNS 回归测试）。
- `cargo clippy --all-targets -D warnings`：0 warning；`cargo fmt --check`：通过。
- 静态关卡：生产代码裸 panic 0；`unsafe` 全部带 SAFETY（3/3）。
- 版本一致性：`scripts/check-version.sh` 通过（3.6.2 ↔ gsn-core 0.3.62，全声明点一致）。

## 四、存量 v3.6.1 节点如何到 3.6.2（重要，诚实说明）

v3.6.1 的更新器**自身连不上域名**，因此存量 v3.6.1 节点**无法靠自动更新自愈**到 3.6.2；
同时默认 minor 通道只跟 `x.Y.0` 基线、本就不会自动追补丁。请用下列任一方式升级：

1. **重装/更新 npm 包（推荐）**：
   `npm install -g --no-fund --no-audit @twinsearth/agent-universe@3.6.2`
2. **手动覆盖 daemon 二进制**：从本 Release 下载对应平台的原始二进制
   （`gsn-daemon-x86_64-unknown-linux-gnu` / `gsn-daemon-aarch64-apple-darwin` /
   `gsn-daemon-x86_64-pc-windows-msvc.exe`），先停 daemon，用其随附 `.sha256` 自行核对后
   替换现有可执行文件（Windows 下旧 exe 被占用需先停节点）。
3. 升级到 3.6.2 后，自动更新即恢复正常；此后 patch/minor 通道与手动 `gsn update` 均可用。

## 五、仍存在的诚实边界（未在本版解决）

- GitHub Release 的 Linux 原始二进制由 CI runner（Ubuntu 24.04，glibc 2.39）构建，
  在更老 glibc 的主机上直接运行会报 `GLIBC_2.39 not found`。不影响 sha256 校验；
  后续考虑降低 runner 基线或改 musl 静态构建（未决）。
- 本沙箱环境访问部分站点需经代理；更新器目前直连（npm/GitHub 在用户网络通常可直连）。
  代理（`HTTPS_PROXY`）支持未在本版实现，按需在后续版本评估。

## 六、与 v3.6.1 的关系

v3.6.1 的功能（npm registry 权威源、minor/patch 双通道、先锋白名单、手动跨大版本、
sha256 fail-closed 原子替换、npm 同步、三平台原始二进制资产）**全部保留**，本版仅修复其
联网落地环节。
