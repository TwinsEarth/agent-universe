# v3.5.9 — 能力边界状态登记 + 库面模块诚实标注 + 历史条目勘误指针（#77 / DEV-01~05、DOC-05/F-4、DOC-08）

v3.5.9 是 v3.5.8 之后的**补丁版本（patch）**，纯**文档与模块注释**变更，**不改变任何
运行时代码与资金/共识语义**。它收尾审计 backlog 中「文档承诺 > 代码事实」的三项残留，
让已知缺口与库面模块的状态可被持续追踪、不再因版本推进而消失。

## 一、能力边界状态登记（DEV-01 ~ DEV-05）

新增 **[`docs/CAPABILITY-STATUS.md`](../docs/CAPABILITY-STATUS.md)** 作为随版本维护的
状态登记册，把此前分散、部分处于「沉默」状态的能力缺口逐条给出：最后陈述版本、
**当前代码事实**（以源码文本 + 生产调用点检索为准）、明确状态与方向。

| 编号 | 缺口 | v3.5.9 结论 |
|---|---|---|
| DEV-01 | LLM 客户端全 Mock | **明确未做（仍未闭合）**：gsn-core 无 reqwest/ureq/hyper 依赖；`llm/network.rs` 只是端点分组/故障转移配置，不发 HTTP；无流式、token 为估算 |
| DEV-02 | 自研应用层 P2P 数据面 | **明确决定**：不自研，网络发现/广播/打洞/中继采用 libp2p（Kademlia/GossipSub/AutoNAT/DCUtR/Relay），并写明理由；不计划重开 |
| DEV-03 | TEE / WASM / fault_tolerance / evolution | **明确未做（路线项）**：TEE 仅枚举与 quote 字段无验真；无 wasmtime/wasmer 依赖，WASM 承载类型化拒绝；后两者仅枚举 |
| DEV-04 | 对称 HMAC / 离线 anchor·bridge / 非长驻 outbox | **保持 v3.5.0 边界**：HMAC 防伪造但非非对称来源证明；chain 插件无 RPC/provider，离线构造；outbox 宿主代投、非长驻 |

维护规则写进文档：每条闭合时标注「已闭合 + 版本 + 证据」，**不得静默删除**。

## 二、库面模块诚实标注（DOC-05 / 自审 F-4）

经生产调用点检索核实：`topology/`、`scheduler/`、`memory/`、`swarm/`、`mesh/`、`nat/`
六个模块的公开类型**仅被 `lib.rs` re-export，不在 `gsn-daemon` 启动运行图中构造**
（`net/peer` 中的 `libp2p::Swarm` 是同名第三方类型，已在注释中提醒勿混淆）。

- `topology/`、`nat/` 的模块头早在 v3.5.3 已标注，本版不重复。
- 本版为 **`scheduler/`、`memory/`、`swarm/`、`mesh/`** 四个模块补齐「**库面/实验性，
  未在守护进程构造，运行面由 libp2p / 官方插件承担**」的头注释。
- `README.md` 核心模块表后新增「库面模块与运行面的区分」说明，避免把代码库清单误读为
  守护进程的实际运行能力。
- `docs/CAPABILITY-STATUS.md` 记录待决项 **D-1：这批模块「接线启用 or 收敛删除」**，
  给出判定标准与关闭条件。**补丁版刻意不接线、不删除**（接线改变运行行为属 minor，
  删除是公开 API 破坏属 major）。
