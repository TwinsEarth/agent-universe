# v3.7.7 — AUSec CPU 调度（1/3）：两级时延优先级 + 优先级与权重（patch）

## 一、交付了什么
本版为 AUSEC-DESIGN §3.1 中 v3.7.7 的交付：把 v3.7.5 预埋、仅用于内存回收排序的
`LatencyClass` 正式升级为一套**跨平台、纯确定性、零 syscall、零 unsafe** 的 CPU
两级优先级模型（新增 `gsn-core/src/ausec/cpu.rs`），并经系统插件
`com.twinsearth.sys.ausec` 暴露一个**只读** PMB 方法。不调用 cgroup cpu.shares/quota、
不调 sched_setaffinity、不做真实限速（真实竞争配额分配在 v3.7.8，突发准入在 v3.7.9）。

1. **两级时延优先级**
   - `LatencyClass::Sensitive`（时延敏感：Agent 交互主循环、通信总线等关键路径）
     数值优先级 `PRIORITY_SENSITIVE=2`；`LatencyClass::Tolerant`（时延容忍：后台批处理）
     `PRIORITY_TOLERANT=1`。仲裁结果里 Sensitive 组整体排前，先被保障，剩余算力才给
     Tolerant 组（真正"竞争下分多少"在 v3.7.8 建模）。
2. **同等级权重（千分点份额）**
   - 每个沙盒带 `weight`（缺省 `DEFAULT_WEIGHT=100`，合法区间 `1..=MAX_WEIGHT=10000`），
     同组内份额 = `weight / 组权重和 × 1000`（u128 中间运算，整数千分点，无浮点）。
   - 排序键完全确定：优先级降 → 权重降 → 申请量降 → `sandbox_id` 字典序；同一份输入
     无论元素顺序如何，结果条目顺序一致。
3. **信任仲裁：沙盒不能自我提级**——这是本版的安全核心。
   - 沙盒申报里的 `latency` 是**可伪造输入**。Sensitive 只允许宿主信任级
     **System（T0）/Official（T1）**；**Certified（T2）/ThirdParty（T3）自报
     Sensitive 一律 fail-closed**（`IllegalLatencySelfPromotion`，报错带实际级别）；
     **Blacklist 不参与调度**（`BlacklistedSandbox`）。
   - 缺省 `latency` 时按信任级安全默认：System/Official→Sensitive，其余→Tolerant；
     PMB 入口对**缺省 tier** 一律按 `third_party`（最小信任 fail-safe 默认，绝不默认给
     Sensitive）。低信任级即便想"抢关键路径"也抢不到。
4. **份额取整如实呈现**：三等权成员份额为 333×3=999，`weight_share_total_permille=999`
   如实给出，不伪称整数世界里恒为 1000；单成员组=1000、空组=0。

- 新增类型/函数：`CpuError`（10 个全具名错误变体）、`CpuSandboxRequest`、
  `EffectiveCpuEntry`、`CpuClassSummary`、`CpuPriorityModel`，常量
  `PRIORITY_SENSITIVE/PRIORITY_TOLERANT/DEFAULT_WEIGHT/MAX_WEIGHT`，解析器
  `parse_tier/parse_latency`，核心纯函数 `arbitrate_priority(capacity, requests)`。
- `ausec/mod.rs`：`pub mod cpu`、re-export（带 `CPU_*`/`parse_cpu_*` 别名避免与内存
  模块符号冲突）、常量 `METHOD_CPU_PRIORITY="cpu_priority"`、手写小写 JSON 的入口
  `cpu_priority_query(Value)`、字节桥 `handle_cpu_priority`（空负载按 `{}` 处理）、
  在单一 register 点注册一行；复用既有 `crate::plugin::tier::Tier` 与
  `ausec::memory::LatencyClass`，不重复定义信任/时延概念。
- PMB 入参：`{capacity_millis:u64(>0), sandboxes:[{sandbox_id, tier?:
  "system"|"official"|"certified"|"third_party"(缺省), latency?:
  "sensitive"|"tolerant", weight?:u32, requested_millis:u64(>0)}]}`；任一沙盒非法
  （空/重复 id、权重越界、申请为 0、低信任自报 Sensitive、黑名单）→ 整体 fail-closed，
  不返回部分结果。

## 二、测试（旧实现会失败的断言，8 新增）
- cpu.rs 7 个：Sensitive（system 缺省）排在第三方 Tolerant 前、两组计数正确；Certified/
  ThirdParty 缺省降 Tolerant 且自报 Sensitive 分别带 `certified`/`third_party` 被拒、
  Blacklist 拒绝；同组 100/300 权重 → 250‰/750‰、份额和=1000、权大者排前、空组=0；
  三个等权成员份额 333×3、组和如实=999（不伪称守恒）；乱序输入确定性按 id tie-break；
  capacity=0 / 空 id / 重复 id / 权重 0 与越上界 / requested_millis=0 全部 fail-closed、
  缺省权重填 100；`parse_tier/parse_latency` 接受合法值、拒绝未知值。
- mod.rs 1 个 PM 桥：经 `cpu_priority` 入口验证 system 缺省 sensitive 排前、tier 缺省
  按 third_party（Tolerant）；Certified 自报 sensitive 经 PM 入口 fail-closed（报错含
  「不得自我提升为时延敏感」）；缺 capacity、weight=0、非法 tier 全部拒绝。
- `cargo test --lib ausec` **81/0**；全量 gsn-core **lib 436 passed / 0 failed**
  （较 v3.7.6 的 428 增 8）；`cargo fmt --check`、
  `cargo clippy --all-targets -D warnings` 干净；check-no-panics 生产 panic=0；
  check-unsafe-containment 全收容（仅 winjob.rs 3 unsafe/3 SAFETY，本版新增 cpu.rs
  **零 unsafe**）；`cargo metadata --locked` 通过；npm 3.7.7 ↔ gsn-core 0.3.77。

## 三、诚实边界
- 本版只交付**优先级模型与权重的确定性仲裁**，是调度策略的"决策面"；**不执行任何真实
  CPU 限速/绑核/配额**——没有 cgroup、sched_setaffinity、时间片抢占。输出的优先级与
  份额不能被解读为"内核已经按此分配了 CPU"。外部参考中"节点 50% CPU 被占时，时延
  敏感任务延迟影响从 45.2% 降到 17.3%"是 **aiwiki.ai / byteiota.com 对 DSEC 的报道、
  非本仓复测**，将仅在 v3.7.8 的竞争配额分配仿真里**引用为目标口径**，不在本版声称
  复现。
- `capacity_millis` 在本版只登记、**不参与容量约束**（不因申请总和超容量而拒绝）；
  竞争下的确定性配额分配在 v3.7.8，突发涌入准入与统一 `ausec status` 在 v3.7.9。
- 信任仲裁只在"宿主已按插件清单前缀正确裁定 `tier` 并传入"的前提下成立；tier 不由
  沙盒自填（PMB 入口缺省 third_party，宿主装配层应以后置裁定的真实 tier 覆盖）。
- 权重份额是整数千分点，取整误差以 `weight_share_total_permille` 透明暴露，调用方
  不得假设组内份额严格守恒为 1000。
