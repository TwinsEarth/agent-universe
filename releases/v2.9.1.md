# v2.9.1 — 沙箱能力声明闸门（默认不执行）、生产 panic 归零、快照持久化告警、cargo fmt 关卡

把参考项目 NewAgentUniverseByDeepSeek（clean-room 重写，只读对照）已验证的 **Agent Sandbox 安全
机制**移植到本项目。核心原则一句话：**边界要么由代码强制执行，要么让请求失败——绝不接受一个
策略然后静默忽略它。**

## 一、沙箱能力声明系统（G1，核心）

新增 `sandbox/capability.rs`：

- **`Capability` 枚举**：12 项安全边界（`#[non_exhaustive]`，snake_case，含 `as_str` / `ALL`）——
  EnvAllowlist、OutputCap、WorkDirIsolation、NetworkDenyAll、NetworkAllowList、FilesystemConfinement、
  Timeout、MemoryLimit、CpuLimit、DiskQuota、ProcessCountLimit、OpenFileLimit。
- **`Waiver { boundary, justification }`**：显式、带理由的豁免，理由非空。
- **`CapabilityDeclaration`**：`new()` 强制理由非空、不自相矛盾、unenforced 排序；
  `require/enforces/check`；`check` 是唯一消费者——
  - 后端 **enforces** 该边界 → Ok；
  - 否则找到对应 **waiver 且理由非空** → Ok；
  - 否则报 `PolicyNotEnforceable`（具名边界 + 后端 + 原因）。
- **`process_declaration()`**：按平台返回真实能力表（见下表）。

| 平台 | 进程后端可强制 | 进程后端无法强制（无 waiver 即拒绝） |
|---|---|---|
| 全平台 | EnvAllowlist、OutputCap、WorkDirIsolation、Timeout | NetworkDenyAll、NetworkAllowList、DiskQuota、FilesystemConfinement |
| Unix 额外 | MemoryLimit、CpuLimit、ProcessCountLimit、OpenFileLimit（`ulimit -v/-t/-u/-n`） | — |
| Windows 额外 | MemoryLimit、ProcessCountLimit（Job Object） | CpuLimit、OpenFileLimit |

`runtime/process.rs`：create 在 validate 后遍历 `cfg.required_boundaries()`，逐条
`process_declaration().check(cap, &cfg.waivers)?`；Unix `build_platform_command` 加
`ulimit -v`（mem_mb×1024）、`ulimit -t`（CPU 秒）、`ulimit -u`、`ulimit -n`，均 `|| exit 200`，
随后 `exec` 替换 bash（无孤儿）。

`config.rs`：`SandboxConfig` 加 `waivers`、`required_boundaries()`、`trusted_local(justification)`
（3 个 waiver：NetworkDenyAll / FilesystemConfinement / DiskQuota）；cpu_millis 重定义为
"累计 CPU 时间上限"默认 10000；**mem_mb 默认 768**（兼容 Node V8 CodeRange，256/512 实测 FAIL）。

`node.rs`：daemon 后端选择读 `GSN_SANDBOX_BACKEND`（默认 process）：
- process/real → `trusted_local`；
- none/off/null/disabled → 严格 default（create 被拒）；
- 拼错值 → eprintln 警告并按禁用处理（**安全配置 typo 绝不静默选中更弱后端**）。

## 边界说明（不夸大）

- **Windows 矩阵在 v2.9.2 才加入**（v2.9.1 CI 仅 ubuntu/macos）；Windows 专属 winjob.rs 编译由
  v2.9.2 的 windows-latest 矩阵覆盖。
- **静态关卡（panic/unsafe 机械检查）在 v2.9.2 才接入 CI**；本轮脚本已就绪但不随 v2.9.1 提交。
- Unix/macOS 进程后端对网络/FS/磁盘无强制原语，需 `trusted_local` 显式 waiver；这是能力缺口
  （宿主级边界），不是安全漏洞。
- **Node 内存限制是分机制的**：JS 对象堆由 `--max-old-space-size` 精确限制（mem_mb-96，
  Linux/macOS 均生效）；Buffer 属外部内存，不受该 flag 限制，Linux 上由宽松 `ulimit -v`
  （至少 2GB，容纳 V8 虚拟预留）兜底。即无 cgroup 环境下，Node 最坏总内存可能高于 mem_mb
  （Buffer 侧），但不能无限分配。
- **macOS 内存限制对 Python 无原语**：macOS 内核不支持 RLIMIT_AS/VMEM（`ulimit -v` 失败或
  静默无效，此前导致所有 spawned 测试 exit 200）。故 macOS 跳过 -v，`trusted_local` 增加
  MemoryLimit waiver（带理由）；Python 内存靠宿主级边界，Node JS 堆仍由 heap flag 限制。
  ulimit -t/-u/-n（CPU/进程数/句柄）在 macOS 仍生效。
- 结算仍按托管总额付款（中标价已持久化并作为下限；差额退款留待后续）。
