# Release v2.6.2 — 版本唯一来源、合约可部署、纠删码真修与网络替身诚实化

**发布日期**：2026-09-28
**主题**：把版本号从"手工登记、已漂移"收敛为根 `VERSION` 唯一权威来源 + `check-version.sh` 全仓一致性断言（CI 强制）；重写此前 4 个中 3 个不可部署的 Solidity 合约并接入 Hardhat 真实编译与逐缺陷测试；把进程内网络替身从 libp2p 命名中剥离（`InMemory*`），用 `reed-solomon-erasure` 把"分片 + SHA256 哈希"的假纠删码替换为真实 Reed-Solomon；对 NAT 穿透与 TEE 的"标志位即能力"做诚实标注。

## 背景

v2.5.6 审计（GAP）剩余的一批"声称具备、实则没有 / 不可部署 / 静默跳过"缺陷在本版集中处理：

1. **版本号手工登记、已漂移（GAP §9.3）**：版本散落在十余个 package / Cargo / 常量中，靠人工记忆同步，长期丢三落四。
2. **合约 4 个中 3 个不可部署（GAP §9.4）**：编译即失败或逻辑断裂（ERC20Votes 自委托计票错误、锚定可被覆盖、结算向 address(0) 转账等）。
3. **网络替身冒用 libp2p 之名（GAP §5）**：`GsnNode / KademliaClient / GossipSub` 是纯 `HashMap` 内存实现，却以 libp2p 类型命名，易被误读为真实组网。
4. **纠删码是假实现**：所谓"校验片"只是数据片副本 + SHA256 哈希，数据片丢失即无法恢复。
5. **NAT / TEE 标志位即能力**：`detect_nat_type` 返回固定值、`connect` 直接假设成功；`with_tee()` 只置 bool，不实例化 enclave、不做远程证明。

## 新增 / 重写

### 1. 版本唯一来源与一致性断言（GAP §9.3）

- 新建根 **`VERSION`**：全仓版本号的唯一权威（当前 2.6.2）。`bump-version.sh` 第一步即写它。
- 新建 **`scripts/check-version.sh`**：读 `VERSION`，断言根 / js / client / desktop 的 package.json、`aip-sdk-py`（pyproject 与 `__init__`）、client / desktop 的 Tauri 壳 Cargo.toml、gsn-core Cargo.toml 全部一致；npm `X.Y.Z` ↔ Rust `0.2.(Y*10+Z)`。任一漂移以非 0 退出。
- `ci.yml` 新增 **version-consistency** job；`publish.yml` / `release.yml` 的 gate 均跑该断言。`bump-version.sh` 末尾自动调用。
- 修复 `bump-version.sh` 表格刷新 awk：表格"说明"列中的 markdown 转义竖线 `\|` 此前被 FS 误当字段分隔，导致含该符号的行"当前值"列不刷新（A5 滞后）；改为先保护 `\|` 再手动 `split`。

### 2. Solidity 合约重写并可部署（GAP §9.4）

- 重写四个合约：
  - **GovernorToken**（ERC20Votes）：修复铸造后自委托计票、委托只减不加、历史投票权 checkpoint。
  - **AgentCardAnchor**：未授权拒绝锚定、首次锚定不可改、校验同时比对 cid 与 agentDidHash。
  - **PoCVSettlement**：零资金任务拒绝、请求方不能自执行、非验证者不能投票、需验证者多数才置 Verified、结算改为 pull 领取（不再向 address(0) 转账）、争议时退款给请求方并罚没质押给国库。
  - **ReputationRegistry**（原 ReputationBridge）：仅 owner 加验证者、超范围分数拒绝、幂等提交、finalize 取中位数并要求法定人数、未知 agent 返回零快照不 revert。
- 接入 **Hardhat**（hardhat.config.js / package.json / .gitignore），`npx hardhat compile` 通过，**18 个逐缺陷测试全过**；ci.yml 新增 contracts-check job 跑真实编译与测试。

### 3. 网络替身隔离与诚实命名（GAP §5）

- `git mv` 并重命名三个进程内替身：
  - `net/libp2p_node.rs` → `net/memory_node.rs`，`GsnNode` → **`InMemoryNode`**
  - `net/dht.rs` → `net/memory_dht.rs`，`KademliaClient` → **`InMemoryKademlia`**
  - `net/gossip.rs` → `net/memory_gossip.rs`，`GossipSub` → **`InMemoryGossip`**
- 同步更新 `net/mod.rs`、`lib.rs` 根导出、`ffi/tauri.rs`、`ffi/uniffi.rs` 及相关测试。命名即说明：这些是进程内 `HashMap` 替身，不联网。

### 4. 真实 Reed-Solomon 纠删码

- 引入 **`reed-solomon-erasure` v6.0.0**（GF(2^8)，纯 Rust），重写 `erasure/mod.rs`：
  - `encode`：数据分为等长数据片（不足补 0）并计算**真实 RS 校验片**。
  - `decode`：按 index 放置存活分片、缺失置 None，由 RS 重建；丢失分片数 ≤ parity 时成功，**含数据片丢失靠校验片重建**；超额丢失明确报错。
  - `verify_parity`：用 RS `verify` 校验校验片与数据片一致性。
- 旧"校验片 = 数据片副本 + SHA256"实现移除。

### 5. NAT / TEE 诚实标注

- `nat/mod.rs`：模块文档与方法注释明确 `gather_candidates / detect_nat_type / connect` 不执行真实 STUN/TURN/打洞，指向 `net::peer::P2pPeer`（AutoNAT + DCUtR + Circuit Relay）与 `node` 中的真实穿透。
- `aca/runtime.rs`：`supports_tee` 字段与 `with_tee()` 标注为"能力声明标志"，不实例化 SGX/TDX/SEV-SNP/TrustZone enclave、不做远程证明。
- `aca/receipt.rs`：`tee_quote` 标注为仅随收据携带、本库不验证真实性。

## 说明 / 边界（未实现项，如实声明）

- **应用层 P2P 数据面未实现**：当前仅传输层（libp2p）就绪；进程内 `InMemory*` 替身不承载真实数据面，见 `net/mod.rs`。真实应用层消息处理属后续版本。
- **NAT 穿透 / TEE**：本版只做诚实标注，未在 `nat` 模块实现真实打洞、未对接任何 TEE attestation；真实穿透见 `net::peer`，TEE 待后续。
- **合约版本独立**：`contracts/package.json` 版本为 1.0.0，独立于 npm `VERSION` 演进，不随 bump 改动。
