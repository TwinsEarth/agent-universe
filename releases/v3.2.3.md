# v3.2.3 — 业务化 agent-skill：按技能发现智能体（discover）

v3.2.3 是 v3.2.2 之后的**小版本**。按版本语义，小版本只更新独立插件、对系统与其它插件
零影响。本版只做一件事：**把第 7 个官方插件 `agent-skill`（技能注册/发现）从"通用
exec 承载"业务化为随插件承载真实算法的 `discover` entry**。

## 一、要解决的问题（根因）

插件化重构后，9 个官方插件中仍有 3 个（agent-skill / chain-anchor / chain-bridge）是
**通用 exec 承载**：清单在、插件能跑，但真实业务算法仍锁在单体
`marketplace/mod.rs` 里，插件本身没有任何可调用的业务方法。

这正是本项目批评上游 `agent-universe` 的核心模式之一——**「没有调用点的修复不算修复」**：
一个声称"技能注册/发现"的插件，若没有真实的 `discover` 方法，就没有兑现能力。

本版选定 agent-skill，因为它在单体中有**真实、独立、输入输出明确**的算法
（`marketplace/mod.rs::discover_by_skill`，配合 `register_agent` 维护的技能反向索引）。

> 本版探查同时确认：**chain-anchor / chain-bridge 在单体中没有独立算法**——
> `chain/mod.rs` 全文仅 `pub mod pocv;` 并 re-export `PoCVVerifier/ProofOfComputation`，
> 不存在 anchor.rs / bridge.rs。按"不能凭空编造算法"的诚实原则，这两个插件本版**不
> 业务化**、保留为通用 exec 承载并明确标注。

## 二、业务化：discover entry（plugin/official/mod.rs）

新增 `SKILL_ENTRY`（Python），并在 `official_entry_source` 中把 `OFF_AGENT_SKILL`
映射到该 entry。spawn 时 entry 被写入隔离工作目录，call 时在隔离进程中
`import plugin` 并调用 `discover`——与 v3.1.0 起其它业务插件完全一致的承载方式。

entry 暴露两个方法：

| 方法 | 作用 |
|---|---|
| `status` | 返回插件 id、tier、方法清单（`["status","discover"]`） |
| `discover` | 移植 `discover_by_skill`，返回声明该技能的全部卡片 |

## 三、算法移植（与单体逐分支对齐）

`discover` 输入：

- `skill`：要查询的技能标签；
- `agents`：卡片列表，每个含 `agent_id`（或 `id`）与 `skills`（标签列表）。

算法步骤（严格对齐 Rust 单体）：

1. 取目标标签 `target = skill.strip().to_lowercase()`；`target` 为空 → 返回空结果；
2. **构建技能反向索引**（对齐 `register_agent` 的 `skill_index` 构建，
   `marketplace/mod.rs:208-214`）：遍历每张卡片声明的每个技能（strip + lower），
   把 `agent_id` 加入 `index[skill]`；
3. **精确匹配查找**（对齐 `discover_by_skill`，`marketplace/mod.rs:294-298`）：
   `ids = index.get(target)`，返回这些 id 对应的卡片。

关键语义：

- **精确匹配**（标签忽略大小写、忽略首尾空白后**相等**），不是子串包含。
  单体 `discover_by_skill` 用 `skill_index.get(skill.to_lowercase())`（精确），
  而 `search_agents` 才用 `contains`（包含）——两者不可混淆。技能 `"Python"` 命中
  查询 `"python"`，但 `"Python Developer"` 不命中查询 `"python"`。
- 同一标签重复声明时索引对同一 id 去重，返回的卡片不重复。

> 卡片标识字段在单体 `MarketAgentCard` 中为 `agent_id`；entry 兼容 `agent_id` 与 `id`，
> 缺 id 的卡片被跳过。本算法不涉及金额运算。

## 四、测试

### process.rs（新增 3 个隔离测试，在隔离进程中真实加载 entry 并调用）

- `agent_skill_discover_finds_agents_by_skill`：a、c 声明 python（c 为大写 `Python`），
  b 仅 rust，查询 `python` → count=2，命中 a、c、不命中 b；
- `agent_skill_discover_is_exact_not_substring`：查询 `PYTHON`，精确标签
  `Python` / `python` 命中，`Python Developer` 为包含、不命中 → count=2；
- `agent_skill_discover_no_match`：无人声明 `haskell` → count=0、agents 为空。

### official/mod.rs（更新单元测试）

`entry_source_for_business_plugins` 增加 `agent-skill` 的 `is_some()` 断言；
"其余 2 个"（chain-anchor / chain-bridge）断言 `is_none()`。
