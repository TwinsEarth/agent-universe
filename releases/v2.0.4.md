## 核心目标

修复 ShardMetadata counts 字段写入不一致问题，确保单一真相源。

## 问题描述

在 v2.0.0 中，`publish_card()` 方法在两个地方更新 counts：
1. 本地内存中的 `meta.counts[sid] += 1`
2. 写入 DHT 的 `meta.to_bytes()`

但如果 DHT 写入失败，本地 counts 已更新，导致内存与 DHT 不一致。

## 修复方案

```python
async def publish_card(self, card: Any) -> None:
    for cap in card.capabilities:
        meta_key = f"/aip/cap/{cap}/r/GLOBAL/meta"
        data = await self.dht.get(meta_key)
        meta = ShardMetadata.from_bytes(data) if data else ShardMetadata(capability=cap)

        sid = shard_of(card.did, meta.num_shards)
        await self.dht.provide(shard_key, self.peer_id)

        # 统一更新 counts
        prev = meta.counts.get(sid, 0)
        meta.counts[sid] = prev + 1

        # 先写 DHT，成功后再认为已发布
        await self.dht.put(meta_key, meta.to_bytes())
```

## 技术决策

| 决策 | 原因 |
|------|------|
| 先写 DHT 再确认 | 确保持久化成功 |
| counts 统一在 ShardMetadata | 避免多处维护 |

## 影响

- 无 API 变更
- DHT 写入失败时不会产生脏数据
