# Release v2.6.1 — 账本落盘与重放恢复、MCP 参数校验

**发布日期**：2026-09-27
**主题**：让只追加结算流水真正落盘并在重启后从流水完整重放恢复账本（余额 / 充值 / 罚没 / 已结算任务），根治"只写不读、账本不落盘"；把 MCP 工具的 inputSchema 从"两份手工列表、从不校验"升级为 tools/list 与 tools/call 共用的单一来源，缺必填 / 类型错误在进入执行器前返回 JSON-RPC `-32602`，杜绝静默降级。

## 背景

v2.5.6 审计（GAP）暴露两类基础设施缺陷：

1. **存储只写不读，账本从未持久化（GAP §6.1，严重）**：`PersistentStore` 建了 agents / tasks / kv_meta / relays 四张表，却**没有余额 / 流水表**；`load_agents / load_tasks / upsert_task` 全仓零调用点。daemon 打开数据库只打印计数，从不把状态载回 actor——actor 每次都以空市场启动。重启即丢账，资金守恒只在单次进程内成立。
2. **MCP schema 两份手工列表且从不校验（GAP §8.1，高）**：`market_tools` 手工声明 19 个工具定义，`call()` 里又是另一份手工分发；`get_money` 缺失 / 非整数时静默返回 `Money::ZERO`、`get_str` 缺失返回空串。server 在调用执行器前对参数零校验，错误参数被静默吞掉。

## 新增

### 1. 只追加流水的重放原语

- `settlement.rs` 新增 `ReplayedLedger { balances, deposits, slashed }` 与模块级自由函数 `replay_records(records) -> Result<ReplayedLedger, String>`：
  - **只信任流水**：按时间序逐条重放有符号增量——`Deposited` 向 to 加钱并累计充值，`Slashed` 从 from 扣钱并累计罚没，其余（Staked / Escrowed / Completed / Refunded / Rejected）按 from→to 搬运（仅正金额）。
  - 所有加减一律 `checked_*`，溢出即 Err，不静默回绕。
- `SettlementEngine::restore(records)`：用 `replay_records` 重建余额与充值 / 罚没聚合，从 `Completed` 流水重建已结算任务集合与 `total_paid`。恢复出的引擎再跑 `independent_audit` 必须通过。
- `independent_audit` 重构为复用 `replay_records`，消除审计与重放两份口径。

### 2. 账本落盘与 actor 持久化接线

- `PersistentStore`（`storage/persist.rs`）：
  - 新建 **`ledger_entries(seq INTEGER PRIMARY KEY AUTOINCREMENT, payload TEXT NOT NULL)`** 表；流水整条序列化为 JSON 存入，SQLite 事务保证不会出现半行。
  - 新增 `append_ledger_record / load_ledger_records / ledger_count`；`load` 对损坏 / 无法解析的行容错跳过，不使整个账本不可读。
- `AgentMarket`（`marketplace/mod.rs`）新增：
  - `settlement_records()`：当前只追加流水（持久化增量来源）。
  - `restore_ledger(records)`：从持久化流水替换结算引擎。
  - `snapshot_agents_for_store() / snapshot_tasks_for_store()`：把 Agent / Task 快照为持久化记录。
- actor（`api/market_actor.rs`）新增 `spawn_with_store(store)`：
  - **启动恢复**：`load_ledger_records → restore_ledger` 完整恢复账本；`load_agents / load_tasks` 真实调用（重启后可见 / 计数）。
  - **写后持久化**：每条写命令处理后，按 ledger 水位增量 append 新流水，并把 agents / tasks 快照 upsert（幂等，覆盖最新状态）。
- daemon（`node.rs run_daemon`）改用 `spawn_with_store(store.clone())`，打印"账本持久化，重启可恢复"。

### 3. MCP 单一来源参数校验

- `mcp/tool.rs` 新增 `validate_arguments(schema, args)`：
  - args 必须是 JSON 对象；required 缺失或被显式 null 占据判"缺少必填参数 '{name}'"。
  - 按 properties 的 `type` 校验实际提供、非 null 的参数（string / integer / number / boolean / object / array），不符判"参数 '{name}' 应为 {type} 类型"；未声明 / 复合类型不强拦。
- `mcp/server.rs`：`tools/call` 在调用执行器前用工具自身的 `input_schema` 跑校验，失败即返回 `McpError::InvalidParams`（**-32602**）。schema 与 tools/list 同源，不再是装饰。

## 修复

- 全仓版本统一到 **npm 2.6.1 / gsn-core 0.2.61**（`bump-version.sh` 自动计算 Rust 线 6*10+1=61）。
- 账本重启不再丢失；MCP 错误参数不再被 `unwrap_or(0.0) / unwrap_or("")` 静默降级。

关键反例 / 往返测试：

- **账本恢复连续**：充值 → 质押锁定 → 托管锁定 → 结算 → 罚没之后，取流水 `restore` 出新引擎；逐账户余额（requester 800 / agent 550 / stake 50 / escrow 50）、守恒总额、充值 / 已付 / 罚没聚合与原引擎逐一相等，恢复后独立审计仍通过。
- **drop / reopen 往返**：写入 agent / task 后 drop 关闭，重新 open 同库，load 回的 name / skills / stake / state / owner / budget 字段逐一相等。
- **同 id 后者覆盖**：同一 agent_id upsert 两次（不同 name / stake），load 只返回最新一条。
- **损坏行容错**：物理插入一条无法解析的 payload，`load_ledger_records` 跳过该行只返回正常记录，`ledger_count` 仍反映物理行数。
- **MCP 校验**：缺 amount / amount=null / amount="100" / amount=1.5 / account=7 / 参数非对象均被拒并指名参数；完整参数与可选参数缺失则通过。

## 说明 / 边界

- 持久化以**账本为权威完整恢复**（资金安全）；agents / tasks 的状态已落盘并在启动 load（可见 / 计数）。内存业务对象的**全字段**完整重建（Task 的 context / todo / trace 等 StoredTask 未含字段）不在本版本范围，后续版本扩展 StoredTask 字段后补齐。
- MCP 参数校验在服务端（Rust）强制执行；账本落盘是 Rust daemon 能力，JS / Python SDK 无需对应改动。
- `ledger_entries` 用 SQLite 事务 + JSON 列提供崩溃安全（不会出现纯文本追加日志的半行）；`load` 仍保留对损坏行的容错跳过。

## 兼容性

- v2.5.7–v2.6.0 的 DID / 签名、整数金额、发布即托管、认证式验收、状态机恢复边与证据闸门语义保持不变；新身份仍用 `did:nau:`，上游 `did:aip:` 仍可解析验证。
- MCP 客户端若此前依赖"错误参数被静默接受"，升级后会收到明确的 -32602，属于正确性修正。
