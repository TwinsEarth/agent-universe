# v2.8.5 — REST 认证闸门/CORS 白名单/状态转换表/罚没服务端定/终局拒绝可达

对应《v2.8.2 增量审计 / Gap Analysis》**§3.5（REST）/ §3.7【critical】/ §3.8 / §2.2.6**。
v2.8.2 的 REST 数据面与争议仲裁存在三类问题：

1. **REST 变更接口完全无认证**：Bearer 闸门只覆盖 `/api/v1/mcp`，而
   `POST /accounts/{acct}/deposit`（免费、无上限、无背书的信用）、
   `/disputes/{id}/arbitrate`、`/tasks/{id}/settle`、`/tasks/{id}/verify`
   全部公开在 4002 端口；同时 `Access-Control-Allow-Origin: *` 且无
   `Origin`/`Host` 校验、无请求体上限、无读超时（slow-loris）。
2. **状态转换被绕过、罚没金额由调用方决定**（§3.7）：`open_dispute` 直接
   `task.state = TaskState::Disputed`（绕过状态转换表，且能从终态 `Settled`
   改），`arbitrate` 无仲裁者身份、`slash_amount` 直接读请求体。
3. **终局拒绝不可达**（§2.2.6）：`reject_task` 逻辑完备却只在库层，
   REST/MCP 零调用点，`SettlementReason::Rejected` 只能由库触达。

## 根因

- HTTP 数据面的安全边界（认证、CORS、body 上限、超时）要么没有，要么只覆盖
  MCP 而漏掉 REST；通配 CORS 让“运维访问的任何网页都能驱动本地守护进程”。
- 争议/仲裁路径绕过了项目自己在别处新建的状态转换表，把“是否合法”“罚多少”
  都交给调用方；叠加 REST 无认证，任何调用者都能翻转任意任务状态并自定罚款。
- `reject_task` 写了能力却没有接线（没有调用点），按审计规则“没有调用点的
  修复不算修复”。

## 修复

### 1. REST 变更接口 fail-closed 认证（§3.5）

- 新增 `rest_authorize(method, auth_header)`：
  - GET/HEAD/OPTIONS 放行（只读）；
  - 配置 `REST_BEARER_TOKEN` 时，POST/PUT/PATCH/DELETE 必须携带
    `Authorization: Bearer <token>` 且匹配，否则 401；
  - **未配置令牌时默认 401（fail-closed）**，仅当显式设置
    `REST_ALLOW_UNAUTHENTICATED=1` 才放行（受信网络逃生口，打印警告）。
- 在读取循环中接入：所有 REST 变更路由经认证闸门，未认证返回 401。

### 2. CORS 白名单 + 请求体上限/读超时（§3.5）

- 新增 `compute_cors(origin)`：从 `REST_ALLOWED_ORIGINS`（逗号分隔白名单）
  读取，**仅命中才回显** `Access-Control-Allow-Origin` + `Vary: Origin`，
  消除通配 `*`；白名单外/无 Origin 一律不回显。
- 新增 `REST_READ_TIMEOUT_SECS`（默认 30）：读取循环用 `tokio::time::timeout`
  包裹，超时返回 408。
- 新增 `REST_MAX_BODY_BYTES`（默认 10MB）：`Content-Length` 或累计读取超限
  返回 413。
- 支持 OPTIONS 预检（返回 204）。

### 3. 状态转换表 + 罚没服务端定（§3.7）

- `open_dispute` 改为经 `state.transition(Disputed)`：**只有 Accepted/Running/
  Verifying/Rework 可发起争议**，Open/Matched 与终态（Settled/Slashed）一律拒绝。
- `arbitrate` 签名改为 `(dispute_id, arbitrator, guilty) -> (verdict, Money)`：
  - **仲裁者身份必填**（空/纯空白拒绝，拒绝匿名）；
  - 重复仲裁拒绝；
  - **罚没金额由服务端规则决定**：仲裁作恶罚没全部质押
    （`SLASH_RATE_ARBITRATION=100%`），不再读取请求体；
  - guilty：罚没全部质押、托管预算全额退需求方、Disputed→Slashed；
  - not_guilty：Disputed→Accepted，不罚没。
- 两条罚没路径统一为 `slash_stake_synced`（先改质押记录再扣账本，根治旧实现
  “只扣账本、质押记录不变”的口径不一致，§3.8）。
- 验收拒绝（settle reject）罚没比例由服务端规则定为 10%
  （`SLASH_RATE_REJECT`）。
- 证据等级提升移到**状态转换成功之后**（旧实现在转换前就把 `evidence_grade`
  升为 `Verified`，转换失败也无法回滚）。

### 4. 终局拒绝 reject_task 接线（§2.2.6）

- **REST**：新增 `POST /api/v1/tasks/{id}/reject`（`TaskReject` 路由）。
- **MarketActor**：新增 `MarketCommand::RejectTask`、`reject_task()` 方法与
  命令处理。
- **MCP**：新增工具 `market_reject_task`（参数 `task_id`）。

## 新环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `REST_BEARER_TOKEN` | 空 | REST 变更接口 Bearer 令牌；未配置时变更接口默认 401 |
| `REST_ALLOW_UNAUTHENTICATED` | 空 | 设为 `1` 时放行无认证变更（受信网络逃生口） |
| `REST_ALLOWED_ORIGINS` | 空 | CORS 白名单（逗号分隔），仅命中回显 |
| `REST_READ_TIMEOUT_SECS` | 30 | 读取/请求处理超时 |
| `REST_MAX_BODY_BYTES` | 10485760 | 请求体上限 |

## 边界说明（不夸大）

- fail-closed 仅在“未配置令牌”这一默认前提下成立；运维显式设置
  `REST_ALLOW_UNAUTHENTICATED=1` 等于自行放宽，已在启动时打印警告。
- 仲裁者身份只是“必填且可记录”，并不证明该仲裁者具备授权（授权名单/
  委员会成员服务端化属后续版本范围）。
