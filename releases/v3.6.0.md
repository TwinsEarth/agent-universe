# v3.6.0 — 新增运维 CLI：`gsn ledger verify` 与 `gsn doctor`（#78，minor）

v3.6.0 是 v3.5.9 之后的**次版本（minor，新功能）**，在不改动任何资金/共识/持久化
**写入**语义的前提下，为运维补两条**只读**命令：离线核验本地账本、一键诊断运行环境。
两命令复用守护进程自身的生产校验路径，**不另造一套会漂移的校验逻辑**。

## 一、`gsn ledger verify [--data-dir D]`

离线（不连接 daemon、不启动节点）核验 `<data-dir>/gsn.db`，依次执行：

1. **存在性**：数据库不存在 → 报 `MissingDb` 退出码 2，**绝不顺手创建空库**
   （避免「核验动作本身改变数据」）。
2. **坏行显式报告**：`load_ledger_records_checked()` 发现无法解析的流水行 →
   `CorruptRows(n)` 退出码 1，不静默跳过（GAP §3.6）。
3. **哈希链 + 锚定 head**：直接调用生产的 `PersistentStore::verify_ledger_chain()`，
   断链/哈希不符报**首个异常 seq**，锚定 head 不符报 `ChainBroken(u64::MAX)`，退出码 1。
4. **重放守恒独立审计**：`SettlementEngine::restore(records)` +
   `independent_audit()`（与结算前/REST `/audit` 同一生产路径），输出
   expected/actual 总额、aggregate_matches、账实不符账户数。

退出码：**0** 通过；**1** 链断/锚定不符/坏行/审计不通过；**2** 缺库/参数错/打不开。

**能力边界（如实陈述，不夸大）**：哈希链是 **tamper-evident（篡改可检测）**，不是
tamper-proof——能重写整份库并连锚点一起改的攻击者检测不到（与 `docs` 既有声明一致）。
离线重放验证的是**流水自身重放后的守恒**；离线 CLI 没有另一份在线余额可交叉比对，
在线账实交叉由运行中的 daemon（REST `/audit`、结算前审计）承担。

## 二、`gsn doctor [--data-dir D] [--api U]`

只读诊断三项并给出 OK/WARN/FAIL：

| 项 | 性质 | 说明 |
|---|---|---|
| CLI 版本 | 信息 | 仅用 `CARGO_PKG_VERSION`，**不新增**版本声明点（避免与权威 VERSION 漂移） |
| 本地账本 | **硬检查** | 复用 `ledger verify` 的 evaluate；缺库为非致命 WARN，链断/损坏为 FAIL |
| daemon 连通性 | 软检查 | GET `<api>/health`，900ms 超时；默认 `GSN_API`/`127.0.0.1:4002`；离线不致命 |

存在硬错误（账本完整性）退出 1，否则 0。

## 三、工程与测试纪律

- 两命令全程**类型化错误**，生产代码无裸 `unwrap/expect/panic`（沿用 no-panics 静态关卡）。
- 新增 **5 个 CLI 回归测试**，且每个都会在旧实现失败：
  正常链 PASS（expected=350）、缺库 `MissingDb` 且不创建文件、篡改 seq=1 payload →
  `ChainBroken(1)`、坏 JSON 行 → `CorruptRows(1)`、篡改 kv_meta 锚定 →
  `ChainBroken(u64::MAX)`。
- **真实 daemon 端到端冒烟**：起 daemon 充值 1000+250 → 停进程 → 离线 verify 对其 gsn.db
  报告 PASS（2 条流水、链 head 一致、重放守恒 expected=actual=1250、0 账实不符）。
