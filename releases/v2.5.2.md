# v2.5.2 - 网络分区感知与自动降级

## 一句话概述

国内/国外模型分两个独立网络组运行，无论在国内网络、国外网络还是跳转网络都能正确路由；外网不可达时自动降级为仅国内模型协商投票。

## 核心机制

### 1. 双网络组独立运行
- `DomesticRegistry` 和 `OverseasRegistry` 各自维护端点表和健康状态
- 国内端点在任何网络环境下都直连可用
- 国外端点在国内网络下自动切换到 `china_proxy_url`（镜像/代理）

### 2. 三种网络环境
| 环境 | 国内模型 | 国外模型 |
|---|---|---|
| 国内网络（Domestic） | 直连 ✅ | 自动切代理 URL |
| 国外网络（Overseas） | 直连 ✅ | 直连 ✅ |
| 跳转网络（Proxy） | 直连 ✅ | 通过代理 ✅ |

### 3. 自动降级协商
`RegionAwareDeliberation`：
- **正常模式**：国内外模型同时加入加权投票
- **降级模式**（外网不可达时）：自动丢弃国外模型，仅国内模型投票
- `downgrade_to_domestic()` 记录降级事件（丢弃了几个国外模型、保留了几个国内模型）
- `restore()` 外网恢复时自动切回

## API

```rust
// 创建路由
let mut router = NetworkRouter::new(NetworkRegion::Domestic);
router.probe_all();  // 健康检查

// 分区感知协商
let mut r = RegionAwareDeliberation::new(NetworkRegion::Overseas);
r.register_domestic(qwen_model);
r.register_foreign(gpt_model);
// 外网不可达时：
r.downgrade_to_domestic();  // 自动降级
let d = r.build_deliberation();  // 仅含国内模型
```

## 边界

- 所有健康检查为模拟（不发真实 HTTP）；生产环境替换 `probe_all` 为真实 TCP/HTTP 探测
- 国外端点的 `china_proxy_url` 为占位符，需用户配置实际代理地址
