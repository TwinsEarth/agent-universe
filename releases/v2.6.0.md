# Release v2.6.0 — 状态机恢复边、证据分级结算闸门

**发布日期**：2026-09-27
**主题**：为任务生命周期建立集中的合法状态转移表，补上两条此前缺失的恢复边（NoQuorum→Open、Rework→Running），消除 NoQuorum 吸收态；把证据分级（EvidenceGrade）从"有谓词、零调用点"升级为结算付款前的强制闸门；policy=None 的任务提交结果即验收、豁免证据门禁。三端（Rust / JS / Python）同步并以测试证明。

## 背景

v2.5.6 审计（GAP）暴露两类任务生命周期缺陷：

1. **NoQuorum 是吸收态（GAP §3.4）**：旧状态机中任务一旦进入 `NoQuorum`（本轮验收未达法定人数），没有任何出边——任务既不能重新开放、也不能换轮，永久卡死；`Rework` 同样缺少回到 `Running` 的恢复边。状态合法性散落在各方法里，没有集中的转移表。
2. **证据分级谓词零调用（GAP「证据谓词零调用点」）**：`EvidenceGrade::is_trustworthy()` 已定义，但全仓没有任何调用点。`settle_task` 只看 `envelope.is_success()`，信封缺失时甚至 `unwrap_or(true)` 放行——Unverified 结果、甚至没有结果也能结算付款。

## 新增

### 1. 集中状态转移表与恢复边

- `TaskState`（`gsn-core/src/marketplace/task.rs`）新增：
  - `can_transition_to(&self, to) -> bool`：集中的合法状态转移表，覆盖发布 / 匹配 / 提交 / 验收 / 结算 / 争议 / 仲裁全生命周期。
  - `transition(self, to) -> Result<TaskState, String>`：非法转移返回"非法状态转移：X → Y"。
  - **两条恢复边**：`Rework → Running`（返工后恢复执行）、`NoQuorum → Open`（无共识后重新开放）。
- `AgentMarket`（`mod.rs`）新增：
  - `resume_after_rework(task_id)`：显式校验前置态为 Rework，再经转移表回到 Running。
  - `reopen_after_no_quorum(task_id)`：显式校验前置态为 NoQuorum，再经转移表回到 Open。
- 全生命周期状态赋值统一改走 `transition`：匹配（→Matched）、提交结果（→Verifying）、验收（→Accepted/Rework/NoQuorum）、结算（→Settled），任何非法跳转都会被阻断。

### 2. 证据分级强制结算闸门

- `settle_task` 在状态检查后加入强制门禁：
  - 任务 `verification_policy` 非 None 时，结果信封必须存在（缺失即"任务缺少结果信封，无法核验证据等级，不能结算"）。
  - 信封 `evidence_grade.is_trustworthy()` 必须为真（Verified / CpuProto）；Unverified 返回"结果证据等级为 X（不可信），不能结算；请重新执行或升级证据等级"。
  - 闸门拒绝时不付款、任务状态保持 Accepted 不变。

### 3. policy=None 提交即验收

- `submit_result`：任务 `verification_policy = None` 时，提交结果直接转 Accepted（无需 QA 委员会投票）；否则进入 Verifying。
- 状态表新增 `Matched/Running → Accepted` 边以支持该路径。
- policy=None 同时豁免证据门禁：无结果信封或 Unverified 证据也可结算。

### 4. 接线与三端同步

- **Rust**：
  - actor（`api/market_actor.rs`）：`MarketCommand` 新增 `ResumeRework / ReopenTask`，handle 新增 `resume_rework / reopen_task`，dispatch 新增两分支。
  - REST（`api/rest.rs`）：新增 `POST /api/v1/tasks/{id}/resume`、`POST /api/v1/tasks/{id}/reopen`。
- **JS**（`js/lib/models.js`、`js/lib/market.js`）：
  - `TaskStatus` 新增 `NO_QUORUM`；转移表新增 `NO_QUORUM→OPEN`、`COMPLETED→NO_QUORUM`（`REWORK→RUNNING` 已存在）。
  - `Task` 新增 `markNoQuorum / reopenAfterNoQuorum / resumeAfterRework`；新增 `verificationPolicy / evidenceGrade` 字段。
  - `AgentMarket` 新增 `resumeAfterRework / reopenTask`；`completeTask` 支持证据等级与 policy=None；`settle` 加入证据门禁（不可信返回 `untrusted_evidence`，不付款）。
- **Python**（`aip/market_client.py`）：新增 `resume_after_rework / reopen_task`（证据门禁在服务端强制执行）。

## 修复

- 全仓版本统一到 **npm 2.6.0 / gsn-core 0.2.60**（`bump-version.sh` 自动计算 Rust 线 6*10+0=60）。
- 消除 NoQuorum 吸收态与 Rework 死路；结算不再 `unwrap_or(true)` 放行缺失 / 不可信结果。

关键反例测试：

- **NoQuorum 恢复**：1 票（< 法定人数 3）→ NoQuorum，`reopen_after_no_quorum` → Open，重新匹配 / 提交 / 验收 / 结算全链路成功。
- **Rework 恢复**：QA 判 Continue → Rework，`resume_after_rework` → Running；非 Rework 状态调用被拒。
- **不可信证据拒付**：Unverified 结果验收 Stop 进入 Accepted 后，`settle_task` 被拒（含"不可信"），状态仍 Accepted、未付款。
- **policy=None 豁免**：无 QA，提交 Unverified 结果即 Accepted，结算成功。
- **非法转移**：`Open → Settled` 等跨级跳转被 `transition` 拒绝；终态 Settled 无出边。

## 说明 / 边界

- 恢复边为显式操作：服务端不会自动重新开放卡死任务，需调用方在识别 NoQuorum / Rework 后调用对应端点（配合 view change / 重订）。
- 证据分级只决定"能否结算付款"，不改变验收投票本身；QA 票数决策仍按 BFT-lite。
- policy=None 适用于无需可信验证的低风险任务；涉及资金 / 高风险任务应保留 BftLite 策略与证据门禁。

## 兼容性

- v2.5.7 / v2.5.8 / v2.5.9 的 DID、签名、整数金额、托管账户、认证式验收语义保持不变；新身份仍用 `did:nau:`，上游 `did:aip:` 仍可解析验证。
- 旧的"无结果 / Unverified 也能结算"行为被收紧为返回明确错误，属于安全口径修正。
