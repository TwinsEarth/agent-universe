# v3.8.0 — 面向 Agent 的资源市场基座（1/10）：领域类型 + 资源单状态机 + 内部记账单位 + T0 系统插件只读状态

## 一、交付了什么

本版开启 v3.8.x「面向 Agent 的资源市场」中版本。第一性原理：**未来每个人都会有多个
Agent，它们闲置时，算力、存储、网络、Agent 能力都是被浪费的资源**；资源市场要把这些
闲置资源变成可挂单、可撮合、可结算、可治理的供给，沉淀为全球智能体网络与市场。

v3.8.0 只交付**确定性领域内核（决策/记账面）**：纯函数、整数记账、零浮点、零 syscall、
零 unsafe、类型化错误无 panic。它不真的撮合、不托管资金、不发链上交易——这些在后续
9 个小版本逐个落地。本版先把"账怎么记、单怎么走、能力谁有"这三件不可回退的底座钉死。

1. **四类闲置资源的领域模型**（`gsn-core/src/economy/resource/mod.rs`）
   - `ResourceKind`：`compute / storage / network / agent_capability`（对应算力/存储/
     网络/Agent 能力四种闲置形态），snake_case 序列化 + `ALL/as_str/parse`。
   - `MeterUnit`：`cpu_millis / gpu_millis / memory_mb_sec / storage_gb_sec /
     network_bytes / invocation / snapshot_restore` 七个多维计量维度。
   - `resource/catalog.rs`：每类资源的默认计量维度**只读静态目录**（容量注册在 3.8.1）。
2. **内部记账单位 `Credits`（u128 微单位，不挂法币、不挂链）**
   - 1 credit = `MICRO_UNITS_PER_CREDIT = 10^6` micro；只做整数运算。
   - `from_credits/from_micro/credits(向下取整)/checked_add`，溢出具名
     `RESOURCE_ARITHMETIC_OVERFLOW` 而非 panic/wrap。
   - 本版本 **fiat_pegged=false、chain_settled=false**：BTC/ETH/稳定币结算是 v3.9.x
     经济体的事，v3.8.x 全程只做内部守恒记账。
3. **资源单生命周期状态机（单一合法转移赋值点）**
   - `OrderState` 11 态：`drafted → published → matched → capacity_held → executing →
     metering → qa_pending → settled`，分支 `cancelled`（撮合/容量阶段可取消，进入执行
     后不可取消）与 `disputed → settled/slashed`（验证失败进仲裁，裁决后结算或罚没）。
   - `can_transition/transition`：越态、跳态、从终态转出、自转一律具名
     `RESOURCE_INVALID_TRANSITION`；`is_terminal` 标识 settled/slashed/cancelled。
4. **挂单/求购/成交的入场校验内核**
   - `ResourceOffer`（供给：provider_did/kind/unit/quantity/unit_price_micro/
     snapshot_ref）、`ResourceAsk`（求购：buyer_did/kind/unit/quantity/
     max_unit_price_micro/latency_sensitive），构造即做正数校验。
   - `ResourceOrder::match_offer_ask`：形态不符 `KIND_MISMATCH`、单位不符 `UNIT_MISMATCH`、
     求购限价低于供给价 `ASK_PRICE_BELOW_OFFER`，全部满足才建单（初始 `matched`），
     成交量取 `min(ask, offer)`；`notional_micro`（量×价）checked 乘法，是 3.8.5 托管
     守恒分账的待托管总额。
5. **五个资源市场能力令牌 + grant 矩阵**（`plugin/capability.rs`，见开发计划附录 B）
   - `market:resource:offer`（挂供给）、`market:resource:ask`（求购）、
     `market:resource:settle`（结算）、`market:stake`（质押）、`market:slash`（罚没）。
   - 授权矩阵：**ask** 对除黑名单外所有级别默认授予（消费者零门槛）；**settle** 仅
     T0 内核 / T1 官方结算插件（持有托管资金守恒分账权，认证/第三方即使声明也拒绝）；
     **slash** 仅 T0（Agent 审判/结算内核）；**offer/stake** 落入声明式档（T0 全有、
     T1/T2 声明式、T3/黑名单拒绝）。
6. **T0 系统插件 `com.twinsearth.sys.resource-market`（只读）**
   - 与 `sys.ausec` 同构：进 `system_ids()` / `bundled_manifests()` / 系统装配
     `register_handlers`，entry=native、无签名、不可热插拔。
   - PMB `resource_market_status`（无参只读）：版本 + 记账单位口径 + 11 态 + 5 能力 +
     **诚实位**（`enforceable.state_machine/matching_kernel=true`，
     `metering_ledger/escrow_settlement/stake_slash/onchain_payment=false`；
     `provided.order_lifecycle_advance/offer_ask_submit=false`）。未接线的方法明确不注册
     （NotFound），不伪造可用。

## 三、诚实边界

- 本版是**领域内核与只读状态**，不是可交易的市场：**不接受**真实挂单写入、**不撮合**
  在场订单、**不计量**真实资源用量、**不托管/不动任何资金**、**不连接**任何区块链或支付
  轨道。`match_offer_ask` 只是后续撮合器（3.8.3）调用的纯校验入场函数，不产生订单副作用。
- `Credits` 是内部整数记账单位，**不锚定法币、不锚定 BTC/ETH/稳定币、不代表可提取资产**；
  它只用于让守恒分账可被单测。汇率、支付、签名、私钥隔离全部在 v3.9.x，且届时私钥永不
  进沙盒。
- 资源市场内核被定为 **T0 系统插件**，是因为托管/守恒/罚没持有资金守恒权、与 AUSec
  沙盒底座同级；面向插件/进程的市场门面（挂单受理、撮合入口）将以 T1
  `com.twinsearth.official.resource-market` 在后续小版本提供，其结算仍回调本 T0 内核，
  避免把 u128 守恒面放进 process/JS 运行时。
- 愿景长文中的外部数字（约 90% 沙盒 CPU<5%、超卖 50×、镜像按需访问 4.2%–13.3%、
  1.71×、内存 −40.2%/−21.2%、x402 月交易量、BlackRock 79.1%/53.2%、ERC-8004 采用量、
  稳定币市值等）均为第三方报道/愿景材料、**非本仓复测**；本版不把它们写进代码或作为已
  验证结论，仅作为机制动机。
- 版本谱系说明：原 AUSEC-DESIGN §3.2/§3.3 曾把 v3.8 规划为 Agent 委员会/pack_diff、
  v3.9 规划为安全组织。按最新规划，**v3.8 重定义为资源市场、v3.9 重定义为加密 Agent
  经济体**；pack_diff 降级为 3.8.6 快照商品化所消费的能力，安全组织前移为市场/支付的
  信任依赖。旧规划段落将在本版文档 PR 中标 superseded 并指向新谱系，不抹历史。
