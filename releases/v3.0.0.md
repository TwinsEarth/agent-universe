# v3.0.0 — 一切插件化架构：插件内核、热更新/热插拔/热兼容、五级插件体系

v3.0.0 是自项目以来的**第三个大版本**。按版本语义，大版本是**架构重构**：本版把系统从
单体结构重构为「**一切插件化**」的内核，并从本版开始支持**热更新、热插拔、热兼容**
（兼容低版本、安全通信）。

设计哲学与网络结构的 Scaling Law 同构：智能体宇宙通过扩展智能体网络结构突破群体智能
边界，插件化架构则通过扩展**功能网络结构**来实现系统能力的弹性伸缩——靠结构扩展而非
单体膨胀。

## 一、架构总览

自上而下五层：

```
插件内核 Plugin Kernel   （注册中心 · 权限仲裁器 · 生命周期管理）
        │
插件总线 Plugin Bus      （消息路由 · 协议协商 · 依赖解析 · 版本仲裁）
        │
五级插件层               系统 / 官方 / 认证 / 第三方 / 黑名单
        │
沙箱隔离层               进程沙箱 · 内存隔离 · 网络隔离（WASM 为可选 feature）
        │
基础设施层               libp2p · Kademlia · GossipSub · CRDT · Reed-Solomon
                         Ed25519 · SQLite · EVM
```

## 二、插件内核组件（gsn-core/src/plugin/）

| 组件 | 文件 | 职责 |
|---|---|---|
| 注册中心 | `registry.rs` | 清单登记、同名同版本幂等、不同版本须走热更新；依赖图与环检测。 |
| 插件总线 | `bus.rs` | pub/sub + request/response；`PmbMessage` 路由；发送方校验、速率限制、违规计数（3 次隔离）。 |
| 权限仲裁器 | `arbiter.rs` | 清单签名校验 → tier 判定；能力令牌 `CapabilityToken` 签发。 |
| 生命周期 | `lifecycle.rs` | `PluginState` 状态机（Discovered…Quarantined）；合法状态边表；终态无转出边。 |
| 能力模型 | `capability.rs` | 能力式安全（capability-based），显式能力集，最小权限。 |
| 黑名单 | `blacklist.rs` | 黑名单条目、匹配、申诉、以新模块解封（仅新摘要可解封）。 |
| 清单 | `manifest.rs` | `PluginManifest`：信息、能力、限制、waiver、签名（含开发者签名 + 官方副签）。 |
| 宿主 | `host.rs` | `PluginHost`：装配、安装、启停、卸载、热更新、legacy 加载、调用。 |
| 分级 | `tier.rs` | `Tier` 五级；`from_name` 按 id 前缀自动判定。 |

## 三、五级插件体系

| 级别 | Tier | 承载 | 权限 | 热插拔 |
|---|---|---|---|---|
| 系统插件 | `System` (Ring 0) | 进程内 native | 全能力（内核接口） | 否（可热配置） |
| 官方插件 | `Official` (Ring 1) | 独立进程（WASM 可选） | 受限系统能力 | 是 |
| 认证插件 | `Certified` (Ring 2) | 独立进程 | 声明式能力 | 是 |
| 第三方插件 | `ThirdParty` (Ring 3) | 独立进程 | 最小能力，默认禁网 | 是 |
| 黑名单 | `Blacklist` (Ring -1) | 禁止加载 | 无 | — |

插件 id 遵循反向域名规则，前缀即分类：`com.twinsearth.sys.*` / `*.official.*` /
`*.certified.*` / 第三方发布者域名 / 黑名单精确匹配。

## 四、热更新、热插拔、热兼容

- **热更新（Hot Swap）**：新版本插件在独立沙箱预加载并初始化，成功后通过总线**原子切换
  路由**，旧版本进入优雅退出；新版本健康检查失败则**保留旧实例、自动回滚**。
  注册中心提供专用 `replace(manifest)` 路径（允许版本变更，与 install 的 `register` 区分）。
- **热插拔（Hot Plug）**：任意时刻加载/卸载，不影响其他运行插件；实例与状态机独立。
- **热兼容（ABI Bridge）**：清单声明 abi，宿主按**主版本号协商**加载低版本插件；patch 级
  自动加载，minor 级重新校验签名/权限，major 级经兼容性适配器或拒绝迁移。

## 五、隔离机制

- **进程沙箱**：T1/T2/T3 独立 OS 进程，复用 v2.9.1 已验证的 ProcessSandbox（能力声明闸门、
  独立工作目录、有界输出、超时）；Windows 用 Job Object（整树 kill、内存/进程数上限）。
- **内存隔离**：插件独立地址空间，崩溃不影响宿主；实例独立。
- **网络隔离**：第三方插件默认禁网；非声明网络在无原语时由 waiver 显式接受或拒绝。
- **能力闸门**：运行时 `declares()` 声明真实强制边界；无法强制且无 waiver 即
  `PolicyNotEnforceable`（不默默降级到不受限运行）。

## 六、T0 系统插件（本版真实运行）

| `com.twinsearth.sys.chain` | `status`（真实声明 evm-light-client / chain-anchor） |

## 七、外部 API（REST，真实端到端验证）

`/api/v1/plugins` 路由块（GET 只读放行；变更类走认证闸门）：

| 方法/路径 | 作用 |
|---|---|
| `GET /api/v1/plugins` | 插件列表（id/version/tier/state） |
| `GET /api/v1/plugins/{id}` | 单个详情 |
| `POST /api/v1/plugins` | 安装（manifest） |
| `POST /api/v1/plugins/{id}/call` | 调用方法（body: `{method, payload}`） |
| `POST /api/v1/plugins/{id}/reload` | 热更新 |
| `DELETE /api/v1/plugins/{id}` | 卸载 |

## 八、版本映射

- 根 `VERSION` 是唯一权威来源：**3.0.0**。
- Rust gsn-core crate 版本映射规则升级为 `0.X.(Y*10+Z)`：**3.0.0 → 0.3.0**
  （`bump-version.sh` / `check-version.sh` 原硬编码 `0.2.` 会把 major 3 误映射为 0.2.0，
  本版改为按 major 动态映射）。

## 边界说明（诚实，不夸大）

- **WASM 运行时是可选 feature，当前构建类型化拒绝**：依赖树无 wasmtime，`runtime/wasm.rs`
  对所有清单返回具名 `Runtime` 错误（不把 WASM 插件悄悄降级到进程后端）。这是**能力缺口的
  诚实标注**，启用 wasm feature 后才承载 WASM 插件。
- **T1 官方插件的「清单 + 承载通道」就位，但业务逻辑迁移在后续中版本**：9 个官方插件
  （agent-card、agent-skill、swarm-emergence、economy-reputation、market-match、
  market-settle、scheduler-task、chain-anchor、chain-bridge）的清单可被 process 后端真实
  承载并 exec；但匹配算法、信誉计算等具体业务逻辑从单体模块迁移为插件方法，将在
  v3.1.0 / v3.2.0 中逐步完成。v3.0.0 真正运行的是插件内核与 4 个 T0 系统插件。
- 已知未修项（沿用，不在本版范围）：node.rs/api.rs 仍有 8 处 `let _ = node.persist();`
  丢弃持久化错误；API token 无法表达标准 DID 形式；结算仍按托管总额付款而非中标价。
