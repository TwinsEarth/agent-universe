# v2.7.3 — 实机部署修复：发布缺字段 422 与认证验收后证据不升级

两个缺陷均来自 Mac / Windows 真机部署（非纸面审计），在真实跑通完整市场链路时被抓到。

## 缺陷一：发布任务缺 `state` 字段即 422

`TaskSpec.state` 没有 serde 默认值，但 `market_actor.rs` 在反序列化成功后又强制 `t.state = TaskState::Open`。于是：

- 调用方不传 `state` → 反序列化缺字段 → **422**；
- 调用方传了 `state` → 反序列化成功后被服务端无条件覆盖为 Open。

字段语义自相矛盾：缺省应当是 Open，却要求调用方必须显式传一个会被覆盖的值。

**修复**：`TaskSpec.state` 加 `#[serde(default = "default_task_state")]`，并新增自由函数 `default_task_state() -> TaskState { TaskState::Open }`。缺省即 Open，发布返回 201。

## 缺陷二：认证验收通过后证据不升级，结算路径不可达

`settle_task` 的闸门要求结果 `evidence_grade.is_trustworthy()`（Verified / CpuProto）。一个 `Unverified` 结果经固定委员集签名投票、认证式 BFT 判定 `decision = Stop`、`state = Accepted` 后，其 `evidence_grade` 仍停在 `Unverified`——此后 `settle_task` 返回 422，而系统没有任何升级证据的 API，导致「验收通过却永远无法结算」的死路。

**修复**：`verify_result_authenticated` 在委员会判定 **Stop** 时，取对应结果信封，若其存在且证据不可信，则提升为 `EvidenceGrade::Verified`。

- 只有**认证式 BFT 验收**才提升证据（签名投票的共识结果）；
- 非认证 `verify_result` 路径**不提升**，保持其较弱的可信度语义。
