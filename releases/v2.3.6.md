# v2.3.6 - MCP/ACA 深化重构 + 三端跨语言可信对齐

## 一句话概述

v2.3.6 在 v2.3.5 跨平台客户端的基础上，把 **MCP（Model Context Protocol）** 与 **ACA（Agent Communication Architecture）** 做深、做实，并让 **Rust / Python / JavaScript 三端**在身份、规范签名、协议与 API 层面完全对齐——同一种子下三端产出的公钥、DID、规范载荷与签名逐字节一致、可互验。

## MCP：从占位门面到真实工具协议

- **字段规范化**：工具字段由 snake_case（`input_schema`、`mime_type`）改为 MCP 规范的 camelCase（`inputSchema`、`mimeType`），协议层统一 camelCase。
- **补齐生命周期方法**：新增 `ping`；`initialize` 返回标准 `protocolVersion` 与 `serverInfo`，并处理 `notifications/initialized`。
- **真实 handler 路由**：`tools/call` 不再返回占位文本，而是经 `MarketMcpBridge` 路由到市场 actor 真实执行；共注册 **18 个 `market_*` 工具**。
- **双传输**：stdio（JSON-RPC 逐行、日志走 stderr、通知不响应）与 HTTP/SSE（`POST` 无状态、`GET` event-stream）均真机走通。

## ACA：身份、签名与信誉补全

- 新增 `crypto` 模块（Ed25519 + 规范 canonical 签名）与 `runtime`。
- `manifest` / `message` / `receipt` 三类协议对象统一加签、可验签。
- 信誉增加时间衰减固化；`verification` 增加 BFT 委员会规格（`n ≥ 3f + 1`）。

## 跨语言可信（硬证据）

新增 Rust 集成测试 `cross_lang_signature.rs`。固定种子（32 字节 `0x01`）下：

| 项 | 值 |
|---|---|
| 原始公钥 | `8a88e3dd7409f195fd52db2d3cba5d72ca6709bf1d94121bf3748801b40f6f5c` |
| DID | `did:aip:34750f98bd59fcfc` |
| 规范载荷 | `{"capabilities":["text-generation","mcp"],"did":"did:aip:34750f98bd59fcfc","name":"CrossLang","stake":100}` |

Rust、Python、JavaScript 三端的公钥 / DID / 规范载荷 / 签名**逐字节一致、可互验**；篡改载荷或使用他人公钥即被拒绝。

- 身份口径统一为：Ed25519 原始 32 字节公钥 → SHA256 前 8 字节（16 hex）→ `did:aip:<16hex>`。
- 规范载荷规则统一为：移除 `signature` 键后，紧凑、对象键按字典序、非 ASCII 不转义的 JSON 字节。
- Python 新增 `crypto` / `aca` / `market_client` / `mcp_client` 模块；JS 新增 `lib/aca.js`、`lib/mcp.js`。
- JS 旧 `Keypair`（`did:au` + SPKI DER）仅为本地教学/向后兼容保留，不用于跨节点互操作；跨节点统一使用 `AipIdentity`。

## 真机验证（非骨架）

- gsn-daemon 真实打开 SQLite、libp2p 绑定 P2P 端口、HTTP API 真实监听。
- 市场端到端闭环真机跑通：充值 → 注册(质押) → 发现 → 发布 → 投标 → 匹配 → 提交结果 → BFT 验证 `accepted` → 结算 `amount=50`，守恒 `conserved=True`。
- MCP 三端真机完成 `initialize` / `ping` / `tools-list`（18 工具含规范 `inputSchema`）/ `tools-call`。
- gsn CLI 真机通过 `version` / `identity` / `market stats`（连节点取真实数据）/ `mcp stdio`。
