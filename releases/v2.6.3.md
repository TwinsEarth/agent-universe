# Release v2.6.3 — 经济结算收尾：重复注册拒绝、出价脱钩校验、Rejected / DuplicateWork 终局可达

**发布日期**：2026-09-28
**主题**：补齐 GAP 审计中经济结算链路的三处缺陷——同一 Agent 重复注册会重复占用质押并静默覆盖、投标报价与任务预算脱钩（0 / 负 / 超预算仍可投标）、结算原因枚举中的 `Rejected` 等变体从未被产出（不可达代码）。本版让"终局拒绝"和"返工后重复劳动"成为真实可达、可结算、可审计的路径。

## 背景

v2.5.6 审计（GAP）在经济结算环节记录了三条缺陷：

1. **重复注册（GAP §2.6）**：`register_agent` 没有"是否已注册"检查，同一 `agent_id` 再次调用会重复 `lock` 质押、向技能索引重复 `push`，最后 `agents.insert` 静默覆盖既有记录。JS 侧（`js/lib/market.js`）与历史回归（REG-020）早已断言重复注册应报错，Rust 侧却静默通过。
2. **出价脱钩（GAP §2.7）**：`submit_bid` 只校验 Agent / 任务存在与信誉门槛，从不校验 `proposed_price`；0、负数甚至远超预算的报价都能进入匹配，`match_task` 对 `price <= 0` 还有专门分支不做惩罚。
3. **结算原因不可达（GAP §2.8）**：`SettlementReason` 枚举含 `Rejected / Slashed / Refunded` 等变体，但 `settle_task` 永远只传 `Completed`；任务状态机也没有"终局拒绝"状态，导致这些变体是不可达代码，"拒绝任务"这一正常业务结果无法表达。

## 新增 / 重写

### 1. 重复注册拒绝（GAP §2.6）

- `register_agent` 在非空校验之后新增 `contains_key` 检查：`agent_id` 已存在即返回错误"Agent X 已注册，禁止重复注册"，不再重复锁定质押、不重复索引、不覆盖记录，与 JS 侧和 REG-020 对齐。
- 既有 `test_register_agent_duplicate` 断言第二次注册 `is_err()` 且 `agent_count() == 1`，在新行为下继续成立。

### 2. 投标报价与预算强校验（GAP §2.7）

- `submit_bid` 改为先取任务（不存在即 `ok_or_else` 报错），依次校验：
  - `proposed_price` 必须为正（0 / 负数拒绝）；
  - 报价不得超过任务 `budget`；
  - 任务必须处于 `Open` 状态（状态前置，关闭后不能再投）。
- `match_task` 成本打分简化为 `cost_score = rep_score / price`，删除 `price <= 0` 的特殊分支（非法报价已在投标阶段拦截）。

### 3. 终局拒绝与重复劳动可达（GAP §2.8）

- **任务状态机**：`TaskState` 新增终态 `Rejected`（label `REJECTED`），并补转移边 `Verifying / Running / Rework → Rejected`、`Rejected → Settled`。
- **结算原因**：`SettlementReason` 新增 `DuplicateWork`；`settle` 中 `Rejected | DuplicateWork` 统一走"付执行者 0、留痕"分支。
- **重复劳动检测**：`AgentMarket` 新增 `result_hashes`（task_id → 结果内容 SHA256）与 `duplicate_work` 集合。
  - `submit_result` 计算结果哈希：若该任务在 QA 要求改进（返工）后再次提交**完全相同**的结果，自动转入 `Rejected` 并标记 `DuplicateWork`；否则正常进入验收并记录哈希。
  - 新增 `reject_task(task_id)`：仅在 `Verifying / Rework` 可拒绝；若结果信封可信且成功则不允许拒绝（防止无依据拒付）。
- **拒绝结算**：`settle_task` 新增 `Rejected` 分支——付执行者 0、托管预算全额退回需求方、罚没执行者 10% 质押、信誉记录一次失败，最后转 `Settled`；`Accepted` 分支保留证据分级闸门与中标价支付逻辑。
- **流程重置豁免**：`reopen_after_no_quorum`（未达成共识、流程重开）会清除该任务上次结果哈希，允许重新提交相同结果；重复劳动判定只针对 QA 明确要求改进后的返工重提，不误伤合法重试。

## 说明 / 边界

- 重复劳动判定基于结果内容的 SHA256 完全相同，且只在 QA 要求改进后的返工路径生效；NoQuorum 流程重置已豁免。
- 罚没比例固定为执行者质押的 10%；终局拒绝不支付任何执行款。
- 本版未引入新的第三方依赖（SHA256 复用既有 `sha2`）。

## 兼容性

- v2.5.7–v2.6.2 的 DID / 签名、整数金额、发布即托管、认证式验收、状态机恢复边、证据闸门、账本落盘、版本一致性与合约语义全部保持不变。
- 新身份仍用 `did:nau:`，上游 `did:aip:` 仍可解析验证；新增的 `Rejected` 状态与 `DuplicateWork` 原因是对状态机 / 枚举的扩展，不影响既有 `Accepted → Settled` 路径。
