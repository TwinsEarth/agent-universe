# v3.7.0 — AUSec 弹性计算基础设施基座：四执行后端模型 + `sys.ausec` 系统插件 + 8 个 `sandbox:*` 能力令牌（minor）

v3.7.0 是 **AUSec（Agent Universe Elastic Compute）版本线的基座（minor）**。它不改变任何
资金/共识/持久化语义，只在 v3.0.0「一切插件化」内核之上新增**弹性沙盒基础设施的类型层、
选择层与权限层**，为 v3.7.1–v3.9.7 的镜像按需加载、内存/CPU 弹性、Agent 委员会与 Agent
安全组织打地基。

总体技术方案见 [`docs/ausec/AUSEC-DESIGN.md`](../docs/ausec/AUSEC-DESIGN.md)。

## 一、本版交付了什么（边界先说清楚）

本版**只交付「选择 + 平台可用性声明 + 权限令牌」，不交付真实容器/虚拟机执行器**。
这是刻意的诚实边界，而非遗漏：在没有强制执行器之前，绝不允许把「探测到 docker」谎报成
「容器沙箱已能安全执行」。

| 交付物 | 位置 | 性质 |
|---|---|---|
| 四执行后端枚举 `FnCall/Container/MicroVm/FullVm` | `gsn-core/src/ausec/backend.rs` | 类型 + 隔离强度标注 |
| 分级×风险 → 默认后端映射 | `backend_for_tier(Tier, RiskGrade)` | 纯函数，黑名单→`None` 不可调度 |
| 平台三态原语可行性 | `PrimitiveAvailability` + `primitive_availability` | Available/NeedsProbe/Unsupported |
| 就绪综合判定 | `Readiness` + `readiness` | 原语 **且** 执行器接线才算 Ready |
| 平台特征探测 | `detect_features()` | PATH 查 docker/podman、Linux 查 `/dev/kvm`+firecracker；未探测即 false（fail-closed） |
| AUSec 系统插件 | `com.twinsearth.sys.ausec`（第 5 个 T0 系统插件） | 经真实装配→spawn→call 暴露 `status`/`select_backend` |
| 8 个 `sandbox:*` 能力 | `plugin/capability.rs` | 治理类仅 System；可委托类 OFF/CERT 声明式、3RD 拒绝 |

### 分级 → 后端映射

| 插件分级 | 标准风险 | 高风险 |
|---|---|---|
| System（T0） | FnCall（进程内，无 OS 隔离） | FnCall |
| Official（T1） | Container | Container |
| Certified（T2） | MicroVM | MicroVM |
| ThirdParty（T3） | MicroVM | **FullVm** |
| Blacklist | 不可调度（`None`） | 不可调度 |

### 就绪模型为什么分「平台原语」和「执行器接线」两层

- `primitive_availability` 只回答「**这台机器理论上有没有 docker/KVM/Hyper-V/Apple VZ**」；
- `ExecutionBackend::executor_wired()` 是**编译期事实**：本仓是否真正实现了该后端执行器。

v3.7.0 只有 `FnCall.executor_wired() == true`。因此即使在一台装了 Docker/KVM 的机器上，
Container/MicroVM/FullVM 的 `readiness` 也一律是 `ExecutorNotWired`、`can_run_now == false`。
MicroVM（Firecracker/KVM）在 macOS/Windows/Other 上直接 `Unsupported`，不降级冒充。

## 二、8 个 `sandbox:*` 能力与授权矩阵

| 能力 | 含义 | System | Official | Certified | ThirdParty |
|---|---|---|---|---|---|
| `sandbox:lifecycle` | 沙盒生命周期 | Granted | Declarable | Declarable | Denied |
| `sandbox:message` | 沙盒消息 | Granted | Declarable | Declarable | Denied |
| `sandbox:create` | 创建沙盒 | Granted | Declarable | Declarable | Denied |
| `sandbox:snapshot` | 快照（pack_diff） | Granted | Declarable | Declarable | Denied |
| `sandbox:restore` | 恢复/分叉 | Granted | Declarable | Declarable | Denied |
| `sandbox:configure` | 配置隔离参数（治理） | **Granted** | Denied | Denied | Denied |
| `sandbox:policy:apply` | 下发安全策略（治理） | **Granted** | Denied | Denied | Denied |
| `sandbox:blacklist:sync` | 黑名单同步（治理） | **Granted** | Denied | Denied | Denied |

治理类（configure/policy/blacklist-sync）与 kernel 能力同级，**只有 System 可持有**，
避免「能创建沙盒的插件自行放宽隔离」的提权路径；`grant_for` 是唯一授权入口。

## 三、系统插件装配（真实调用点，非死代码）

- `system_ids()` 由 4 个增至 **5 个**，新增 `SYS_AUSEC = com.twinsearth.sys.ausec`；
  系统插件数量断言改为与 `system_ids().len()` 绑定，避免今后再漂移。
- `register_handlers` 末尾无条件调用 `crate::ausec::register(rt)`（status/select 不依赖
  store/peer 句柄）；处理器走 `Fn(&str,&[u8]) -> PluginResult<Vec<u8>>` 字节桥，
  坏 JSON→`PluginError::Manifest`，序列化失败→`PluginError::Runtime`，无裸 unwrap/expect/panic。
- PMB 方法：
  - `status`：实时探测平台特征，列出四后端 `state/can_run_now/executor_wired/os_isolation/startup_hint`；
  - `select_backend`：入参 `{plugin_id, risk?}`，返回分级、默认后端与该后端当前就绪度；
    缺 `plugin_id`、非法 `risk` 均类型化拒绝。

## 五、诚实边界（不夸大）

- 本版**不能**真正在容器/MicroVM/FullVM 里执行任何东西；`startup_hint` 的 `<1ms/毫秒/十毫秒/
  百毫秒` 是**设计目标/外部资料数量级，非本仓基准**（CI 三平台无 Docker/KVM/GUI 环境）。
- `virtio-pmem/DAX/DAMON/balloon/seccomp/landlock/AppArmor/eBPF` 等 Linux 专有原语本版**未接入**，
  将在 3.7.4–3.7.6、3.9.7 按「有原语才 Available、无原语具名拒绝」落地，不在本版承诺。
- 外部性能数字（镜像访问占比 4.2–13.3%、按需加载约 1.71×/磁盘写降约 57%、约 90% 沙盒
  CPU<5%、超卖 50×、共享页缓存峰值内存降 40.2%、累计再降 21.2%、时延影响 45.2%→17.3% 等）
  均为外部实测，来源 `https://aiwiki.ai/wiki/dsec#2` 与
  `https://byteiota.com/deepseek-dsec-agent-training-sandbox/#1`，**不是本仓复测结果**。
