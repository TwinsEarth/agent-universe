# v2.8.0 — 沙箱集成核心链路（大版本）

把 v2.7.6–v2.7.9 的沙箱核心、进程运行时、生命周期管理、安全边界集成进
daemon 的核心执行链路：REST（E2B 兼容）、MCP 工具、Kubernetes API 声明。

## 新增：sandbox/api.rs（REST / E2B 兼容）

- 纯函数 `handle_api(method, path, body, &mut SandboxManager) -> (u16, Value)`，
  与 `rest::route` 风格一致，无 I/O、可单测。
- 端点：`POST /api/v1/sandboxes`（创建，201）、`GET`（list）、`GET /{id}`、
  `POST /{id}/exec`（执行代码，Paused 自动 wake）、`POST /{id}/pause`、
  `/resume`、`DELETE /{id}`。
- **E2B 别名**：`/v1/sandboxes`、`/v1/sandboxes/{id}/commands`、`/run`，
  便于已有 E2B 应用迁移。
- 错误码映射：404 / 403 / 400 / 429 / 422 / 500。
- `is_sandbox_route` 快速分流；`default_sandbox_dir` 统一沙箱目录。

## node.rs 接入（独立分流）

- `run_api_server` 新增 `Arc<std::sync::Mutex<SandboxManager>>` 参数；
- loop 内 sandbox 分支经 `spawn_blocking` 取锁处理（不阻塞异步运行时）；
- main 在 data-dir 下构建 manager（warm_size=0）并传入。

## 新增：mcp/sandbox_tools.rs（7 个 MCP 工具）

- `sandbox_create / sandbox_list / sandbox_get / sandbox_run_code /
  sandbox_pause / sandbox_resume / sandbox_destroy`；
- 复用 `handle_sandbox_api`（与 HTTP REST 同一处理器，单一来源）；
- 在 MCP `sse.rs`（HTTP）与 `stdio.rs`（本地）两条路径都接入，
  工具定义合并、tools/call 按名分流；mutating 工具在无 token 时默认拒绝。
- 公共构造 `tool()` / `ParamBuilder` 上移到 `mcp/tool.rs`。

## 新增：sandbox/k8s.rs（Kubernetes API 声明）

- 生成 `AgentSandbox` CRD 清单（openAPIV3Schema、printer columns、status）
  与示例实例，可直接 `kubectl apply`；
- 给出 operator reconcile 协调步骤；
- 当前节点无 K8s 集群，仅生成清单、不实际连接（诚实标注）。

## 验证（tests/v280_test.rs，5 项）

- 完整生命周期：create→get→exec(Python/JS)→pause→resume→list→destroy；
- E2B 别名路由；错误码（缺 code/不支持语言/不存在沙箱）；
- 路由识别；Kubernetes CRD 清单。
- clippy 零警告；全量 Rust 测试、JS 21 项、回归 14 项全绿。
