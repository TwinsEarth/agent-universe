# v3.8.4 — 面向 Agent 的资源市场（5/10）：准入质押冻结/罚没账本（StakeLedger 四桶资金守恒，罚没只能来自己冻结保证金，决策/资金分离）

## 一、交付了什么

v3.8.1 的容量注册带了一个 `stake_micro` 字段，但它只**登记**供给方申报的准入保证金
数额，既不冻结、也不罚没；v3.8.3 的撮合在判罚（`adjudicate_slash`）时也只能归还容量、
没有真正可动的质押资金。v3.8.4 新增**独立的准入质押账本 `StakeLedger`**，把「容量」
（资源量）与「质押」（资金量）**两账分离**，在不改动容量账本任何 hold/release 语义的
前提下，落地可记账、可守恒、可单测的保证金冻结/解冻/罚没/提取面。零浮点、零 syscall、
零 unsafe、无 panic 路径，金额全 `u128` checked 运算。

新增文件 `gsn-core/src/economy/resource/stake.rs`。每个供给方（按 DID）持一个
`StakeAccount`，资金在任一时刻必落在四个互斥分桶之一：

- `available`：已质押、可自由解冻后提取的保证金；
- `frozen`：因挂单/在持订单而**冻结**、承担担保责任的保证金；
- `slashed`：经仲裁**罚没**、累计离开该主体的资金（**终局，不可回流**）；
- `withdrawn`：正常**提取**离场、累计离开该主体的资金。

方法（`deposit/freeze/unfreeze/slash/withdraw`，顺序确定的有序 Vec 账户集）：

1. **存入 `deposit`**：`deposited/available` 同增；账户不存在自动开户，可多次累计；
   空/空白 DID 报 `RESOURCE_EMPTY_PROVIDER_DID`，零额报 `RESOURCE_NON_POSITIVE_QUANTITY`，
   u128 溢出报 `RESOURCE_ARITHMETIC_OVERFLOW`。
2. **冻结 `freeze`（available → frozen）**：可用不足 fail-closed 报
   `RESOURCE_INSUFFICIENT_FREE_STAKE { requested, available }`，且**失败后分桶逐字节不变**。
3. **解冻 `unfreeze`（frozen → available）**：解冻超过冻结额报
   `RESOURCE_UNFREEZE_EXCEEDS_FROZEN { attempted, frozen }`。
4. **罚没 `slash`（frozen → slashed，终局）**：**只能罚没已冻结部分**，冻结不足报
   `RESOURCE_SLASH_EXCEEDS_FROZEN { attempted, frozen }`；即使账上有大笔 `available`，
   一分钱未冻也不能罚——这是本版的核心安全口径。
5. **提取 `withdraw`（available → withdrawn）**：只能提可用余额，冻结中不可提，超可用
   报 `RESOURCE_INSUFFICIENT_FREE_STAKE`。
6. **守恒不变量**：单账户 `conserves()` 与全表 `invariant_holds()` 恒断言
   `deposited == available + frozen + slashed + withdrawn`（checked 求和）。冻结/解冻只在
   available↔frozen 间搬运不改变总额；罚没、提取是离开主体的终局去向。
7. **决策/资金分离 + 4 个具名错误**：账本**不判定谁违规**，只表达「治理裁决要罚没时，
   钱只能从已冻结桶出」；要惩罚主体必须先经后续 QA/审判令其保证金处于冻结态。
   `ResourceError` 新增 `StakeAccountNotFound / InsufficientFreeStake /
   UnfreezeExceedsFrozen / SlashExceedsFrozen` 并补齐 `RESOURCE_*` Display；PMB
   `resource_market_status` 诚实位置 `enforceable.stake_ledger=true`、
   `provided.stake_ledger_persistence=false`，`stake_slash/escrow_settlement/
   onchain_payment` 仍 false。

## 二、测试（旧实现无法表达的断言，7 新增）

`economy/resource/stake.rs` 7 个，全部针对「质押资金此前只有登记额、无法保证冻结/罚没
守恒，尤其不能让罚没直接划走未冻结的可用余额」：

1. `deposit_freeze_unfreeze_settle_path_conserves`：多次存入累计、freeze/unfreeze/
   withdraw 全路径，终局 deposited1500 == available500+frozen700+slashed0+withdrawn300。
2. `freeze_failclosed_when_free_insufficient_leaves_buckets_untouched`：可用 40 时再冻
   50 被 `INSUFFICIENT_FREE_STAKE` 拒绝，且失败后账户与失败前逐字节一致（无半笔移动）。
3. `unfreeze_cannot_exceed_frozen`：解冻 31 > 冻结 30 被 `UNFREEZE_EXCEEDS_FROZEN`
   拒绝；恰好 30 可解冻回 available。
4. `slash_only_consumes_frozen_and_is_terminal`：罚没 250 只使 frozen→slashed；后续
   解冻/再存不再令 slashed 回流（终局累计），deposited 守恒仍成立。
5. `slash_cannot_touch_available_balance`：一分未冻时即使账上有 1000 可用，罚 1 也被
   `SLASH_EXCEEDS_FROZEN{0}` 拒绝；冻 100 罚 101 拒绝且可用 900 不受影响。
6. `zero_amount_empty_and_unknown_account_rejected`：空 DID 存拒绝；五操作零额统一
   `NON_POSITIVE_QUANTITY`；从未开户主体的 freeze/unfreeze/slash/withdraw 统一
   `STAKE_ACCOUNT_NOT_FOUND`（与余额为 0 区分）。
7. `multiple_providers_are_isolated_and_withdraw_respects_freeze`：两供给方账户互不串账；
   a 不能提走冻结中的 400（提 700 > 可用 600 拒绝）；b 罚没全部冻结 500 后可用 1500
   完好，全表 deposited 求和 = 3000 守恒。

  resource 模块 39/0）；`cargo fmt`、`cargo clippy --all-targets -D warnings` 干净；

## 三、诚实边界

- 质押账本是**确定性内存记账面**：不持久化、不跨进程/跨节点共享、不是全局单例；宿主市场
  门面持有它。**本版不把质押与撮合订单/容量联动**——何时按订单自动冻结、罚没多少，要等
  v3.8.5 托管结算与后续 QA（v3.8.8）/审判驱动接线；当前 freeze/slash 只能由宿主在库内调用。
- **账本不做违规判定、不接链、不受理 PMB 外部写、不新增能力令牌**：它只保证资金四桶守恒
  与「罚没只能来自己冻结保证金」。私钥隔离、真实 BTC/ETH/稳定币结算在 v3.9.x，本版不做。
- 罚没的 `slashed` 只表达「资金终局离开该主体」的记账去向，**本版不定义罚没资金归属**
（进入治理池/补偿买方/销毁在 v3.8.5 托管守恒里作为分账桶表达）。
- `CapacityRegistration.stake_micro` 语义保持不变（仍只是申报登记），本版**不**自动用它
给 StakeLedger 开户或冻结，避免把资源登记误当资金动作；两者的对账接线在后续小版本。
- 外部数字（90% 沙盒 CPU<5%、超卖 50×、镜像访问 4.2–13.3%、x402/BlackRock 等）仍为
第三方报道、非本仓复测，仅作机制动机，不写进代码或作为已验证结论。
