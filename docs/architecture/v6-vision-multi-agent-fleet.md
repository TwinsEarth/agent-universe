## 一、总体架构：五层协作体系

当 Agent 规模从数十个扩展到成千上万、跨越不同网络、平台和对话会话时，系统需要一套全新架构支撑编队协同、记忆管理、资源调度与委员会治理。总体采用五层协作架构：

1. **网络/传输层**：跨网络 P2P、中继、多协议适配、身份解析。
2. **编队协同层**：动态 Leader-Follower 编队、角色化最小权限、协同/协作/协助/协调。
3. **记忆层**：对话/个体/集体三层记忆、跨会话持久化、巩固与遗忘。
4. **权限与调度层**：数值权威、自动审批、多 Agent 强化学习资源调度。
5. **治理与协防层**：委员会协商、加权投票、共识自动接受、递归治理、BFT 协防。

## 二、编队协同 / 协作 / 协助 / 协调 / 协防

### 2.1 编队模型：动态 Leader-Follower + 异构优化

- 编队采用动态 Leader-Follower 模型，领导权在多个 Agent 之间动态分配。
- 研究称具有最优分配的异构参数 Agent 群体表现优于同构群体（收敛速度优势的具体数字待一手核验）。
- 不同 Agent 应按能力特长被赋予不同角色权重。

**层级编队结构：**

| 层级 | 角色 | 职责 | 规模 |
|---|---|---|---|
| L0 | 全局协调层（总指挥） | 跨编队任务分解、资源协商 | 1–3 |
| L1 | 编队指挥（Captain） | 编队内任务分配、权限管理、冲突消解 | 每编队 1 |
| L2 | 专业执行（Worker） | 具体任务执行（读/写/验证/审查） | 每编队 5–50 |
| L3 | 辅助支持（侦察/证据） | 只读、证据汇总、历史检索 | 按需动态创建 |

最小权限执行模型按**角色**而非按个体授权：小任务可只需 Captain / Implementer / Validator；大任务可增加 Planner、Scope Guardian、Knowledge Scout、Review Agent、Evidence Collector。读、规划、审查、验证、证据起草可并行；写、Git、任务生命周期、最终证据权限独占且受策略管控。

### 2.2 四种协同模式

- **协同（Collaboration）**：多 Agent 对同一任务的不同部分并行（fan_out 并行分支，Pipeline）。
- **协作（Cooperation）**：Agent 相互依赖，A 输出是 B 输入（DAG 编排、动态依赖解析）。
- **协助（Assistance）**：低权限向高权限请求帮助（权限提升请求，Captain 审批）。
- **协调（Coordination）**：解决资源/任务冲突（CID Broker 作为跨任务冲突治理者，对共享表面写入仲裁）。

### 2.3 三层协防体系

| 防御层 | 角色 | 职责 | 手段 |
|---|---|---|---|
| 感知层 | Sensor Agent | 本地行为监控、异常特征提取 | eBPF 系统调用监控 |
| 分析层 | Analyst Agent | 威胁检测、行为画像 | LLM 语义推理 + 数值置信度 |
| 协调层 | Coordinator Agent | BFT 共识、防御决策 | 混合语义-数值共识 |

### 2.4 跨平台通信协议

统一通信协议应支持：可验证身份（基于指纹的角色/权限/能力标识）、JWT 认证、基于角色的访问控制、跨组织联邦（端到端加密保持）。EdgeCitadel 式的混合消息编排可支撑异构 Agent 连接、持久化重放与直接对等委派。

## 三、记忆系统

### 3.1 三层记忆架构

| 层级 | 类型 | 存储位置 | 生命周期 | 访问权限 |
|---|---|---|---|---|
| L1 | 对话记忆（工作记忆） | Agent 本地内存 | 会话级 | 仅本 Agent |
| L2 | 个体记忆（经验/技能/反思） | 分布式文件系统 | 持久 | 本 Agent + 授权访问者 |
| L3 | 集体记忆（共享知识/最佳实践/教训） | 分布式共识存储 | 永久 | 按角色权限 |

记忆类型可细分为语义、情景、程序、工作、反思、世界模型、通信记忆等，通过标准化接口形成集成认知记忆系统。

### 3.2 集体记忆的形成机制

- 集体记忆通过个体记忆与**环境痕迹（stigmergy）**的相互作用涌现：Agent 维护内部记忆状态，同时沉积持久环境痕迹，创建空间分布的集体记忆而无需集中控制。
- 对本项目的启示：`pack_diff` 生成的快照本质是"环境痕迹"；其他 Agent 可从该点继续，前 k 步环境共享，仅后续变化需单独记录。

### 3.3 跨会话认知协作（MMP）

- **P1 字段级接受**：逐字段决定从同伴接受什么，而非整条接受/拒绝。
- **P2 来源可追溯**：每个声明可追溯来源，识别接收者自己先前思考的回声。
- **P3 存储即相关**：跨会话重启存活的记忆因存储方式而相关，而非因检索方式。
- 四个原语：CAT7、SVAF、inter-agent lineage、remix。

### 3.4 记忆巩固与遗忘

- 生物启发的主动遗忘（FadeMem）以提升多跳推理/检索效率并降低存储。
- 记忆巩固分：短期（会话级缓存，TTL）、中期（快照持久化，按需恢复）、长期（写入分布式文件系统，Merkle-SHA256 完整性签名）。
- 具体存储/稳定性数字待一手核验。

## 四、队长（权限管理）/ 审核（自动审批）/ 调度

### 4.1 数值权威模型

类比 Unix 权限级别，每个 Actor 携带整数 `authority_level`：

| 层级 | authority_level | 权限范围 |
|---|---|---|
| 普通 Agent | 0–49 | 创建目标与会话数据（自身范围） |
| 队长 Agent | 50–69 | 创建团队目标、管理团队成员 |
| 组织管理员 | 70–89 | 创建组织目标、注册 Actor、设置覆盖 |
| 系统管理员 | 90+ | 创建全局目标、跨组织配置、覆盖任何低级约束 |

每条规则可指定 `matching_exempt_level`，达到或超过该级别的 Actor 绕过组织/团队会员检查（类似 root 绕过文件权限）。

### 4.2 自动审批流程

```
Agent 提交请求 → 权限检查（authority_level ≥ 规则最低要求）
  → 是：自动批准（记录为监督者验证证据）
  → 否：进入待审批队列 → 队长 / 组织管理员 / 系统管理员逐级审批
```

审批结果可链上存证锚定；跨会话待审批索引使监督者从统一队列审查所有未决请求。

### 4.3 资源调度：多 Agent 强化学习

调度维度包括：CPU（时延敏感优先）、内存（共享页缓存 + 空闲页回收）、存储（按需加载、镜像种子）、P2P 网络（路由优化）、电力（可再生能源/峰谷定价）。集群级需通过分层调度、增量聚类、位置预测应对"协同崩溃"（具体延迟/命中率数字待核验）。

## 五、委员会协商机制

### 5.1 结构化委员会协议

- 蓝图设想固定角色委员会（Memory、Guardian、Learning、Specialist、Shadow、Experimental），每角色由恰好一个活跃 Agent 支持。
- 决策分阶段：上下文摄入 → 立场提出 → 跨 Agent 对齐 → 加权重分配投票 → 所有权投票 → 能力执行 → 结果学习；并把"实体是否应被重新分配"与"谁应拥有它"分开。
- 每个决策受预算约束、产生不可变快照、保留异议论点。
- **注意**：蓝图引用的"AURA Council Protocol（Zenodo 21783184）"未能证实；v6 立项时应以 AgentCity / MADA / COA-MAS 等真实委员会研究为来源（详见尽调报告）。

### 5.2 委员会治理三层

| 层级 | 类型 | 决策范围 | 机制 |
|---|---|---|---|
| L1 | 操作委员会 | 编队内任务分配、角色调整 | 加权多数投票 |
| L2 | 协调委员会 | 跨编队资源分配、冲突仲裁 | 委员会共识 |
| L3 | 治理委员会 | 规则修改、黑名单、协议升级 | 链上治理 |

### 5.3 加权投票

权重维度：信誉分（质量/速度/诚实/可用，不可转让）、判断质量、贡献量、权威级别。

### 5.4 共识自动接受

多个受信任 Agent 投票批准贡献时自动接受（Ed25519 身份、能力注册表、可验证行为账本）。运行数据（如 pcell.si）须标注抓取时间点。

### 5.5 递归治理

Sentinel + MetaSentinel 递归治理：Sentinel 检测违规，MetaSentinel 监控 Sentinel 本身，防止治理者被攻破或被诱导作恶——与本项目 v3.9 的警察/监察/审查/审判体系同构。

## 六、跨网络 / 跨平台 / 跨对话

### 6.1 多协议适配

PMB（Plugin Message Bus）可扩展为多协议适配层：通用 Agent 协作协议、A2A、NATS-MQTT、libp2p GossipSub、NLIP（WebSocket 实时双向 + CBOR 高效多模态 + AMQP 复杂拓扑）。**蓝图引用的 InterMesh 协议未能证实，立项前须重新定位一手来源。**

### 6.2 跨平台身份解析

Agent 携带平台限定句柄（如 `email:alice@acme.com`、`telegram:alice_tg`），区分业务级身份（属于哪个组织）与基础设施级身份（通过哪个网关路由）。

### 6.3 跨对话记忆持久化

可移植情景身份记忆应包含：可移植 envelope（身份快照、时空来源、逐字段权限声明）、权限/联邦层（决定哪些记忆维度在哪些边界共享）、隐私层（传输前变换、会话内一致性、会话间不透明性）。预处理管道通过去重/蒸馏降低上下文 token（`token_budget` 支持预算规划）。

### 6.4 大规模扩展

- 实际限制：30–50 Agent 时受上下文窗口约束，token 成本高；100+ 出现"协同崩溃"（超线性退化）。
- 应对：分层编队（编队内 30–50）、位掩码协议（亚 10ms 协调，数字待核验）、CRDT 状态同步、分布式语义一致性账本。

## 八、设计原则

1. **分层治理，分权制衡**：从个人 Agent 到 Captain 到委员会到全局治理，每层有明确权限边界与制衡；数值权威精确控权，递归治理防止治理权滥用。
2. **记忆分层，共享涌现**：对话/个体/集体三层记忆，通过环境痕迹实现集体记忆涌现，通过字段级接受与来源追溯确保可控、可审计。
3. **调度智能，资源弹性**：MARL 调度结合时延敏感/容忍分级，在异构环境中实现资源最优分配。
4. **共识驱动，异议留存**：结构化决策、加权投票、共识自动接受，同时保留异议论点，确保可追溯、可审计。
5. **攻防持续，治理先行**：安全治理是持续过程；三层协防结合内核级防御与 BFT 共识，把攻防从暗箱变为可审计、可回放、可治理的工程流程。
