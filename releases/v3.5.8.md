# v3.5.8 — 守护进程真实端到端吞吐/延迟基准 + 历史无测量性能小节诚实化（#76 / DOC-07）

v3.5.8 是 v3.5.7 之后的**补丁版本（patch）**。它回应审计项 **DOC-07**：全文此前
**没有任何一处守护进程吞吐/延迟基准**，唯一名为「性能指标」的小节（v2.1.8）给出过
冷启动 / 内存 / 包体积数字却从未测量。本版做两件事：**①新增可复现的真实端到端基准；
②把历史无测量小节明确标注为「设计目标」并加勘误指针。** 不含产品功能变更。

## 一、新增：真实端到端基准（不是库函数、不是 mock）

新增 `scripts/bench-e2e.mjs`（Node，自包含）：

- 拉起一个使用**临时 data-dir** 的 **release `gsn-daemon`**，经真实 **HTTP/1.1 回环**
  发请求；结束自动清理。
- 每轮闭环：充值（一次性）→ 发布任务并托管 50 → 投标 10 → 匹配 → 提交结果
  （policy=None 直接验收）→ 结算（按中标价 10 付款、余款 40 退回、落 SQLite）。
- 记录每个阶段的 avg/p50/p95/p99/max 与整轮吞吐；**结束前拉 `/api/v1/audit` 与
  `/api/v1/conservation`，审计不通过或资金不守恒即以退出码 2 失败**——
  防止「跑得快但账错了」的数字被采信。

复现：

```bash
cd gsn-core && cargo build --release --bins -j2 && cd ..
node scripts/bench-e2e.mjs \
  --bin gsn-core/target/release/gsn-daemon \
  --n 200 --warmup 20 --port 4091 --p2p-port 4090 --out result.json
```

写操作通过 `REST_ALLOW_UNAUTHENTICATED=1` 放行（仅本地基准临时 data-dir），
`RUST_LOG=error`。方法学、口径与全部数字见 `docs/benchmarks/`（含 JSON 快照）。

## 二、v3.5.8 实测（被测 = gsn-core 0.3.58 release，Linux 云沙箱 4 vCPU/8 GB）

n=200，warmup=20，墙钟 46.823s：

| 指标 | 值 |
|---|---|
| 闭环吞吐 | **4.27 轮/秒** |
| 单轮 avg / p50 / p95 / p99 | 234.1 / 234.6 / 247.7 / 251.0 ms |

| 阶段（avg ms） | publish | bid | **match** | result | **settle** |
|---|---|---|---|---|---|
| avg | 1.686 | 4.835 | **109.243** | 1.930 | **116.331** |
| p95 | 2.487 | 7.289 | 114.372 | 3.554 | 123.414 |

正确性：`/api/v1/audit` `passed=true`（663 条流水独立重放，expected=actual=12100，
无 mismatch），`/api/v1/conservation` `conserved=true`。

## 三、瓶颈根因（已查实，本版刻意不改）

`match` 与 `settle` 各稳定在约 109–116 ms、方差极小，且与版本无关（v3.5.6 二进制同脚本
跑出 108/115 ms）。这不是 CPU 或网络特征，而是 **SQLite 同步提交的 fsync 开销**：
存储层未设置 `PRAGMA synchronous` / `journal_mode`，采用默认 rollback journal +
`synchronous=FULL`，每次提交都刷盘；云沙箱 overlayfs 上一次 fsync 约 100 ms。

**本版不修改同步策略**：切 WAL 或 `synchronous=NORMAL` 涉及断电/崩溃一致性权衡
（本项目账本的卖点正是可重放、防篡改），需要专门设计与崩溃注入验证，超出 DOC-07
「补真实测量」的范围。已登记为后续候选——**不得在未论证崩溃语义前为吞吐放松持久性。**

## 四、历史文档诚实化

`releases/v2.1.8.md` 的「性能指标」改名为 **「性能指标（设计目标，非实测）」**，并加
勘误指针说明：那三项数字（冷启动 <1s / 空闲内存 30–40MB / 包体积 2.5–10MB）在 v2.1.8
发布时未经基准测量，当时只有 10/10 单测与跨平台编译，不支撑这些数字；原文保留备查，
真实基准指向 v3.5.8。v3.2.2 出现的「性能指标」是 f64 语义说明，与本项无关，未改。

## 五、测量口径与不可外推边界

- 单机回环、单连接、顺序请求，含真实 SQLite 落盘与真实 HTTP 解析。
- **不含**跨网 libp2p 往返、LLM 推理、并发竞争、TLS。
- 因此这是「守护进程本地市场/账本栈顺序负载基线」，**不能外推为公网多节点 TPS**。
- 论文目录 `docs/papers/` 中的 244 tasks/s 等数字已明确标注为 CPU 原型/研究口径，
  非产品 wall-clock 声称，本次不动。
