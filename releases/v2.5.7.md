# Release v2.5.7 — 跨实现身份一致性 + 客户端构建链路修复

**发布日期**：2026-09-27
**主题**：统一 Rust / JavaScript 两端（及上游 gsn-core）的 DID 派生与规范签名口径，用独立实现的测试向量证明跨实现一致性；同时根治 client/desktop 客户端"演示壳与发布包结构脱节、tag 构建时拿不到本版本 SDK"的构建缺陷。

## 背景

身份层此前存在两套互不一致的 DID 派生口径：Rust 对**原始 32 字节公钥** SHA256 取 8 字节、前缀 `aip`；JS `keychain` 对 **SPKI DER** 取 16 字节、前缀 `au`（JS `aca.js` 又是第三套）。同一把密钥在不同端得到不同 DID，跨端互认、跨实现签名校验无从谈起。

客户端侧，client/desktop 的前端为避开浏览器 / WKWebView 无 `node:crypto`，故意只 import SDK 的 `/lib/market.js` 子路径；但根发布包只含 `js/`（实体在 `/js/lib/market.js`），`/lib/market.js` 在根包里不存在，且 tag 触发的客户端构建与 npm 发布并行、存在时序竞争，客户端构建必然失败（GAP §9.5）。

## 新增

### 1. 统一三端 DID 派生口径

| 端 | 文件 | 口径 |
| --- | --- | --- |
| Rust | `gsn-core/src/identity/did.rs` | `fingerprint = hex(SHA256(原始 32B 公钥)[..8])`（16 hex）；新身份 `did:nau:` |
| JS | `js/lib/keychain.js` | 同一口径（剥 SPKI 前缀取 32B 原始公钥）；新身份 `did:nau:` |
| 上游兼容 | 同上 | `Did::parse` / `parseDid` 同时接受 `did:aip:` 与 `did:nau:` |

- `did.rs`：常量 `METHOD_AIP = "aip"` / `METHOD_NAU = "nau"`；公开 `fingerprint(pubkey)`、`parse(s)`、`method()`、`identifier()`；`from_public_key` 改产 `did:nau:`；含 5 个单测。
- `keychain.js`：`SPKI_PREFIX`、`rawPublicKey()`、静态 `fingerprint`、`parseDid`（正则 `^did:(aip|nau):([0-9a-f]+)$`），保留 sign/verify。

### 2. 跨实现签名向量（真正的 cross-implementation 校验）

- 新增 `conformance/generate.mjs`：用 **Node/OpenSSL** 的 Ed25519 独立生成密钥与签名（PKCS8/SPKI 前缀手工拼接、`JSON.stringify` 固定键序 capabilities/did/name/stake），与 Rust 实现**不共享任何代码**。
- 产出 `conformance/vectors.json`。第一条向量取自上游自己的测试（`gsn-core/tests/cross_lang_signature.rs`）：
  - seed = `0x01 × 32`；公钥 = `8a88e3dd…b40f6f5c`；上游 DID = `did:aip:34750f98bd59fcfc`
  - 规范载荷 = `{"capabilities":["text-generation","mcp"],"did":"did:aip:34750f98bd59fcfc","name":"CrossLang","stake":100}`
  - 上游签名 = `e14d3f9e…65da0e`
- **本项目（Node 独立实现）产出的签名逐字节相同**，且 `Did::parse` 接受上游 `did:aip:` 前缀。这不是上游那种"自己验自己"的自洽检查。

### 3. ACA 运行时兼容上游身份

- `gsn-core/src/aca/runtime.rs` 的 `register_peer`：原用 `Did::from_public_key(pubkey)`（现产 nau）与传入 DID 严格相等，会拒绝声明 aip 的上游对端；改为 `Did::parse(did)` + `Did::fingerprint(pubkey)`，只比较 `identifier()`（与方法无关），aip/nau 均可注册。

### 4. 客户端构建链路根治

| 改动 | 文件 | 作用 |
| --- | --- | --- |
| 根包补 `/lib/*` 子路径 | 根 `lib/{aca,dht,keychain,market,mcp,models}.js`（6 个 re-export）+ 根 package.json files 加 `lib` | 让根发布包物理暴露 `/lib/market.js`，浏览器端可只引市场模块（market.js 仅依赖 models、不引 node:crypto） |
| 依赖改 `file:..` | `client/package.json`、`desktop/package.json` | 构建直接打包仓库根源码，根治"tag 构建时本版本 npm 包尚未发布"的时序竞争 |
| `install-links=true` | `client/.npmrc`、`desktop/.npmrc` | 让 `file:..` 按 files 白名单打包成 node_modules 内真实拷贝（默认 false 建 symlink，Vite 解析到 node_modules 外源码、CJS 不被转换） |
| default import + 解构 | `client/src/main.js`、`desktop/src/main.js` | `import AU from '.../lib/market.js'; const { AgentMarket, MIN_STAKE } = AU;`，规避 rollup 对 re-export CJS 命名导出的静态识别失败 |

## 说明 / 边界

- JS 保留**两套身份类**：`Keypair`（`js/lib/keychain.js`，did:nau，通用密钥对）与 `AipIdentity`（`js/lib/aca.js`，did:aip，面向 ACA，有 signObject/verifyObject/fromSeed，其口径本就正确、签名命中上游）。两者指纹口径已统一（仅前缀之分），功能侧重不同，不合并。
- 客户端桌面演示仍用固定 DID（WKWebView 无 node:crypto，市场结算链路本身不依赖 Ed25519 签名；要真用密钥签名需走 Rust 侧 Tauri command）。
- 完整 Tauri 成品（.dmg/.exe/.apk）由 `.github/workflows/client-build.yml` 在打 tag 时构建；本版本已保证其前端构建链路可用。

## 兼容性

- 完全向后兼容：上游 / 旧 `did:aip:` 身份与签名继续可验证；新身份额外使用 `did:nau:` 前缀。客户端构建方式变更不影响运行时业务 API。
