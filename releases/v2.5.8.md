# Release v2.5.8 — 精确整数账本（Money）+ 发布即托管，根治 f64 跨语言守恒失效

**发布日期**：2026-09-27
**主题**：把全链路金额从浮点（f64）改为精确整数（Rust `Money(i64)` / JS 安全整数 / Python `int`），守恒检查改为精确相等；发布任务即把预算锁定到托管账户，付款方余额不足一律拒绝，杜绝凭空铸币；用一份三端共享的金额向量证明 Rust 与 JS 逐账户余额一致。

## 背景

旧账本金额全程使用 f64，且 Rust 与 JS 的守恒容差相差六个数量级（Rust `0.001`、JS `1e-9`），浮点表示误差使"同一笔账"在不同语言得到不同结果，跨语言守恒必然失效（GAP §2.1）。更严重的是：付款方余额不足时，旧版结算会凭空铸币完成支付（GAP §2.3）；JS 发布任务时预算只从需求方扣除、未转入任何账户，发布后到结算前系统余额暂时少一块（中途不守恒）。

## 新增

### 1. Rust 精确整数金额 `Money(i64)`

- 新增 `gsn-core/src/marketplace/money.rs`：
  - `Money(pub i64)` newtype，`#[serde(transparent)]`；常量 `ZERO`、`MIN_STAKE = Money(100)`。
  - 方法 `new / as_i64 / is_negative / is_positive / checked_add / checked_sub / min`。
  - **刻意不实现 `Add / Sub`**：强制所有金额运算走 `checked_*`，从类型层面杜绝溢出与隐式铸币。
- 账本（`settlement.rs`）`balances: HashMap<String, Money>`：`deposit` 拒绝负数（checked），`transfer` 余额不足即 `Err`、不铸币；`conservation_check` 改为**精确相等、无容差**。

### 2. 发布即托管（Escrow），任意时刻守恒

- 账户命名（与 JS 对齐）：质押锁定 `__stake__:{agent}`、任务预算托管 `__escrow__:{task}`。
- `publish_task`：预算从需求方转入 `__escrow__:{task}`（钱仍在系统内）。
- `settle_task`：从托管账户支付给执行者（pay）、余款退回需求方（refund），结算后托管账户清零。
- 注册即把质押从自有账户转入 `__stake__:`；未充值即注册被拒绝（不铸币）。

### 3. JS SDK 整数化并对齐托管模型

- `js/lib/market.js` 新增 `_assertMoney(v, label)`：要求 `number` + `Number.isInteger` + `Number.isSafeInteger`，否则抛错；在充值 / 质押 / 发布 / 投标 / 罚没各入口调用。
- `submitBid` 与 `slash` 额外拒绝 `<= 0`（GAP §2.7：出价 0/负反而被判最优）。
- 新增 `_escrowAccount(taskId)`；`publishTask` 把预算转入 `__escrow__:`，`settle` 从托管账户 pay/refund（旧版预算发布后"消失"、结算时数学补回）。
- `conservationCheck` 改为 `balanceSum === expected` 精确相等（旧 `Math.abs(...) < 1e-9` 容差）。

### 4. Python SDK 类型对齐

- `aip/market_client.py`：`build_task_spec` 的 `budget`、`deposit` 的 `amount`、`arbitrate` 的 `slash_amount` 由 `float` 改为 `int`。

### 5. 跨语言金额向量（权威单一来源）

- 新增 `conformance/money-vectors.json`：定义同一市场场景（worker 充值100/质押100/投标10；requester 充值50；任务预算50；结算 pay10/refund40）。
- 期望逐账户：`agent-1 = 10`、`__stake__:agent-1 = 100`、`requester-1 = 40`、`__escrow__:task-1 = 0`。
- 期望聚合：`total_deposits 150 / total_paid 10 / total_slashed 0 / balance_sum 150 / conserved true`。
- Rust 测试 `test_money_vector_matches_conformance`（`v234_test.rs`）与 JS 测试读取**同一向量**，逐账户、逐聚合值断言一致。

## 说明 / 边界

- 整数账本以最小货币单位记账，不支持小数金额；如需更小粒度，应在更上游统一调整最小单位，而非在账本内引入浮点。
- 跨语言向量目前覆盖 Rust 与 JS；Python 为薄客户端（类型已对齐 int），其金额经 REST/JSON 传输，JSON 整数可被 Rust `Money` 精确解析。

## 兼容性

- 金额由浮点改整数属**接口口径收紧**：旧的浮点金额请求会被明确拒绝（而非静默舍入）。守恒、托管、质押、结算、罚没的业务语义与账户命名在 Rust/JS 间保持一致。
