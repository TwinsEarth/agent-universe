# v3.9.7 — 比特币/以太坊 Agent 经济体（8/9）：链上锚定最终性 + 跨链桥风控的纯链下确定性决策（确认数/显式最终性/重组深度/32B 承诺一致 + 开关/暂停/方向资产目的白名单/最小额/单笔上限/速率窗口/累计额度；只做链下 fail-closed 整数决策，不连 RPC/桥/合约、不读区块与时钟、不做默克尔或轻客户端证明、不构造签名广播跨链消息、不锁定/铸造/释放资产，生产 relay 默认 BRIDGE_NOT_CONFIGURED fail-closed）

## 一、交付了什么

v3.9.0–v3.9.6 已立「只决策不动钱」的结算路由、宿主签名闸门、EVM x402、闪电 L402、
ERC-8004、ERC-4337 Paymaster、BTC HTLC/RGB 纯校验面。v3.9.7 把 Agent 经济体在「据以
行动前」必须回答的两个安全问题做成纯链下确定性决策内核：**一笔跨链/锚定数据现在是否
已经足够安全可采信（锚定最终性）**，以及**一笔跨链转移在风控策略下是否允许放行（桥
风控）**。两者都只对调用方取证后传入的快照做整数决策，不联网、不读时钟、不持钥、不
真转资产；任何安全门槛不满足都具名 fail-closed，绝不返回「带警告的安全」。

本版本**不引入任何新 crate**（仅 std + 仓内既有 serde）；零浮点、零 syscall、零 unsafe、
无 IO、无生产 panic；金额全部 u128、计数 u64，checked 整数运算。

新增文件 `gsn-core/src/economy/payment/anchorguard.rs`，并扩展 `payment/mod.rs` 与
`plugin/system/mod.rs`。不改 router.rs（3.9.0）、signer.rs（3.9.1）、x402.rs（3.9.2）、
l402.rs（3.9.3）、erc8004.rs（3.9.4）、paymaster.rs（3.9.5）、htlc.rs/rgb.rs（3.9.6），
与它们并列、互不改动。它与 v3.3.0 的 chain-anchor 官方插件（keccak 锚定构造）、
v3.4.0 的 chain-bridge 官方插件（跨链信誉中位数共识）是不同位置，均不改动旧插件。

1. **锚定最终性决策 `verify_anchor_finality(policy, evidence)`**：按严格短路顺序判定——
   - 策略必须至少有一道安全闸门：`require_finalized=false` 且 `required_confirmations=0`
     一律 `ANCHOR_POLICY_NO_SAFETY_GATE`（拒绝在无任何最终性保证下运行）。
   - `source_chain` 非空，否则 `ANCHOR_BAD_CHAIN`。
   - **重组优先**：`observed_reorg_depth > max_tolerated_reorg_depth` 先拒
     `ANCHOR_REORG_EXCEEDED`（恰好等于容忍深度含放行）；重组判断先于确认数。
   - **最终性不可用确认数替代**：`require_finalized=true` 但取证 `finalized=false` 一律
     `ANCHOR_NOT_FINALIZED`。
   - 确认数严格门槛：`confirmations < required` 拒
     `ANCHOR_INSUFFICIENT_CONFIRMATIONS`，**恰好达门槛通过**。
   - 32 字节承诺规范化（可选 `0x`、hex 校验、大小写不敏感）：提供锚点承诺时须与声明
     承诺逐字节一致，不一致 `ANCHOR_COMMITMENT_MISMATCH`，坏 hex
     `ANCHOR_BAD_COMMITMENT_HEX`；**不提供锚点承诺则不报错但诚实置
     `commitment_verified=false`**。
   - 回执 `AnchorReceipt` 回显确认数/门槛/最终性/重组深度/承诺核对结果，且恒
     `onchain_read_in_kernel=false`；`anchor_safe=true` 仅表取证快照按策略自洽，不代表
     链上真实不可回滚。

2. **跨链桥风控决策 `decide_bridge_transfer(policy, req)`**：fail-closed 短路链——
   `enabled=false` → `BRIDGE_DISABLED`；`paused=true` → `BRIDGE_PAUSED`；
   `policy.validate`（`per_transfer_cap>0`、`rate_window_max_count>0`、
   `min_transfer<=per_transfer_cap`，否则 `BRIDGE_BAD_POLICY`）；方向白名单（**空默认
   全拒**，未知方向 `BRIDGE_DIRECTION_NOT_ALLOWED`）；资产白名单（**空默认全拒**，未知
   资产 `BRIDGE_ASSET_NOT_ALLOWED`）；可选目的白名单（要求但不在册
   `BRIDGE_DESTINATION_NOT_ALLOWLISTED`）；`amount>0`
   （`BRIDGE_NON_POSITIVE_AMOUNT`）；最小额（`BRIDGE_BELOW_MINIMUM`）；单笔上限
   （`BRIDGE_EXCEEDS_PER_TRANSFER_CAP`）；速率窗口（`prior_count+1` checked，超
   `rate_window_max_count` 即 `BRIDGE_RATE_LIMITED`）；累计额度（`prior+amount`
   checked_add 防溢出，`>cumulative_cap` 即 `BRIDGE_EXCEEDS_CUMULATIVE_CAP`，**恰好花完
   允许**，`cumulative_cap=0` 首笔即拒）。回执 `BridgeDecision` 回显投影后窗口笔数与
   累计用量，恒 `bridge_relay_executed=false`。

3. **真实跨链中继 fail-closed `relay_bridge_transfer()`**：本版本无任何桥后端，对任何
   请求一律 `BRIDGE_NOT_CONFIGURED` 具名拒绝；不连接锁仓/铸造合约，不构造、不签名、不
   广播跨链消息，不锁定/铸造/释放资产，绝不伪造锁定或释放结果。真实桥接须由宿主经独立
   闸门注入。

4. **PMB 字节桥**（同一 T0 系统插件 `com.twinsearth.sys.payment-router`）：新注册
   `anchor_finality_check` / `bridge_transfer_decide` / `bridge_relay` 三个 handler，连旧
   v3.9.0–v3.9.6 共 **22 个 handler**；两个请求体 `AnchorFinalityRequest{policy,evidence}`、
   `BridgeTransferRequest{policy,transfer}` 均 serde 反序列化，空/坏负载一律运行时拒绝不
   panic。`payment_router_status` 增 `anchor_finality` / `bridge_risk` 两段完整诚实块与
   `anchor_finality_introduced_in` / `bridge_risk_introduced_in = v3.9.7`，`enforceable`
   增 anchor_integer_confirmation_gate / anchor_reorg_depth_gate /
   anchor_finality_fail_closed / anchor_commitment_exact_match /
   bridge_fail_closed_when_paused_or_over_limit /
   bridge_default_deny_non_whitelisted_direction_asset /
   bridge_integer_checked_cumulative / bridge_relay_not_configured_fail_closed，`provided`
   增 anchor_finality_check / bridge_transfer_decide /
   bridge_relay_when_bridge_configured 三 true，与 anchor_onchain_read /
   anchor_merkle_or_lightclient_proof / bridge_or_contract_connection /
   crosschain_message_relay / asset_locking_minting_or_release 等 false 诚实位；
   `capabilities_declared` 由 8 增至 **10**（加 `chain:anchor:read`、
   `bridge:risk:decide`），`bridge:relay:execute` 与 `chain:anchor:write` 登记为后续保留
   能力。

内核仍零浮点、零 syscall、零 unsafe、无生产 panic、无 IO；不连 RPC/节点/桥/合约、不读
区块与时钟、不做默克尔证明/轻客户端证明/签名或聚合签名验证、不构造签名广播跨链消息、
不锁定/铸造/释放资产。确认数、最终性标志、重组深度、窗口计数、累计已用均由调用方取证
后显式传入，保持纯函数可复算、可审计。

版本映射：npm `@twinsearth/agent-universe` 3.9.7 ↔ Rust `gsn-core`/`gsn-daemon` 0.3.97。

## 三、诚实边界（做不到的具名拒绝）

- 本版本交付的是 **锚定最终性 / 跨链桥风控的纯链下确定性整数决策内核**，不是节点或桥
  集成，也不连任何 RPC/P2P/合约：不查链上真实确认数、不读区块/UTXO/事件日志、不做
  默克尔包含证明或轻客户端证明、不验交易签名或聚合签名、不连接锁仓/铸造合约、不构造或
  签名或广播跨链消息、不锁定/铸造/释放任何资产。
- `anchor_safe=true` / `approved=true` 只表示**调用方提供的取证快照按策略自洽且通过所有
  fail-closed 门槛**，不代表链上真实不可回滚，也不代表桥已执行；确认数、finalized、重组
  深度、窗口计数、累计已用全部由调用方取证传入，内核不读时钟、不联网，纯函数可复算。
- **承诺只做 32 字节 hex 形状与「锚点承诺==声明承诺」逐字节一致性**；不证明该承诺在链上
  真实存在或属于某区块头。不提供锚点承诺时不做比对且诚实置 commitment_verified=false。
- **最终性不用确认数替代**：require_finalized=true 时只有显式 finalized=true 才放行；本
  版不内置任何链的确认数/最终性常数，所有阈值是调用方策略输入。
- **风控决策不持久化**：速率窗口与累计额度的 prior 用量由调用方传入，内核不记账、不做
  时间窗推进；白名单为空默认全拒，策略非法具名 BRIDGE_BAD_POLICY。
- **relay 默认 fail-closed**：无桥后端时 bridge_relay 一律 BRIDGE_NOT_CONFIGURED。真实
  锁仓/中继/铸造须由宿主在后续版本经独立闸门授权，并与 v3.9.1 宿主签名闸门、v3.9.4
  ERC-8004 身份/信誉联动。
- ZK 支付意图 / OWS 统一钱包 / 合规接口在 **v3.9.8**。落地前相关方法不注册（NotFound）或
  只提供决策面，不伪造真网可用。
- 文档涉及的外部协议/生态数字（跨链桥采用、最终性机制、x402/L402 规模等）均为
  **第三方报道口径，非本仓复测**，内核不内置这些数字作为事实。
