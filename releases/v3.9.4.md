# v3.9.4 — 比特币/以太坊 Agent 经济体（5/9）：ERC-8004 三注册表纯协议内核（Identity 身份句柄绑定 + Reputation 带质押权重的整数信誉聚合 + Validation 独立验证者 BFT-lite（n≥3f+1）裁决；只做链下可验证决策面，不铸造 ERC-721 / 不连 RPC / 不读写链上注册表 / 不持私钥）

## 一、交付了什么

v3.9.0 立「只决策不动钱」的结算路由，v3.9.1 立「签名是宿主能力」的边界，v3.9.2 落地
EVM x402 纯协议面，v3.9.3 落地闪电 L402 纯协议面。v3.9.4 把 **ERC-8004 Trustless
Agents 三注册表（Identity / Reputation / Validation）上沙盒可以安全做的纯协议部分**
落地：在不连任何链、不持任何私钥的前提下，给出身份句柄绑定校验、带质押权重的整数信誉
聚合（守恒 + 自评拦截 + nonce 重放拦截）、独立验证者 BFT-lite（n≥3f+1）多数裁决。链上
注册表的真实读取/写入由调用方取证后以快照传入，或留待后续版本经宿主签名闸门单独授权。

本版本**不引入任何新 crate**（仅复用仓内已有的 `sha2 0.10` 与 `hex 0.4`，外加 std 的
`serde`/`collections`）；零浮点、零 syscall、零 unsafe、无 IO、无生产 panic；不连 RPC、
不广播、不划转、不铸造 ERC-721、不读取/写入链上注册表、不持私钥。

新增文件 `gsn-core/src/economy/payment/erc8004.rs`，并扩展 `payment/mod.rs` 与
`plugin/system/mod.rs`。不改 router.rs（3.9.0）、signer.rs（3.9.1）、x402.rs（3.9.2）、
l402.rs（3.9.3），与它们并列、互不改动。

1. **身份注册表 `IdentityRegistry`（Identity Registry 纯内核）**：以
   `token_id(u64) ↔ DID ↔ Ed25519 公钥(32B) ↔ tokenURI 的 SHA-256 承诺` 四元组建档。
   - `validate_did`：要求 `did:` 前缀、方法体非空、总长 ≤256、无空白/控制符。
   - `validate_pubkey_hex` / `hash_token_uri`：公钥须为 32 字节 hex；tokenURI 承诺按
     **标准 SHA-256（非 keccak）**求 hex。
   - `mint`（传 tokenURI 原文，内核自算承诺）与 `mint_with_hash`（传取证得到的承诺 hex，
     承诺必须本身是 32 字节 hex，否则 `InvalidUriHash`）；拒绝 tokenId=0、坏 DID、坏
     公钥、坏承诺，以及 token / DID / 公钥任一重复（`DuplicateIdentity`）。
   - 存储与比对统一 **剥 `0x`/`0X` 前缀 + 小写归一化**（`norm_hex32`），大小写不敏感，
     避免同一字节因表示不同被当成两个身份。
   - `verify_binding`：给定四元组返回是否与注册表快照**完全一致**；任何一项非法或不匹配
     返回 false（普通校验结论，不 panic）。

2. **信誉注册表 `ReputationRegistry` / 无状态 `aggregate_feedback`（Reputation Registry
   纯内核）**：
   - 四维 `ReputationDimension`：quality / speed / honesty / availability，维度间相互隔离。
   - `Feedback{reviewer, subject, dimension, score:i16(-100..=100), weight:u64(>0),
     nonce:u64}`；评分越界 `InvalidScore`、权重为 0 `InvalidWeight`、评审人=被评人
     `SelfFeedbackForbidden`、双方身份须在注册表内（否则 `UnknownIdentity`）、
     `(reviewer, nonce)` 重复 `DuplicateFeedbackNonce`（重放拦截）。
   - 累加全程 `i128`/`u128` checked 运算，溢出具名 `ArithmeticOverflow`。
   - `ReputationAccumulator::score_01k()`：无反馈返回中性 500；否则
     `clamp(signed_sum*500/(total_weight*100) + 500, 0..=1000)`——满分 +100 且权重足够
     时趋近 1000，满分负向趋近 0，**整数守恒、无浮点**。正/负反馈、权重偏置、维度隔离、
     中性默认都有锚点测试。
   - `ReputationSnapshot` 记录每维 signed_sum/total_weight/count；无状态
     `aggregate_feedback(&[Feedback], &IdentityRegistry)` 一次性对一批反馈做身份、自评、
     重放校验并按主体×维度聚合，供链下取证后复算。

3. **验证计账 `ValidationTally`（Validation Registry 纯内核）**：
   - 验证方法 `ValidationMethod`：stake_rerun（质押重跑）/ tee_attestation / zkml；
     裁决 `ValidationVerdict`：valid / invalid。
   - `ValidationVote{validator, method, verdict, weight}` + 32 字节证据哈希；
     `record_vote_checked` 校验验证者身份存在、证据为 32 字节 hex、权重 >0。
   - `decide()` 执行 **BFT-lite n≥3f+1**：总权重为 0 报 `InvalidQuorumTally`；某一方向
     需 `weight*3 >= total*2` 且**严格多于**对方才 ConfirmValid/ConfirmInvalid
     （故 2 valid / total 2 即满足 ≥2/3 且多于 0，判 ConfirmedValid；2 valid + 1 invalid
     = total 3 时 2*3≥3*2 成立仍 ConfirmedValid；1:1、1:2 未达 2/3 或未严格多于则
     Inconclusive）。权重以字符串输出到 PMB JSON，规避 u128 序列化精度问题。

4. **错误枚举 `Erc8004Error`（15 变体）**：稳定 `code()->&'static str` 与 Display/Error：
   InvalidDid / InvalidPubKey / InvalidTokenId / InvalidUriHash / DuplicateIdentity /
   UnknownIdentity / EmptySubject / SelfFeedbackForbidden / DuplicateFeedbackNonce /
   InvalidScore / InvalidWeight / InvalidEvidenceHash / InvalidQuorumTally /
   InvalidVerdict / ArithmeticOverflow。生产路径全部具名返回，不 panic。

5. **PMB 字节桥**（同一 T0 系统插件 `com.twinsearth.sys.payment-router`）：新注册
   `erc8004_identity_check` / `erc8004_reputation_aggregate` /
   `erc8004_validation_decide` 三个只读 handler，连旧 v3.9.0–v3.9.3 共 **13 个 handler**。
   调用方把从受信任索引/RPC 取证的身份快照（数组）连同待核输入传入，内核重建注册表后
   给出可复算结论；维度/方法/裁决字符串做白名单解析（非法维度/方法/裁决具名拒绝）。
   `payment_router_status` 增 `erc8004_introduced_in=v3.9.4` 与完整 `erc8004` 诚实块
   （`onchain_mint_or_write=false`、`evm_rpc_connection=false`、`live_registry_read=false`、
   `self_feedback_blocked=true`、`feedback_nonce_replay_guard=true`、`integer_only=true`、
   `fail_closed_on_bad_identity_or_quorum=true`、信誉区间/四维/三方法/2-of-3 规则），
   `enforceable` 增 `erc8004_integer_reputation_conservation` /
   `erc8004_bft_lite_two_thirds_quorum` /
   `erc8004_fail_closed_on_bad_binding_or_quorum` 三个位，`provided` 增三个 true 与
   `erc8004_onchain_registry_write=false`；`capabilities_declared` 由 4 增至 5（加
   `erc8004:registry:read`），`capabilities_reserved_later` 登记 `erc8004:registry:write`。

内核仍零浮点、零 syscall、零 unsafe、无生产 panic、无 IO；不连 RPC、不铸造 ERC-721、
不读写链上注册表、不持私钥、不广播、不划转。

版本映射：npm `@twinsearth/agent-universe` 3.9.4 ↔ Rust `gsn-core`/`gsn-daemon` 0.3.94。

## 三、诚实边界（做不到的具名拒绝）

- 本版本交付的是 **ERC-8004 纯协议决策内核（身份绑定 / 整数信誉聚合 / BFT-lite 裁决）**，
  不是链上集成：不铸造 ERC-721、不连任何 EVM RPC、不读取或写入链上 Identity /
  Reputation / Validation 注册表、不持私钥、不签名、不广播、不划转。调用方须自行从受信任
  索引/RPC 取证，把身份/反馈/投票快照传入；内核只保证在给定快照下的可复算与 fail-closed。
- **身份绑定 true 不等于链上真实持有**：只表示传入快照内四元组自洽；链上锚定、注册事件
  证明、ENSIP-25 关联等需有状态/链上读取，留待后续版本。
- 信誉聚合是**链下整数复算**，不自动同步到链上 Reputation Registry；分数范围、权重口径
  为本内核定义（0..=1000、中性 500），与任何已部署合约的真实取整规则不做等价声称。
- BFT-lite 仅按传入权重与 2/3 + 严格多数规则裁决，不负责验证者选举、质押真实性、
  equivocation 罚没或证据内容本身的真伪（stake_rerun/tee/zkml 的证据只校验为 32 字节
  hex，不验证 TEE 报价或 zk 证明）。
- ERC-4337 Paymaster 在 **v3.9.5**；BTC HTLC/RGB 纯校验在 **v3.9.6**；链上锚定/跨链桥
  风控在 **v3.9.7**；ZK 支付意图 / OWS / 合规接口在 **v3.9.8**。在对应版本落地前这些方法
  不注册（NotFound）或只提供决策/校验面，不伪造真网可用。
- 文档涉及的外部协议采用量/规模数字（ERC-8004 已注册 Agent/反馈数、x402 交易量、
  BlackRock 模型占比、稳定币市值等）均为**第三方报道口径，非本仓复测**，内核不内置这些
  数字作为事实。
