# v2.7.7 — 进程级隔离运行时（沙箱真正能跑代码）

在 v2.7.6 核心架构之上，本版本提供**在云电脑 / 普通 PC 上真实可跑**的进程级隔离运行时，不依赖 Docker/KVM。

## 新增：sandbox/runtime/

- `mod.rs`：`CodeLanguage`（Python / JavaScript，含 from_label）。
- `process.rs`：`ProcessSandbox`，实现 `Sandbox` trait。

## 隔离手段（strength = Process）

1. 每个沙箱独立临时目录（`au-sandbox-{id}`），作为唯一工作目录；
2. 子进程只在该目录内运行，文件操作经 `safe_join` 拒绝绝对路径与 `..` 逃逸；
3. 子进程 `env_clear`，不继承宿主环境，仅注入受限 PATH + cfg.env 白名单；
4. 经 `timeout -k 1`（超时强杀，退出码 124 → ResourceLimitExceeded）+ `bash -c ulimit`（进程/句柄上限）；
5. 不挂载宿主路径，仅能写自己的临时目录。

## 能力

- `run_code(language, code)`：写入 main.py / main.js 并调用解释器（Agent 主用法）；
- `exec(program, args)`：仅白名单解释器（python3/node），bash 需显式 `allow_shell`；
- `write_file` / `read_file`：路径校验，沙箱间文件互不可见；
- `pause` / `resume`：标记状态并保留文件（进程级无常驻进程，真正 checkpoint 在 v2.7.8）；
- `destroy`：删除临时目录。

## 实机验证

- Python：`print`、计算（21×2=42）、非零退出码（sys.exit(3)）均正确；
- JavaScript：node 正常输出（修复了默认 max_processes 64 导致 V8 worker 线程 abort 的问题，提升到 512）；
- 超时：`while True: pass` 在 1s 超时被强杀，返 ResourceLimitExceeded；
- 隔离：两沙箱同名文件互不干扰；路径穿越/绝对路径/非白名单程序/默认 shell 全部拒绝。

## 验证

- `cargo build` 通过；`gsn-core/tests/v277_test.rs` 17 项全过。

## 边界

进程级隔离不提供内核级隔离，不用于运行完全不可信代码；需要强隔离时用容器/microVM 后端（v2.7.8+）。
