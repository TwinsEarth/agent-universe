# Agent Universe v2.6.8 — MCP 认证闸门 + LLM 适配器去 panic

> 发布日期：2026-09-28 · gsn-core 0.2.68

## 主题

按 GAP-ANALYSIS §7.5 / §8.3 / §8.4 / §8.5 / §8.8 修 MCP HTTP 端点无认证挂动钱工具、握手状态机缺失、RequestId 无 Null、未知工具返回协议错误、以及 LLM 适配器每个 `chat()` 都 `unwrap()` + 空数组索引 panic。§8.6 SSE 假流、§7.6 `probe_all` 假网络分区检测归入 v2.6.9。

## 改动

### §8.8（严重）HTTP MCP 无认证挂动钱工具 → Bearer 闸门 + 默认安全
`sse::handle_post` 此前不读任何 header/token/origin 就把请求分发到 `market_deposit` / `market_arbitrate` / `market_settle_task` / `market_register_agent` 等动钱工具，任何能访问端口者均可提款/罚没。重写：
- `handle_post(body, market, auth_header, expected_token)` 增加认证参数；
- 配置 `MCP_BEARER_TOKEN` 后，必须带 `Authorization: Bearer <token>`，否则 HTTP 401；
- **未配置令牌时默认拒绝全部写/动钱工具**（`is_mutating_tool()` 集合 10 个），只放行只读工具——安全默认失败；
- `node.rs` 从请求头提取 `Authorization`、从环境变量读令牌并传入。

### §8.3 RequestId 无 Null
`protocol::RequestId` 增加 `Null` 变体。解析失败 / 非法请求的 JSON-RPC 响应回 `"id": null`（JSON-RPC 2.0 §5.1），不再回 `id:0` 伪造。

### §8.4 未知工具返回协议错误 → result + isError:true
`server.rs` / `sse.rs` 中 `tools/call` 未知工具此前返回 `-32001` 协议错误。改为正常 result 携带 `isError:true`，与桥接层对同一输入的行为一致。

### §8.5 无握手状态机 → initialized 闸门 + 版本解析
`McpServer` 增加 `initialized:bool`。握手前除 `initialize` 外全部方法返回 `-32002 NotInitialized`；`handle_initialize` 改为 `&mut self` 置位并读取客户端 `protocolVersion`。新增错误码 `NotInitialized(-32002)`、`Unauthorized(-32001)`。

### camelCase 修复（§8.7 局部）
`ToolResult.is_error` 此前序列化为 snake_case `is_error`，MCP 规范要求 `isError`。加 `#[serde(rename="isError")]`。

### §7.5 LLM 适配器每 chat() unwrap → 不 panic
`llm/adapter.rs` 五个适配器（OpenAI / Gemini / Anthropic / Doubao / Domestic）的 `chat()` 此前 `client.chat(&req).unwrap()` 且 `choices[0]` 空数组即 panic。改为 `match` 错误返回 `ERROR: ...` 文案结果，`choices/candidates/content` 空数组走 `.first()` 友好降级，不再在请求失败或空响应时崩溃。
