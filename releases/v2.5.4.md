# Agent Universe v2.5.4 — NAT 穿透增强

**发布日期**: 2026-09-26
**代号**: Traversal
**前置版本**: v2.5.3 (Mesh)

## 核心目标

v2.5.3 的 mesh 模块在单机和局域网内工作正常，但跨 NAT 场景下节点无法直连。v2.5.4 在真实 libp2p 层（而非模拟 nat 模块）加入 Circuit Relay v2、AutoNAT、DCUtR 打洞和 Ping 保活，使分属不同 NAT 的节点可通过公共中继跨网互连。

## 新增能力

### 1. Circuit Relay v2 客户端

- 类型: `libp2p::relay::client::Behaviour`
- 节点在 NAT 后可向公共中继申请 reservation
- 其他节点通过中继地址（`/p2p/<relay>/p2p-circuit/p2p/<target>`）dial 到本机
- SwarmBuilder 链新增 `.with_relay_client(noise, yamux)`

### 2. AutoNAT 自动 NAT 检测

- 类型: `libp2p::autonat::Behaviour`
- 主动向已连接节点发起 dial-back 探测
- 三态输出: `public` / `private_nat` / `unknown`
- 配置: retry_interval 10s, refresh_interval 30s, confidence_max 1

### 3. DCUtR TCP 打洞

- 类型: `libp2p::dcutr::Behaviour`
- 直连失败后自动协调双方同时向对方发起连接
- 打洞成功后升级为直连，无需中继转发

### 4. Ping 连接保活

- 类型: `libp2p::ping::Behaviour`
- 15 秒间隔保持 NAT 映射不过期
- 同时测量连接 RTT

### 5. 公共网络引导

- 新增 `P2pPeer::bootstrap_public_network()`
- 自动 dial 4 个官方 `bootstrap.libp2p.io` 节点（同时是 relay 中继）
- 新增 HTTP API:
  - `POST /api/v1/network/bootstrap-public` — 发起公共网络连接
  - `GET /api/v1/network/nat` — 查询 NAT 检测状态

## API 变更

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/v1/network/bootstrap-public` | POST | 连接公共 libp2p bootstrap/relay 网络 |
| `/api/v1/network/nat` | GET | 获取 AutoNAT 检测的 NAT 状态 |
| `/api/v1/network/info` | GET | PeerInfo 新增 `nat_status` 字段 |

libp2p features 新增:

## 真机部署修复（Windows 实测）

在真实 Windows 主机接入公共网络时，发现并修复两个阻断性问题，二者均为"feature 编译了但运行时未生效"类问题：

### 修复 1: 启用 RSA 密钥 feature

- **现象**: dial 公共节点报 `InvalidKey(DecodingError { msg: "cargo feature rsa is not enabled" })`
- **根因**: 官方 bootstrap/relay 节点使用 RSA 密钥（Peer ID 以 `Qm` 开头），而 libp2p 默认未启用 rsa
- **修复**: libp2p features 增加 `rsa` 与 `ed25519`
- **验证**: 独立诊断程序 694ms 连上 sg1（新加坡中继），ping RTT 448ms；修复后可正常连接 Qm 开头的 RSA 节点

### 修复 2: SwarmBuilder 显式启用 DNS 解析

- **现象**: `bootstrap-public` dial `/dnsaddr/bootstrap.libp2p.io/...` 报 `MultiaddrNotSupported(/dnsaddr/...)`
- **根因**: 仅在 Cargo features 中开启 `dns` 只会编译 libp2p-dns crate；SwarmBuilder 必须显式调用 `.with_dns()` 包装 transport，运行时才具备 `/dns4`、`/dns6`、`/dnsaddr` 解析能力
- **修复**: SwarmBuilder 链在 `.with_tcp()` 之后增加 `.with_dns()?`
- **验证**: `bootstrap-public` 端到端成功，dnsaddr 自动解析并连接，**connected 16、Kademlia routing_entries 124、AutoNAT 正确识别为 private_nat**

### 网络栈周期 poll 兜底

- `run_swarm_actor` 增加一个 5 秒静默 idle tick
- 原因: `tokio::select!` 在命令到达时会取消 `next_event` future，Kademlia 路由刷新、AutoNAT 重测、dnsaddr 解析等状态机依赖被反复 poll；idle tick 保证即使 waker 未及时唤醒也能推进网络栈

## 测试

- 单元测试: **102 passed / 0 failed**（DNS 修复后回归无变化）
- 真机测试（Windows, 广州家用宽带 NAT 后）:

## 边界声明

- 公共中继连接需要节点出站能访问 bootstrap.libp2p.io（TCP 4001/443）
- 出站严格受限的网络环境（仅 DNS）无法建立中继连接
- DCUtR 打洞成功率取决于 NAT 类型；对称型 NAT 打洞成功率低，仍需中继
- 原模拟 nat 模块（`src/nat/`）保留，mesh.rs 仍引用其数据结构；真实穿透由 libp2p 层承载
