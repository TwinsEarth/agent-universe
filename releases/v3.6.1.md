# v3.6.1 — daemon 自动更新（npm registry 权威源 + 双通道 + 白名单先锋/贡献者）

v3.6.1 是 v3.6.0 之后的**补丁版本（patch）**，新增 daemon **自动更新子系统**，并同时更新
**daemon 二进制**（GitHub Release 原始资产）与 **npm JS 包**（`@twinsearth/agent-universe`）。
本版不改任何资金 / 共识 / 持久化写入语义。

## 一、需求与行为

1. **每次启动联网检查**：daemon 启动时在后台任务（`spawn_blocking`，带超时、非阻塞）访问
   npm registry 完整 packument
   `https://registry.npmjs.org/@twinsearth%2Fagent-universe`，判断是否最新。
   检查结果只打印/记录一行；任何网络/TLS/解析失败都**不阻断启动**。
2. **双通道自动更新**：
   - **默认 Minor 通道**：只自动跟进同一大版本内最新「中版本基线」`x.Y.0`；当前中版本线上
     出补丁**不追**；也**绝不跨大版本**。
   - **Patch 通道（白名单先锋队员 & 贡献者）**：自动跟进同一大版本内最新「小版本」`x.Y.Z`。
     白名单为仓库内置、编译期嵌入的 `config/pioneers.txt`（Peer ID 每行一个），可用
     `GSN_PIONEERS_FILE` 追加、或 `GSN_UPDATE_TRACK=patch|minor` 显式指定本机通道。
3. **手动更新任意版本**：`gsn update <X.Y.Z>` 可更新到任意版本，**允许跨大版本/降级**；
   自动通道从不跨大版本，发现更高大版本时只提示手动命令。

## 二、命令

| 命令 | 行为 |
|---|---|
| `gsn update` | 按本机通道检查并自动更新 daemon + npm 包 |
| `gsn update --check` | 只联网检查，不安装 |
| `gsn update <X.Y.Z>` | 手动更新到指定版本（可跨大版本） |
| `gsn update --track minor\|patch` | 本次按指定通道选择目标 |
| `gsn update --no-npm` | 只更新 daemon 二进制 |
| `gsn version --check` | 只查询通道内目标与新大版本提示，不安装 |

环境变量：`GSN_AUTO_UPDATE=0`（启动只检查不自动安装）、`GSN_NO_UPDATE_CHECK=1`（完全关闭
联网检查）、`GSN_UPDATE_TRACK=minor|patch`、`GSN_PIONEERS_FILE=<path>`、`GSN_UPDATE_NPM=0`。

## 三、安全与正确性设计（对上游 v2.8.2 审计教训的贯彻）

- **版本权威源是 npm packument 全量版本表**，通道选择在本地按规则计算，
  **不盲信 `dist-tags.latest`**；预发布（`-rc`/`beta` 等）与畸形版本键一律忽略。
- **daemon 二进制更新 fail-closed**：安装前强制下载 `.sha256` 摘要（CI 每个资产都产出），
  实际 SHA-256 不符报 `ChecksumMismatch` 并拒绝落盘。
- **原子替换**：同目录唯一临时文件 → `sync_all` → Unix `chmod 0755` 后 `rename` 覆盖
  （旧 inode 上正在运行的进程不受影响）；Windows 先把旧 exe 改名为 `.old` 再落新，
  旧文件被占用（`PermissionDenied`）明确报 `LockedBinary`，不静默失败。
- **最小 HTTPS 依赖**：用已在依赖树的 `rustls 0.23`（ring provider）+ `webpki-roots 1.x`
  手写同步 HTTPS/1.1 客户端，只跟 https 跳转（≤4 跳），带响应体上限、读超时、Content-Length
  截断检查；**不引入 reqwest/hyper/native-tls/OpenSSL**，避免在 8C16G 构建机上 OOM。
- npm 走 `npm install -g --no-fund --no-audit @twinsearth/agent-universe@<ver>`
  （钉死精确版本，Windows 用 `npm.cmd`，超时 kill）；**npm 失败不致命**，daemon 二进制
  仍是权威更新，失败仅告警。
- 全程**类型化错误**，生产代码无裸 `unwrap/expect/panic`；网络调用全部在阻塞线程，
  daemon 主事件循环不被拖住。

## 四、发布资产（release.yml 变更）

三平台矩阵在保留原有 `tar.gz` / `zip` 外，**每个版本额外上传原始可执行文件 + sha256 摘要**，
资产名与 `gsn-core/src/update/registry.rs::platform_asset_name` 一一对应：

| 平台 | 原始二进制资产 | 摘要 |
|---|---|---|
| linux x86_64 | `gsn-daemon-x86_64-unknown-linux-gnu` | 同名 `.sha256` |
| macOS aarch64 | `gsn-daemon-aarch64-apple-darwin` | 同名 `.sha256` |
| windows x86_64 | `gsn-daemon-x86_64-pc-windows-msvc.exe` | 同名 `.sha256` |

macOS x86_64 及矩阵外平台 `platform_asset_name()` 明确返回 `UnsupportedTarget`，
**不猜测资产名**。该流水线仅由 `push: tags` 触发（无 `workflow_dispatch`），随本版 tag 产出。

## 五、诚实边界（不夸大）

- daemon 二进制安装后在**下次启动生效**；本版不强制重启正在运行的进程。
- **macOS x86_64（Intel Mac）无发布资产**，自动更新在该平台报不支持（仅 Apple Silicon 有产物）。
- npm 全局安装在无全局写权限 / 未装 npm 的环境会失败并告警，但不影响 daemon 更新。
- Windows 下 daemon 正在运行、exe 被占用时，更新报 `LockedBinary`，需先停止节点再更新。
- 检查源是 npm registry，下载源是 GitHub Release；任一不可达即本次检查失败并提示，不降级为
  「假装最新」。
- 白名单 `config/pioneers.txt` 目前为**占位名单（无真实 Peer ID）**，即所有节点默认 Minor 通道；
  先锋/贡献者 Peer ID 经 PR 审核合入后，下一版本生效。
