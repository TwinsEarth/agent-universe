# Agent Universe v2.6.7 — 记忆层加固（Memory Hardening）

> 发布日期：2026-09-28 · gsn-core 0.2.67

## 主题

按 GAP-ANALYSIS §7.1 / §7.2 / §7.3 / §7.4 / §7.7 修三层记忆的假哈希链、假 LRU、未执行的防污染与盲猜死循环。§7.5/§7.6 LLM 适配器与网络分区检测归入 v2.6.8。

## 改动

### §7.1 假「SHA-256」链 → 真 SHA-256 + 存载荷
`memory/layered.rs` 的 `sha256_hex` 实为 `DefaultHasher` 16 hex（64 位），假名、非密码学、且跨 Rust 版本不稳定；两条链都只存摘要丢弃载荷、轨迹不可复现。改为真实 `sha2::Sha256`（64 hex），每环同时保存载荷；`IntergenMemory::verify_chain()` 与 `TraceLedger::verify_chain()` 重算每一环，报出**首个**断裂索引。新增篡改任一载荷即被定位的测试。

### §7.2 假 LFU「LRU」→ 真 LRU
`memory/enhanced.rs` 此前按单调 `access_count` 最小淘汰（实为 LFU）。改为记录 `last_used` 逻辑时钟，写/查即 tick，淘汰最近最少使用项。测试 `eviction_is_lru_not_lfu` 特意构造为在 LFU 规则下会失败（a 被查 3 次后 b 最近使用，LRU 淘汰 a，LFU 会错误保留 a）。

### §7.3 防污染从未执行 → 派生质量 + 整数 bps
- `enhanced.rs` 评分从 `f64` 改整数 `score_bps`（1 bps = 0.01%），排序用 `cmp`，消除 `partial_cmp().unwrap()` 的 NaN panic；
- `shared_memory.rs` 删除发布者自报的 `weight: f64`（恶意发布者设 1.0 即胜出），改为记录 `successes/failures`，质量由 `quality_bps()` = 成功率×10000 **派生**、发布者无法谎报；
- `publish(entry, min_quality_bps)` 派生质量低于阈值返回 `BAD_REQUEST:` 拒绝上库；`best_strategy` 用整数 `max_by_key`。

### §7.4 飞轮诚实标注
`memory/flywheel.rs` 的 `is_spinning()` 是四个单调计数的闩锁（一旦为真恒真），`optimize_structure()` 只递增计数、并未接线任何真实拓扑/记忆模块。按 GAP 重写处理，不在本版伪造因果闭环：保留 API 作计数器快照，在模块文档明确「这是计数快照、不是已落地的反馈机制」。

### §7.7 blind_attempt 死循环
`swarm/memory.rs` 拒绝采样 `while tried.contains(&pick)` 在 `budget >= choices` 时永不终止。加防护：抽完所有可选项即 break，choices==0 早退，防御分支直接返回。
