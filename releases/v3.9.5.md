# v3.9.5 — 比特币/以太坊 Agent 经济体（6/9）：ERC-4337 账户抽象 Paymaster 纯确定性赞助决策内核（UserOperation 气体/费用字段校验 + v0.6 paymasterAndData / v0.7 paymaster+paymasterData 解析对齐 + 五类气体 checked 求和×maxFee 整数上估 + SponsorPolicy 开关/链/时间窗/白名单/单笔上限/累计预算 fail-closed 决策；只决策是否代付 gas，不连 bundler/EntryPoint、不广播 UserOp、不持 Paymaster 私钥、不垫付 gas、不链上质押）

## 一、交付了什么

v3.9.0 立「只决策不动钱」的结算路由，v3.9.1 立「签名是宿主能力」的边界，v3.9.2 落地
EVM x402 纯协议面，v3.9.3 落地闪电 L402 纯协议面，v3.9.4 落地 ERC-8004 三注册表纯协议面。
v3.9.5 把 **ERC-4337 Account Abstraction 的 Paymaster 在上沙盒可以安全做的纯决策部分**
落地：在不连任何 bundler/EntryPoint RPC、不持任何私钥的前提下，校验 UserOperation 气体/费用
字段、解析并对齐 v0.6 拼接式 `paymasterAndData` 与 v0.7 分离式 `paymaster`/`paymasterData`、
按整数上估最大 gas 成本，并在一份显式赞助策略下给出「赞助或具名拒绝」的确定性结论。真实的
担保签名、UserOp 聚合/广播、Paymaster 存款质押由宿主在后续版本经独立闸门授权，本版本一律
fail-closed，不伪造真网可用。

本版本**不引入任何新 crate**（仅复用仓内已有的 `hex 0.4` 以及 std 的
`serde`/`collections`，地址类型直接复用 `x402::EvmAddress`，不复制 keccak）；零浮点、零
syscall、零 unsafe、无 IO、无生产 panic；不连 RPC、不聚合/广播 UserOperation、不持私钥、
不产出担保签名、不垫付 gas、不在链上质押/充值、不校验链上 nonce/存款。

新增文件 `gsn-core/src/economy/payment/paymaster.rs`，并扩展 `payment/mod.rs` 与
`plugin/system/mod.rs`。不改 router.rs（3.9.0）、signer.rs（3.9.1）、x402.rs（3.9.2）、
l402.rs（3.9.3）、erc8004.rs（3.9.4），与它们并列、互不改动。

1. **v0.6 / v0.7 paymaster 字段纯解析对齐**：
   - `hex_decode`：剥 `0x`/`0X` 前缀，要求偶数长度 ASCII hex，坏字符具名返回 None。
   - `parse_paymaster_and_data`：v0.6 拼接式前 20 字节为 paymaster 地址、其余为 data
     （data 可空）；不足 20 字节 `PaymasterDataTooShort{bytes_len}`，坏 hex
     `BadPaymasterDataHex`。
   - `UserOperation::effective_paymaster`：同时接受 v0.6 `paymasterAndData` 与 v0.7
     `paymaster` + `paymasterData` 两种表示；两者都给且不一致 `PaymasterMismatch`，只给
     data 不给地址 `NoPaymasterProvided`，都不给则无 paymaster。

2. **气体/费用字段校验与整数上估 `UserOperationGas`**：七字段（preVerificationGas /
   verificationGasLimit / callGasLimit / paymasterVerificationGasLimit /
   paymasterPostOpGasLimit / maxFeePerGas / maxPriorityFeePerGas，均 u128/整数 wei）。
   - `validate`：除 `call_gas_limit` 允许 0 外，其余气体字段为 0 具名拒绝
     （ZeroPreVerificationGas / ZeroVerificationGas）；maxFee 为 0 ZeroMaxFeePerGas、
     maxPriorityFee 为 0 ZeroMaxPriorityFeePerGas、priority>max
     PriorityFeeExceedsMax。
   - `total_gas`：五类气体上限 **checked 求和**（callGas 允许 0）；`estimated_max_gas_cost`
     先 validate 再 `total_gas * max_fee_per_gas` checked 相乘，溢出具名
     `ArithmeticOverflow`，全程无浮点、无 panic、只上估不下估。

3. **赞助策略 `SponsorPolicy::decide_sponsorship`（fail-closed 决策链）**：策略字段
   paymaster 地址 / chain_id / enabled / allow_any_sender / whitelist(BTreeSet<[u8;20]>)
   / per_op_max_gas_cost_wei / total_budget_wei / valid_after / valid_until；决策输入
   `(uo, spent_before_wei, now_unix)`，`now` 由调用方显式传入（内核不读时钟）。按序短路：
   开关关 → PolicyDisabled；sender 零地址 → ZeroSender；paymaster 零地址 → ZeroPaymaster；
   链不符 → ChainMismatch；maxFee/maxPriority 零或越界（气体校验）；策略限额非法
   PolicyLimitsInvalid；时间窗非法 InvalidPolicyWindow，未到/已过 PolicyNotYetValid /
   PolicyExpired；effective paymaster 与策略地址不一致 PaymasterMismatch；上估 gas 成本；
   超过单笔上限 PerOpGasCostExceeded；非白名单且未放开任意发送者 SenderNotWhitelisted
   （**白名单为空默认拒绝全部**）；累计 `spent_before + estimated` checked 超过总预算
   BudgetExceeded（守恒，恰好花到预算允许、再超拒绝）。

4. **结论 `SponsorshipApproval` 与签名 fail-closed**：批准结论含 decision="approved"、
   paymaster/sender hex、chain_id、estimated_max_gas_cost_wei、spent_before_wei、
   budget_remaining_after_wei；**`produces_paymaster_signature=false`、
   `relays_user_operation=false` 恒为 false**。`preview_paymaster_signature` 恒返回
   `paymaster_signer_configured=false`/无签名；`sign_paymaster_data` 恒返回
   `PaymasterSignerNotConfigured`——本版本不持 Paymaster 私钥、不产出
   `validatePaymasterUserOp` 担保签名，绝不伪造。

5. **错误枚举 `PaymasterError`（23 变体）**：Serialize/Deserialize，Display 全
   `PAYMASTER_*` 前缀并 impl Error：PolicyDisabled / ZeroSender / ZeroPaymaster /
   ChainMismatch / ZeroMaxFeePerGas / ZeroMaxPriorityFeePerGas / PriorityFeeExceedsMax /
   ZeroPreVerificationGas / ZeroVerificationGas / BadPaymasterDataHex /
   PaymasterDataTooShort / NoPaymasterProvided / PaymasterMismatch / PolicyLimitsInvalid /
   InvalidPolicyWindow / PolicyNotYetValid / PolicyExpired / SenderNotWhitelisted /
   PerOpGasCostExceeded / BudgetExceeded / ArithmeticOverflow /
   PaymasterSignerNotConfigured。生产路径全部具名返回，不 panic。

6. **PMB 字节桥**（同一 T0 系统插件 `com.twinsearth.sys.payment-router`）：新注册
   `paymaster_userop_validate` / `paymaster_decide_sponsorship` / `paymaster_sign` 三个
   handler（decide 的白名单以 `Vec<String>` 入参再转 BTreeSet，坏地址返回
   `PAYMASTER_BAD_WHITELIST_ADDRESS` 运行时拒绝），连旧 v3.9.0–v3.9.4 共 **16 个 handler**。
   `payment_router_status` 增 `paymaster_introduced_in=v3.9.5` 与完整 `paymaster` 诚实块
   （produces_paymaster_signature=false、bundler_or_entrypoint_connection=false、
   useroperation_broadcast=false、live_gas_payment=false、paymaster_stake_or_deposit=false、
   onchain_nonce_or_balance_check=false、clock_read_in_kernel=false、整数 checked/默认
   fail-closed/白名单空默认拒），`enforceable` 增 paymaster_integer_gas_cost_checks /
   paymaster_fail_closed_when_over_limit_or_unconfigured /
   paymaster_default_deny_non_whitelisted_sender 三个位，`provided` 增三个 true 与
   erc4337_bundler_relay=false、erc4337_paymaster_stake_write=false；`capabilities_declared`
   由 5 增至 6（加 `erc4337:paymaster:decide`），`capabilities_reserved_later` 登记
   `erc4337:bundler:relay`、`erc4337:paymaster:stake:write`。为消除 serde_json 宏嵌套过深，
   status_payload 把 paymaster/enforceable/provided 三个大对象抽为独立局部 `json!` 变量。

内核仍零浮点、零 syscall、零 unsafe、无生产 panic、无 IO；不连 RPC、不聚合/广播
UserOperation、不持私钥、不产出担保签名、不垫付 gas、不链上质押/充值。

版本映射：npm `@twinsearth/agent-universe` 3.9.5 ↔ Rust `gsn-core`/`gsn-daemon` 0.3.95。

## 三、诚实边界（做不到的具名拒绝）

- 本版本交付的是 **ERC-4337 Paymaster 纯链下决策内核（字段校验 / gas 上估 / 赞助策略
  裁决）**，不是 Paymaster 合约集成，也不连 Bundler/EntryPoint：不聚合、不提交、不广播
  UserOperation，不模拟链上执行，不校验 EntryPoint 合约地址、链上 nonce、签名聚合或
  Paymaster 存款余额（这些需有状态/RPC，由调用方取证后自行保证）。
- **`decision=approved` 不等于链上会代付**：只表示在调用方传入的显式策略、链号、当前
  时间、已花费额度下，这笔 UserOperation 的上估 gas 成本落在限额/预算与白名单内；真实
  扣款发生在链上 EntryPoint 从 Paymaster 存款扣除，内核不参与。
- gas 成本是**按五个上限字段×maxFeePerGas 的最大上估**（整数 wei），不是链上实际扣费；
  实际 gas 用量、L2 专属字段（如 L1 data fee）、base/priority fee 的真实成交均不在内核
  计算内。
- **不持 Paymaster 私钥、不产出 `validatePaymasterUserOp` 担保签名**：`paymaster_sign`
  一律 `PAYMASTER_SIGNER_NOT_CONFIGURED` fail-closed；bundler 中继与链上质押/充值写方法
  未注册（NotFound）。真实签名后端/中继/质押留待宿主经独立签名闸门授权。
- 时间窗判定的 `now_unix`、`chain_id`、累计 `spent_before_wei` 与链上余额均由调用方显式
  传入，内核不读系统时钟、不联网，保持纯函数可复算。
- BTC HTLC/RGB 纯校验在 **v3.9.6**；链上锚定/跨链桥风控在 **v3.9.7**；ZK 支付意图 /
  OWS / 合规接口在 **v3.9.8**。在对应版本落地前这些方法不注册（NotFound）或只提供决策/
  校验面，不伪造真网可用。
- 文档涉及的外部协议采用量/规模数字（ERC-4337 生态、x402 交易量、Gas 费水平等）均为
  **第三方报道口径，非本仓复测**，内核不内置这些数字作为事实。
