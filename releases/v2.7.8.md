# v2.7.8 — 沙箱生命周期管理与弹性供给

在 v2.7.7 进程级运行时之上，新增 `SandboxManager`，管理多个沙箱的完整生命周期与弹性供给。

## 新增：sandbox/manager.rs

`SandboxManager` 提供：

- **批量创建 / 获取 / 回收**：`acquire` / `release` / `destroy`；
- **预热池（warm pool）**：提前创建并 start 空闲沙箱，请求到达即用，降低冷启动；
- **休眠唤醒**：`release` 把空闲沙箱 pause 释放资源，`wake` 唤醒；
- **Checkpoint**：把工作目录快照到 checkpoints 区；
- **Fork**：从活沙箱或 checkpoint 复制新沙箱，从同一起点继续（对应训练评测的 Reset/Fork/Replay）；
- **evict_idle**：回收休眠过久的沙箱并补预热；
- **shutdown**：清理全部。

## 配置变更

- `SandboxConfig` 新增 `work_dir_base`：管理器统一编排时指定沙箱目录父路径，保证所有沙箱（含 fork）落在 manager 根下；`ProcessSandbox` create 据此定位（否则用系统 temp_dir）。

## 实机验证（tests/v278_test.rs，13 项）

- 预热池填充到目标大小、acquire 优先取预热/池空时即时创建；
- release 后状态 Paused、wake 恢复 Running；
- 在 acquire 的沙箱上真实跑 Python 代码；
- checkpoint 生成含文件的快照；fork 继承父沙箱文件、父沙箱不受影响；从 checkpoint fork 同样成功；
- destroy 移除单个（不存在的返回 NotFound）；shutdown 清理全部；
- evict_idle 回收休眠沙箱并补预热（预热池中的不被回收）。

## 边界（如实标注）

进程级 checkpoint 只保存**文件系统状态与配置**，不保存解释器内存；真正的内存级 checkpoint 依赖 microVM（v2.8.0+ 部署）。
