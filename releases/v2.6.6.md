# Agent Universe v2.6.6 — HTTP & Storage Hardening（存储/HTTP 加固）

> 发布日期：2026-09-28 · gsn-core 0.2.66

## 主题

按 GAP-ANALYSIS §6.2 / §6.3 / §6.4 / §6.5 / §6.6 修存储锁毒化、守护进程 accept 容错、HTTP 方法校验、错误码类型化与 URL 解码。（§6.1 账本落盘 + 重启重放已在 v2.6.1 完成，本版不重复。）

## 改动

### §6.2 锁毒化根除
`storage/persist.rs` 22 处 `.lock().unwrap()` 一次持锁 panic 即毒化全局锁、之后每次存储调用都 panic。全部改为 `.lock().unwrap_or_else(|e| e.into_inner())`——锁中毒后取回内部数据、继续服务，不再永久杀死存储层。

### §6.3 accept 错误不再杀进程
`node.rs` 接收循环 `listener.accept().await?` 一次 `EMFILE`/`ECONNABORTED` 即从 `run_daemon` 返回 `Err`、整个 daemon 退出。改为：瞬时 accept 错误打印并退避 100ms 后继续 accept，listener 本身绑定失败仍按 `?` 返回。

### §6.4 写操作强制 POST（405）
此前绝大多数路由忽略 HTTP 方法：`GET /tasks/t1/settle` 真的会结算、`GET /disputes/d1/arbitrate` 会仲裁（无 body 时 `guilty` 默认 false），违反 HTTP 缓存语义。现在 TaskBids / TaskMatch / TaskResults / TaskVerify / TaskSettle / TaskResume / TaskReopen / DisputesCollection / DisputeArbitrate / AccountDeposit 全部要求 POST，非 POST 返回 **405 Method Not Allowed**。

### §6.5 错误码类型化，不再匹配中文子串
此前 `from_mr` 靠 `e.contains("不存在")` 这四个汉字决定 404 vs 422——任何恰好含该子串的校验错误都会被误判为 404，且无机器可读错误码。现约定机器码前缀：

- `NOT_FOUND:` → 404；
- `CONFLICT:` → 409；
- `BAD_REQUEST:` → 400；
- 其余 → 422。

marketplace / market_actor / qa_committee / proof 中 14 处「资源不存在」错误统一加 `NOT_FOUND:` 前缀；分类由 `match` 前缀决定，错误体原样回传。

### §6.6 url_decode off-by-one + UTF-8
`%` 转义判断 `i+2 < len` 改为 `i+3 <= len`，字符串末尾的 `%41` 现在正确解成 `A`；百分号编码的多字节 UTF-8（如 `%E4%B8%AD` = "中"）正确还原。
