# v3.8.2 — 面向 Agent 的资源市场（3/10）：计量账本（append-only 正计量 + consumed≤allocated + 整数实耗/待退结算视图）

## 一、交付了什么

v3.8.1 保证了"挂多少、预留多少不能超卖"。v3.8.2 回答订单真正执行起来后的问题：
**Agent 在沙盒里实际用了多少？用超了怎么办？实耗少于预留该退多少？** 本版新增
**纯确定性、内存态的计量账本**：按 `(订单, 资源形态, 计量维度)` 对真实用量做
append-only 正计量，累计实耗不得超过撮合预留上限，并以整数算出"实耗金额 / 待退金额
/ 预留总额"三个结算视图，为 v3.8.5 托管结算守恒提供计量侧依据。零浮点、零 syscall、
零 unsafe、无 panic 路径，数量/金额全部 `u128` checked 运算。

1. **计量线类型**（`gsn-core/src/economy/resource/metering.rs`，新增文件）
   - `UsageLine { order_id, kind, unit, allocated, consumed, unit_price_micro }`：某订单
     在某资源形态 + 计量维度下的一条计量账。`new` 即入场校验（非空订单 id、正预留
     `allocated`、正单价、`unit` 必须属于该形态 [`catalog::default_units`] 目录），
     初始 `consumed = 0`。
   - `allocated` 是撮合预留上限（= 成交量 filled_quantity）；`consumed` 是截至目前
     累计实耗，恒满足 `consumed <= allocated`，只增不减。
   - 整数金额（micro）：`consumed_cost = consumed × 单价`、`refund =
     (allocated - consumed) × 单价`、`reserved_cost = allocated × 单价`，全部 checked
     乘法；恒有 `reserved_cost = consumed_cost + refund`（托管守恒的计量侧依据）。
2. **计量账本 `MeteringLedger`（有序 Vec，确定遍历）**
   - 唯一键 `(order_id, kind, unit)`；有序 `Vec` 保证遍历/序列化顺序确定，便于单测与
     回放；规模为在计订单条目数，线性查找足够。
   - `open`：校验 + 唯一性（同键重复 → `RESOURCE_DUPLICATE_USAGE_LINE`）；同订单不同
     维度、不同订单同维度是不同键，可共存。
   - `record(amount)`：**只接受正增量的 append-only 计量**。amount 为 0 / 计量线不
     存在 / `consumed + amount > allocated` 一律具名拒绝；超配额报
     `RESOURCE_USAGE_EXCEEDS_ALLOCATION { consumed_after, allocated }`，且拒绝时账本
     **不被改写**（失败的上报不留痕、不冲减）。
   - `consumed/get`：未开线具名 `RESOURCE_USAGE_LINE_NOT_FOUND`（区别于"实耗为 0"）。
3. **整数结算视图 `settlement_view` → `MeterSettlement`**
   - 返回 `{ consumed, allocated, consumed_cost_micro, refund_micro,
     reserved_cost_micro }`，纯整数视图，**只算钱、不动钱**：本版不托管、不分账、不
     连链，供 v3.8.5 托管守恒（`escrow_locked = payout + royalty + governance_fee +
     refund_buyer + slashed`）取"实耗应付 / 少耗待退"两笔。
4. **跨订单聚合 + 全表不变量**
   - `total_consumed(kind, unit)`：某形态/维度下所有在计订单累计实耗之和（checked
     累加），无任何线条目时为 0，用于宿主做资源池维度的用量观测。
   - `invariant_holds()`：每条线恒有 `consumed <= allocated` 且
     `reserved_cost = consumed_cost + refund`，供宿主在关键边界 fail-closed 自检。
5. **4 个新具名错误 + 状态诚实位更新**
   - `ResourceError` 新增：`EmptyOrderId / DuplicateUsageLine / UsageLineNotFound /
     UsageExceedsAllocation`，全部补齐 `RESOURCE_*` Display 码。
   - PMB `resource_market_status` 诚实位更新：`enforceable.metering_ledger=true`、
     `provided.metering_ledger_persistence=false`（内存态、不持久化、非全局单例、不接
     真实用量上报通道）；escrow/stake/onchain 仍为 false，不夸大边界。

## 二、测试（旧实现无法表达的断言，8 新增）

`economy/resource/metering.rs` 8 个，全部针对"旧实现没有计量概念、会允许超配额/负冲减/
金额对不上"：

1. `open_valid_starts_zero_consumed_full_remaining`：合法开线 consumed=0、
   remaining=allocated、不变量成立。
2. `open_rejects_empty_order_zero_allocation_zero_price_foreign_unit`：空白订单 id、
   零预留、零单价、Compute 配 storage_gb_sec（越目录维度）四类入场拒绝。
3. `duplicate_open_rejected_distinct_units_and_orders_coexist`：同键重复开线拒绝；
   同订单 cpu/gpu 不同维度、不同订单同维度作为不同键共存。
4. `record_accumulates_and_never_exceeds_allocation`：600→900 累计，再要 200 越过
   上限 1000 `USAGE_EXCEEDS_ALLOCATION` 且账本不改写（仍 900），恰好到 1000 允许。
5. `record_zero_and_unknown_line_rejected`：未开线直接计量 NotFound（区别于实耗 0）；
   零增量拒绝（不接受负/零计量）；查询未知线 NotFound。
6. `settlement_view_conserves_reserved_equals_cost_plus_refund`：allocated 1000/单价
   2、耗 700 → consumed_cost 1400、refund 600、reserved 2000，守恒式成立；全耗尽时
   refund=0、实耗=预留。
7. `unknown_settlement_view_rejected`：未知线取结算视图 NotFound。
8. `total_consumed_aggregates_only_matching_kind_and_unit`：cpu 跨两订单聚合 650、
   gpu 仅 100 不混入，无线条目维度聚合为 0。

## 三、诚实边界

- 计量账本是**确定性内存记账面**：不持久化、不跨进程/跨节点共享、不是全局单例；宿主或
  沙盒计量探针在每笔订单上持有它并在真实消耗时调用 `record`。真实探针采集（CPU 毫秒/
  存储 GB·秒如何采样）、按墙钟的计费窗口、跨节点用量聚合不在本版。
- `record` 是**只增不减**的正计量：不提供负增量/冲减/回退写接口，防止把已用量"记回去"
  作弊或重复退款；订单取消/争议时的量如何处理由后续撮合（3.8.3）与托管结算（3.8.5）按
  订单状态决定，本版不提前假装。
- 本版**只算出**实耗/待退整数视图，**不托管、不分账、不罚没、不接真实支付/链**；资金
  守恒分账在 v3.8.5，质押罚没在 v3.8.4，BTC/ETH/稳定币结算与私钥隔离在 v3.9.x。
- `open/record/settlement_view` 是纯规则函数，本版**不自动**在订单
  `executing → metering` 状态转移时调用——订单↔容量预留↔计量的端到端联动随 v3.8.3
  撮合器接线；此处先保证规则本身可单测、不可超配额、守恒成立。
- 不新增能力令牌：计量属于市场内核内部记账，不直接对外暴露新 PMB 写方法；
  `resource_market_status` 仍为只读，未接线的写方法继续不注册（NotFound）。
- 外部数字（90% 沙盒 CPU<5%、超卖 50×、镜像访问 4.2–13.3% 等）仍为第三方报道、非本仓
  复测，仅作机制动机，不写进代码或作为已验证结论。
