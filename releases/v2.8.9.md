# v2.8.9 — 修复“声明大量不成立”：弱公钥拒绝、贡献验证 DID 绑定、生产 panic、NAT 守卫、毒化告警

对应《v2.8.2 增量审计 / Gap Analysis》**§2.2（声明不被代码支持）** 与 **§2.3（仍未修复）** 中
被点名的“上游声称修了、代码却没有”的条目。按审计两条自定规则——
**“没有调用点的修复不算修复”**、**“在修复前代码上也能通过的测试什么也没证明”**——逐条接入。

## 修复对应

| 审计条目 | 修复前问题 | 修复 |
|---|---|---|
| §2.2 弱公钥拒绝 | `is_weak_pubkey` 仅在 did.rs 定义，零非测试调用点 | 接入 ACA `register_peer`、REST `parse_committee_members`、PoC `verify_contribution_signed` 三个真实入口 |
| §2.2 贡献验证 DID 未绑公钥 | `verify_contribution_signed` 只验签，从不校验 `Did::fingerprint(pubkey) == verifier_did`，一把密钥可伪造不同 DID 绕过去重 | 验签前强制 DID 解析 + 指纹绑定 + 弱公钥拒绝 |
| §2.2 时钟 panic | 多处生产代码仍 `.unwrap()`/`.expect()` | 审计点名的时钟 panic 全部改为类型化错误 |
| §2.2 NAT 守卫 | `assert!(!nat_type.is_empty())` 任何新编造值都能通过 | 改为断言具体值 `assert_eq!(nat_type, "Unknown")` |
| §2.2 纠删码假测试 | `test_erasure_recover_from_parity` 把 6 个分片全交回，等于没测恢复 | 重写为丢 index 0、2 两个数据片，仅靠校验片重建 |
| §2.2 毒化恢复静默 | `into_inner()` 恢复后无任何日志，可能处于半写状态 | persist/沙箱/ffi 全部恢复点加 eprintln 告警 |

## 根因

- `is_weak_pubkey` 写了但没接进任何生产路径：注册委员、注册对端、贡献验证都可以用
  全零 / 平凡公钥通过。
- 带签名的贡献验证只证明“签名由该公钥做出”，却不证明“该公钥属于这个 DID”，于是
  同一把密钥贴上不同 DID 就能反复为同一贡献背书，绕过去重。
- QA 委员的“认证”此前只意味着已签名、不意味着已授权：测试用伪造 `did:nau:qa-i`
  与公钥不匹配也能通过。
- NAT 守卫是 `!is_empty()`，不锁死具体值，任何编造（如 `FullCone`）都能过。

## 修复

### 1. 弱公钥拒绝真正接入（§2.2）

- `identity/mod.rs` 导出 `is_weak_pubkey`。
- **aca/runtime.rs `register_peer`**：在 `Did::parse` 之前先拒绝弱公钥。
- **api/rest.rs `parse_committee_members`**：拿到每个 32 字节公钥后，弱公钥拒绝 +
  DID 解析 + `Did::fingerprint(&pk) == did.identifier` 绑定，任一不满足返回 400。
- **proof/poc.rs `verify_contribution_signed`**：找到记录后先做 DID 解析 +
  指纹绑定 + 弱公钥拒绝，再进入验签。

### 2. 生产 panic 改为类型化错误（§2.2）

- 审计点名的时钟 panic（erasure decode 循环、node relay class parse / AddBootstrap /
  ListenRelay、swarm/consensus、economy/reputation、economy/contribution、
  marketplace/reputation、identity/keyring、collaboration/hetero_llm 等）全部改为
  返回类型化错误。
- `net/peer.rs` 中真实 libp2p 固定构造（gossipsub 配置 / Behaviour 构造 / swarm 事件流）
  不在审计点名范围，保留并诚实标注。

### 3. 守卫与假测试诚实化（§2.2）

- `mesh/mesh.rs` 拓扑测试：`assert!(!nat_type.is_empty())` → `assert_eq!(nat_type, "Unknown")`。
- `tests/v232_test.rs test_erasure_recover_from_parity` 重写：
  - 丢掉 index 0、2 两个数据片，存活 4 个（数据片 1、3 + 校验片 4、5）；
  - 仅靠校验片重建全部数据并断言相等。
- `tests/v235_test.rs`、`tests/v273_test.rs` 中伪造的 `did:nau:qa-i` 全部改为
  由公钥派生的真实 DID（`did:nau:<Did::fingerprint(pk)>`）。

### 4. 锁毒化恢复加告警（§2.2）

- `storage/persist.rs` 全部 28 处连接锁、`node.rs` / `mcp/sandbox_tools.rs` 沙箱管理器锁、
  `ffi/uniffi.rs` 节点读锁的 `into_inner()` 恢复点，统一在恢复时 eprintln 告警，
  提示可能处于半写状态、需人工核查。
