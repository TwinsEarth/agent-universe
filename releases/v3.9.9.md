# v3.9.9 — 主网就绪加固版：CRDT 状态同步接线 + 纠删码分布式分片接线 + 链上信任锚完整代码路径（Base/Arbitrum 测试网+主网双就绪）+ DHT Server 模式规模修复（真实多节点 3/5/10/20/50 回归 + 分区/恶意节点 + Docker/Compose/CI/可观测/部署运维手册）

## 一、定位

v3.9.9 是 **v3.9.x 小版本序列的「主网就绪加固版」**：不是新功能大版本（资源市场 MVP
属 **v4.0.0**，需单独授权），而是把第一、二轮端到端复查暴露的「多节点组网 / 状态共享 /
分片冗余 / 链上信任锚 / 可观测与部署」链路，在本地修复、真实多进程回归并补齐交付物。

本版本的工作全部在本地完成：**未 push、未发 PR、未打 tag、未发 Release/npm**；版本号
仅预置（npm 3.9.9 ↔ gsn-core/gsn-daemon 0.3.99），发布动作待用户确认后统一执行。

## 二、交付了什么

### 1. 五个 P0（第二轮修复，第三轮回归）

| 编号 | 问题 | 修复 | 测试 |
|---|---|---|---|
| P0-1 | Kademlia 从不 `add_address`，DHT 无法自举 | ConnectionEstablished 臂 add 被 dial 地址；Identify listen_addrs 逐个 add；BootstrapDht 迭代 self-lookup | `p01_dht_add_address_populates_kbucket`、`p01_server_mode_serves_inbound_kad_query` |
| P0-2 | GossipSub 订阅了但入站 Message 零消费 | 补 `gossipsub::Event::Message` 分支 + `GossipDedup`（message-id 去重，FIFO 4096）投递应用层 | `p02_gossipsub_delivers_between_real_swarms`、`p02_gossip_dedup_filters_duplicates_and_evicts`、`p02_coldstart` |
| P0-3 | PoCV 可任意伪造 | 重写为 `SignedProofOfComputation`：贡献者 Ed25519 签名 + domain `AU-POCV/v1` + DID 指纹绑定 + nonce 防重放 + 实际 input/output SHA256 一致性校验，接入 `submit_result` | chain/pocv 10 个测试 |
| P0-4 | 经济写无鉴权，自报仲裁者即可罚没 | 新增 `marketplace/governance.rs`：`SignedGovernanceCommand`（domain `AU-GOV-CMD/v1`），`Governance::from_env` 读 `GSN_GOVERNANCE_FILE`，未配置 fail-closed；罚没/授信只接受受权治理集签名 | governance 11 + 市场接线 4 测试 |
| P0-5 | 同机多节点 PeerId 相同（身份绑死 `~/.gsn`） | 身份按 `--data-dir` 首次生成并持久化（`load_or_create_identity_in`，Unix 0600）；`with_data_dir` | `p05_identity_persists_per_data_dir` |

### 2. CRDT 状态同步接线（第三轮）

- 新增 `gsn-core/src/crdt/store.rs`：LWW 键值 Map（newer(ts,origin)），含 max_keys 上限。
- 订阅 `gsn/crdt`：GossipSub 低延迟 Op + 周期 Snapshot 反熵（`GSN_CRDT_SNAPSHOT_INTERVAL_SECS`
  默认 15s）；inbound 消费者按 topic 解析，`Op→apply_op`、`Snapshot→merge_snapshot`，
  解析失败只 warn（不 panic/不杀消费者）。
- `CrdtHandle` 与 REST `/api/v1/crdt` 系列（GET 汇总/stats/{key}、POST 写入/快照）。
- 防膨胀：`GSN_CRDT_MAX_KEYS`（默认 100_000）给键数硬上限，超限 dropped_capped；
  24h 增长脚本 `scripts/crdt-24h-growth.sh` 输出 CSV。

### 3. 纠删码分布式分片接线（第三轮，升级）

- 新增 `erasure/distributed.rs`：`ShardEnvelope`（StoreShard/NeedShards/ShardReply/
  BlobSealed）、`ShardTransport` trait、`DistributedShardNode`（FNV-1a 确定性放置、
  `original_size/shard_size` 随消息携带并校验 `payload.len()==shard_size`、缺失拉取有界
  重试、收满 data_shards 自动 RS 重建）。
- 新增 `erasure/wire.rs`：`ShardWire` 目标封装 + `GossipShardTransport` 桥接 GossipSub
  主题 `gsn/shards`；node 分片驱动 500ms tick 推进。
- REST `/api/v1/erasure/{ingest,reconstruct}`；冗余度默认 4 data + 2 parity。
- **真实 3 进程 e2e 实跑通过**：node0 ingest，node2/node1 本地分片不足（2/4），经
  NeedShards/ShardReply 跨节点拉取后 RS 重建，重建数据逐字节 MATCH（
  `scripts/regression-erasure.sh`）。

### 4. DHT Server 模式规模修复（第三轮关键）

- 根因：libp2p-kad 0.46 节点默认 `Mode::Client`，仅在确认外部地址后才转 Server；
  Client 模式用 `DeniedUpgrade` 拒绝入站 kad、不向 Identify 注册 kad，DHT 无法扩散。
- 修复：Archive/Full 节点启动显式 `set_kad_server_mode()`（Light/Edge/Browser 保持 Client）；
  ConnectionEstablished 仅 dialer 方 add 被 dial 地址、监听方跳过 ephemeral send_back_addr；
  新增跨节点查找 `GET /api/v1/network/find`。
- 真实多进程规模：**20 节点全 19 路由条（100% ≥ K=12）；50 节点 50/50 存活、42–46
  条、100% ≥ K=20，GATE_PASS=yes**。

### 5. 链上信任锚完整代码路径（第三轮升级）

- 新增 `chain/{config,rlp,keys,tx,eip712,paymaster,rpc,http}.rs`，详见第四节。
- 私钥/RPC 仅从环境变量或本地密钥文件；主网默认 fail-closed（需
  `GSEN_CONFIRM_MAINNET=1`）。
- 依赖新增最小密码学 crate：`sha3`（Keccak-256）、`k256`（features ecdsa/arithmetic），
  **未引入 ethers/alloy**，复用现有 rustls。

### 6. 可观测性 / 部署 / 工程

- 真实 `/health`：硬检查 storage（失败 503），软检查连接/DHT/CRDT。
- `/metrics`：Prometheus 文本（DHT 条目、连接数、GossipSub、CRDT 键数/ops/字节等）。
- `gsn-daemon --healthcheck`（手写 TCP，仅 http；`GSN_HEALTHCHECK_URL`）。
- 多阶段 Dockerfile（distroless static）+ .dockerignore + docker-compose（3/5 节点）。
- CI 改 Swatinem/rust-cache@v2，顺序 fmt→clippy→test→release。
- 文档：docs/DEPLOY.md、docs/ROLLBACK.md、deploy/systemd/gsn-daemon.service、.env.example。
