# v3.5.6 — 中继池遥测落盘失败显式化 + 市场层结算独立审计/防重复结算回归（#74）

v3.5.6 是 v3.5.5 之后的**补丁版本（patch）**。它收尾 GAP §3.6「持久化写入失败被静默
吞掉」在**网络中继池运维路径**上的残留，并为「按中标价付款 + 预算余款退回」补齐市场层
独立审计与防二次结算断言。不含功能新增，不改变任何资金/共识语义。

## 一、范围说明：结算中标价 + 差额退款早已落地，本版不重复实现

recon 证实 `AgentMarket::settle_task`（`marketplace/mod.rs`）在 v3.5.1–3.5.3 已实现：
拒绝/重复分支付 0 并退全额、10% 罚没走 `slash_stake_synced`；证据闸门通过后
`price = winner_price.unwrap_or(budget)`、`pay = price.min(budget)` 从托管付执行者，
再把 `budget - pay` 差额退回需求方，任务转 Settled。端到端用例已钉住
budget 50 / bid 10 / paid 10 / 执行者收 10 / 需求方余 40 / 托管 0 / 质押 100 / 守恒 150。

因此本版真实改动只有两块：**(A) 中继池遥测落盘失败显式告警；(B) 补两条市场层回归**。

## 二、修复

| 项 | 改动 |
|---|---|
| **A. relay 遥测不再静默** | 新增 `node::log_relay_persist_err(op,id,err)`，把 `node.rs` 中 **11 处**中继池 SQLite 写入的 `let _ = store.…(...)` 全部改为 `if let Err(e)=… { 打印 ⚠️ [relay-persist] … }`。覆盖：hop 自动入池、连接 `ConnectionClosed` / `OutgoingConnectionError`、reservation 续约、`ensure_channels` listen 失败、周期 probe 的 Ok(true)/Ok(false)/超时三分支、手动 `RemoveRelayCmd` 删除、`ExpandCapacity` 容量元数据、`init_relay_pool` 的 start_time/manual_bonus 两处。 |
| **B1. 市场层独立审计回归** | 新增 `test_market_independent_audit_passes_after_winner_price_refund`：走完完整市场状态机结算后断言 `independent_audit().passed`，且 `expected_total == actual_total == 150`、`replayed_records > 0`，同时守恒成立。 |
| **B2. 市场层防二次结算回归** | 新增 `test_market_settle_task_twice_rejected`：二次 `settle_task` 必须返回 `Err`（含「不能结算」，Settled 终态无入边），账户余额不再变、`settled_count` 不增加。 |

### 为什么告警而不是中断

这 11 处写入的是**尽力而为的运维遥测**（健康位 / 失败计数 / 容量元数据），不是资金账。
若让一次磁盘/锁错误向上传播，会拖垮整条 P2P/swarm 事件循环。因此控制流刻意不中断、
本次运行继续按内存状态工作，但必须**留痕**（与 `market_actor` 的 `warn_persist` 同一
原则：降级路径可观测）。资金路径不受影响——`append_ledger_record` 早已是「失败返回错误
且不推进水位」（v3.5.3 AU-14），本次未触及。

## 三、回归测试（旧行为下缺失的断言）

新增独立测试文件 `gsn-core/tests/v356_test.rs`（自包含，不依赖 v234 helper），2 个用例：

- `test_market_independent_audit_passes_after_winner_price_refund`
- `test_market_settle_task_twice_rejected`

此前 SettlementEngine 层有独立审计与防重复支付测试，但**市场层**（经完整任务状态机 +
真实 escrow/refund 账户）这两条路径无任何断言；状态机一旦放宽，二次结算会铸出第二笔款。
