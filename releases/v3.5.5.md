# v3.5.5 — gsn CLI 鉴权 / 金额 / 仲裁契约加固（W-03）与 daemon 版本开关（W-02）

v3.5.5 是 v3.5.4 之后的**补丁版本（patch）**，只修 `gsn` 命令行客户端与 `gsn-daemon` 的
参数/契约缺陷，不改变服务端资金与共识语义。

## 一、背景：CLI 与 v2.8.5/v2.8.6 之后的服务端契约已经漂移

守护进程在 v2.8.x 陆续收紧了 REST：写操作在配置 `REST_BEARER_TOKEN` 时必须带 Bearer、
deposit 金额只接受 JSON 整数、arbitrate 必填非空仲裁者且罚没由服务端规则决定。
但 `gsn market` 用的是一个手写的极简 HTTP/1.1 客户端，仍停留在旧契约，导致三类实际故障：

1. daemon 一开鉴权，所有 `gsn market` 写操作一律 401（客户端不发 `Authorization`）。
2. `gsn market deposit acct lots` 把非法金额静默存成 0 却返回成功。
3. `gsn market arbitrate` 发送已被服务端忽略的 f64 `slash_amount`，且不给仲裁者身份。

## 二、修复

| 项 | 改动 |
|---|---|
| **W-03-a Bearer** | `gsn market` 新增 `--token <t>` 与 `GSN_API_TOKEN`；非空时注入 `Authorization: Bearer <t>`，未配置不发该头（与无鉴权 daemon 兼容） |
| **W-03-b 金额** | 新增 `parse_amount`：仅接受十进制整数（可选 `+`/`-`），拒绝浮点/指数/千分位/空串/非数字/i64 溢出；非法即退出码 2，绝不发 `amount:0` |
| **W-03-c 仲裁** | 命令改为 `arbitrate <dispute_id> <guilty> <arbitrator>`；请求体仅 `{"guilty","arbitrator"}`，删除被服务端忽略的 f64 `slash_amount`；缺仲裁者报错 |
| **W-02 版本** | `gsn-daemon` / `gsn daemon` 新增 `--version` / `-V`，输出 gsn-core crate 版本后退出 |

`--api`/`GSN_API` 语义不变（默认 `http://127.0.0.1:4002`）。鉴权与节点地址均可通过命令行
或环境变量提供，令牌不会被写进进程命令行历史之外的持久位置。

## 三、回归测试（旧实现必失败）

在 `gsn` 二进制内新增 4 个纯解析单测（`cargo test --bin gsn`）：

- `amount_accepts_plain_integers_and_signs`
- `amount_rejects_non_integer_instead_of_defaulting_to_zero`
  —— 覆盖 `lots`/`10.5`/`10.0`/`1e3`/`0x10`/`1,000`/空串/i64 溢出，旧 `unwrap_or(0)`
  实现会把它们静默变 0。
- `deposit_body_carries_parsed_integer_and_rejects_bad_amount`
- `arbitrate_requires_arbitrator_and_omits_client_slash_amount`
  —— 缺仲裁者必须报错，请求体不得含 `slash_amount`，旧实现无法表达该契约。

## 五、诚实边界

- 本版只改 CLI 与参数解析，**不放宽也不旁路**服务端鉴权：Bearer 仍由服务端 fail-closed
  逻辑校验（配 token 必校验、未配默认拒绝写操作，除非显式 `REST_ALLOW_UNAUTHENTICATED=1`）。
- CLI 的手写 HTTP 客户端仍只面向本地/可信网络的运维用途，未引入 TLS 与重定向支持；
  跨主机公网访问应放在带 TLS 的反向代理之后。
