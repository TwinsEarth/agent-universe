# v2.7.4 — 重启恢复修复：agents/tasks 未注入内存 market

一个 Mac 真机部署才暴露的真 Bug：daemon 重启后，账本/余额/守恒从 SQLite 正确恢复，但 HTTP `/agents`、`/tasks/{id}`、`/stats` 全空 / 0 / `not_found`。

## 根因

`market_actor::spawn_with_store` 启动恢复时只对 `store.load_agents()` / `store.load_tasks()` 取了 `.len()` 打印日志，**并未把业务对象注入内存 market**——只有账本走了 `restore_ledger`。

于是重启后：

- SQLite 里 agents / tasks 快照明明在（`SELECT * FROM agents` 有行）；
- 内存 `AgentMarket.agents` / `AgentMarket.tasks` 两个 `HashMap` 却是空的；
- HTTP 层查的是内存 market，因此 `/agents` 返回空列表、`/tasks/{id}` 返回 not_found、`/stats` 计数为 0。

## 修复

三处：

1. **`marketplace/task.rs`**：新增 `TaskState::from_label(label: &str) -> TaskState`。磁盘存的是 `label()` 产出的大写字符串（`"SETTLED"`、`"NO_QUORUM"`…），恢复时需要反向解析；未知 / 空串 / 坏值一律回 `Open`，避免坏数据让状态机在恢复阶段 panic 或进入不可达状态。

2. **`marketplace/mod.rs`**：新增两个一等恢复方法：
   - `restore_agents_from_store(Vec<StoredAgent>)`：重建 `MarketAgentCard` 并重建 `skill_index`；快照未存字段（version / description / modalities / models / endpoint / pricing / sla 等）用安全默认值补齐。
   - `restore_tasks_from_store(Vec<StoredTask>)`：重建 `TaskSpec`；快照未存字段（context / done / todo / trace / required_skills / requester / winner_price / deadline）用安全默认值补齐，状态经 `TaskState::from_label` 反解析。

3. **`api/market_actor.rs`**：启动时真正调用这两个方法，把磁盘快照注入内存 market（替换原来只取 `.len()` 的日志行）。
