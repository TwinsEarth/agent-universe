# v3.9.13 — 自建 Relay 中继服务端 + 自有 P2P 服务器能力（打通闸门③ Mac↔Windows 跨网络互连）

## 一、定位

v3.9.13 是 v3.9.x 小版本序列的「自建中继服务端」版本：为 gsn-daemon 新增完整的
Circuit Relay v2 服务端能力（hop 角色），打通历史长期卡点 **闸门③ Mac↔Windows
跨网络跨版本互连**——此前跨公网互连缺自建中继节点，本次新增 `--relay-server`
服务端与 `--relay <addr>` 客户端注入，并提供配套部署包（含公网云服务器
`202.182.123.154` 部署步骤）。

按版本语义：v3.9.13 为小版本（插件级更新），只更新网络层中继相关模块，对系统
其他插件无影响；不触碰 v4.0.0（预留给「一切面向智能体开发！」架构）。

## 二、交付了什么

### 2.1 中继服务端能力（gsn-core/src/net/peer.rs）

- `PeerBehaviour` 新增 `relay_server: Toggle<relay::Behaviour>`（libp2p-relay
  0.18.0 Circuit Relay v2 服务端，hop 角色；Toggle 用于「未启用时行为完全缺席」）。
- 新增构造：`with_data_dir_relay(data_dir, Option<relay::Config>)` 与
  `with_identity_relay(local_key, Option<relay::Config>)`；原构造转发 `None`。
- `PeerEvent` 新增 `RelayServer(relay::Event)` 分支与 `impl From<relay::Event>`。
- 修复 libp2p-swarm 0.45.1 移除 `Option<T>: NetworkBehaviour` impl（E0277）：
  全部改用 `swarm::behaviour::toggle::Toggle<T>`。

### 2.2 CLI 与运行接线（gsn-core/src/node.rs）

| 参数 | 说明 | 默认 |
|---|---|---|
| `--relay-server` | 启用 Circuit Relay v2 中继服务端 | false |
| `--relay <addr>` | 注入自建 relay 地址（多值，同 `--bootstrap` 吞值模式） | 空 |
| `--relay-max-circuits` | 服务端最大并发 circuit 数 | 512 |
| `--relay-max-reservations` | 服务端最大 reservation 数 | 1024 |

- `--relay` 注入后：`extract_relay_peer_id` 取 relay_id → `store.upsert_relay`
  （Dedicated 分类，relay_pool 优先级最高）→ `peer.add_bootstrap(addr)`；
  `ensure_channels` 自动消费并 `listen_via_relay` 建立 reservation。
- 服务端启动后打印「🔄 Relay Server 已启用」与「其他节点请以
  `--relay /ip4/<本机公网IP>/tcp/{port}/p2p/{peer_id}` 加入」。

### 2.3 部署包（deploy/relay/）

- `docker-compose.yml`：中继服务端单容器，端口 4001（libp2p）与 4002（HTTP API）。
- `systemd/agent-universe-relay.service`：生产级 systemd 单元。
- `deploy-relay.sh`：一键部署脚本（含 peer-id 获取与通告）。
- `README.md`：公网服务器 `202.182.123.154` 部署步骤 + 客户端 `--relay` 用法 +
  多节点同机部署 `--api-port` 注意事项。
