# v3.8.7 — 面向 Agent 的资源市场（8/10）：四维信誉账本（quality/speed/honesty/availability，不可转让、整数评分、归一权重复合分，为撮合优先级/定价权提供确定性输入）

## 一、交付了什么

资源市场到 v3.8.6 已经有「容量→计量→撮合→质押→托管结算→快照版税」的资金/资源
记账链，但撮合排序与后续定价缺一个确定性的**信任输入**：某个供给方/Agent 结果好不好、
快不快、诚不诚实、稳不稳。v3.8.7 新增**四维信誉账本**，把每笔已结算订单的事后反馈按
四个相互独立的维度累计：

- `quality` 结果质量；`speed` 交付速度；`honesty` 诚实度（作弊/谎报/equivocation）；
  `availability` 可用性（接单/在线/履约稳定）。

新增文件 `gsn-core/src/economy/resource/reputation.rs`。纯确定性内存记账面：零浮点、
零 syscall、零 unsafe、无 panic 路径。评分整数 `0..=100`（`MAX_RATING`），均值用整数
**千分位 permille** 表达（`PERMILLE=1000`，100000 permille = 100.0 分），
`sum×1000/count` 确定性向下取整；复合分用四维之和恰为 **1000‰** 的整数权重加权（默认
等权各 250‰，`DimensionWeights::new` 对非归一权重 fail-closed）。信誉**绑定身份、
不可转让**：账本只有「记反馈 `record`」与「读聚合」，没有任何转账/过户/买卖接口
（不可转让性在 API 表面编译期保证，并有测试断言主体间分数互不影响）。

单一事实源与守恒：账本只保存不可变反馈日志 `ReputationFeedback`，所有维度求和/计数/
均值/复合分都在查询时由日志确定性 fold（不另存会漂移的累加器）。`invariant_holds`
独立复核：①权重归一；②全表反馈数 == Σ 每个主体反馈数；③各维千分位均值 ∈
[0,100000]；④复合分经**两条独立路径**重算一致——路径 A 逐维度均值加权，路径 B 对每条
反馈先算四维加权复合分再对反馈取均值。

核心 API：`record(ReputationFeedback)`（空 feedback_id / 空主体 / 任一维分 >100 /
重复 feedback_id 全部 fail-closed，且拒绝不落账）、`dimension_sum`、
`dimension_average_permille`、`composite_permille`、`feedback_count_for`、
`subjects`、`len/is_empty/feedbacks`。`ResourceError` 新增 5 变体
（`EmptyFeedbackId`/`EmptyReputationSubject`/`ReputationRatingOutOfRange{dimension,value}`/
`DuplicateReputationFeedback{feedback_id}`/`ReputationWeightsNotNormalized{sum}`）并复用既有
`ArithmeticOverflow`，全部补齐对应 `RESOURCE_*` Display；PMB
`resource_market_status` 诚实位 `enforceable.reputation_scoring=true`、
`provided.reputation_ledger_persistence=false`，`stake_slash/onchain_payment` 仍 false
（同步系统插件 status 快照测试）。

## 二、测试（旧实现无法表达的断言，7 新增）

`economy/resource/reputation.rs` 7 个，全部针对「此前市场链没有任何跨订单信任信号，
无法表达四维评分、无法确定性聚合、无法保证信誉只随自身反馈变化且不可转让」：

1. `record_feedback_updates_four_dimensions_and_mean`：单条 (90,80,70,100)，各维 permille
   均值=评分×10，等权复合=(90+80+70+100)/4=85 分=85000，不变量成立。
2. `multiple_feedback_integer_mean_deterministic_floor`：多反馈整数均值确定性向下取整
   （(90+71)/2=80.5→80500；90+90+91 →271*1000/3=90333）。
3. `rating_out_of_range_rejected_and_not_recorded`：四维任一 101/200/102 越界拒绝
   （带 dimension/value），账本不污染；边界 0 与 100 合法。
4. `duplicate_feedback_id_once_and_empty_fields_rejected`：重复 feedback_id（即便主体
   不同）全表唯一拒绝，空 id/空主体拒绝，且不新增记录。
5. `unknown_subject_returns_zero_not_error`：无反馈主体各维均值与复合分返回 0 而非报错，
   subjects 为空，不变量成立。
6. `custom_normalized_weights_composite_and_weight_validation`：非归一权重和 950 拒绝
   （带 sum=950）；400/200/300/100 合法，单条 (90,80,70,60) 复合
   =(36000+16000+21000+6000)/1000=79 分=79000。
7. `multiple_subjects_independent_and_non_transferable`：两主体多反馈计数独立
   （全表 3=alice2+bob1），alice 复合 75、bob 复合 40，互不影响；API 无 transfer
   （不可转让），subjects 首次出现顺序确定，不变量成立。

## 三、诚实边界

- 信誉账本是**确定性内存记账面**：不持久化、不跨进程/跨节点、不是全局单例；宿主市场
  门面持有它。本版只**接收有界反馈并确定性聚合**出四维均值与归一复合分，**不自动采集
  真实质量/速度/诚实信号、不做 BFT 验证、不自动驱动撮合排序或定价、不经 PMB 受理外部
  写、不新增能力令牌、不连链**。
- 评分来源在本版是**入参**：账本校验的是「评分 ∈0..=100、一笔订单只评一次、主体非空」，
  不担保评分本身真实——防买方刷分/女巫/合谋需要 v3.8.8 的 BFT-lite QA（n≥3f+1）抽样
  验证与 v3.8.4 质押罚没联动，本版不做。
- **信誉不可转让**在本版的含义是「没有任何转移 API、分数只随主体自身反馈 fold」；它
  尚不是链上不可转让（ERC-8004 Reputation Registry 的链上锚定/可移植身份在 v3.9.4），
  也不提供信誉衰减、时间加权、申诉撤销（反馈一旦记入不可变日志即不改写，与审计友好
  一致；未来如需纠错应走追加更正单而非抹除）。
- 权重为调用方提供的静态归一组，本版不做按场景学习/自适应权重；动态定价、信誉溢价、
  稀缺度定价在 v3.8.9。真实 BTC（闪电/L402/RGB）、ETH/稳定币（x402/ERC-8004）结算与
  私钥隔离在 v3.9.x。
- 外部数字（90% 沙盒 CPU<5%、超卖 50×、x402/BlackRock/ERC-8004 采用量等）仍为第三方
  报道、非本仓复测，仅作机制动机，不写进代码或作为已验证结论。
