# v3.7.6 — AUSec 内存共享（3/3）：回收/超卖统计 + 越界拒绝 + Linux 专有原语诚实门（patch）

## 一、交付了什么
本版为 AUSEC-DESIGN §3.1 中 v3.7.6 的三项交付，全部**跨平台、纯确定性、只读/决策**，
不调用任何 syscall、不碰真实页、不修改 v3.7.4/v3.7.5 的既有语义：

1. **回收/超卖统计只读汇总**（`memory.rs` 新增 `ReclaimLedger` + `ReclaimStats`）
   - `ReclaimLedger` 把一次次 v3.7.5 的 `ReclaimPlan` 作为**不可变历史**入账，
     账本本身无 OS 依赖；`ReclaimStats` 由已入账记录 + 可选当前配额池
     （`MemoryPool`）+ 可选当前空闲观测**确定性重算**。
   - 汇总字段：`records / cumulative_reclaimed_bytes / cumulative_target_bytes /
     cumulative_shortfall_bytes / sufficient_records / insufficient_records /
     reclaim_success_rate_permille / distinct_reclaimed_sandboxes`，以及在给出池/观测时
     才有的 `physical_bytes / committed_bytes / nominal_bytes /
     current_overcommit_permille / cumulative_reclaim_of_committed_permille /
     idle_footprint_bytes / reclaimable_idle_bytes / idle_reclaimable_fraction_permille`
     （千分点口径，全程无浮点；缺池/缺观测对应字段为 `null`，不凭空造比例）。
2. **越界拒绝（fail-closed，入账即校验）**——这是本版的安全核心：
   - `ZeroReclaimStep`：任何 `bytes==0` 的回收步骤拒绝入账（伪造的空动作不能进账）；
   - `ReclaimStepTotalMismatch`：步骤合计 ≠ 声明 `reclaimed_bytes`（账实不符）拒绝；
   - `RecordReclaimedExceedsTarget`：声明回收 > 目标，或 `shortfall_bytes` 与
     `target−reclaimed` 不自洽，拒绝；
   - `ReclaimArithmeticOverflow`：历史求和溢出 u64 拒绝；
   - `ReservedReclaimOverflow`：观测的 `reserved_bytes + reclaimable_idle_bytes`
     溢出 u64（申报边界不合法）拒绝；
   - 空/重复 `sandbox_id` 沿用 v3.7.5 的 `EmptySandboxId / DuplicateIdleObservation`。
   - 任意一条记录非法 → 整体拒绝、账本不变（不会出现"半条好看记录污染统计"）。
3. **Linux-MicroVM 专有内存原语诚实门**（新增 `gsn-core/src/ausec/primitives.rs`）
   - 对 virtio-pmem / DAX / DAMON / virtio-balloon 四原语建模
     （`MemoryPrimitive`、`MemoryPrimitiveState{DeclaredLinux, Unsupported}`、
     `MemoryPrimitiveStatus{state, can_enforce, detail}`）。
   - **Linux**：识别/声明为平台层面存在的 Linux-MicroVM 原语，但状态是
     `declared_linux` 且 `can_enforce` **恒为 false**——v3.7.6 执行器未接线，
     不声称已真实共享/回收任何物理页。
   - **macOS / Windows / Other**：一律 `unsupported` 并附**具名理由**
     （依赖 Linux KVM/Firecracker guest 的 virtio/内核能力，本平台无对应原语），
     不静默、不降级、不把"记账策略生效"谎报成"OS 原语生效"。
   - 该门与 `backend.rs` 的 `PrimitiveAvailability × executor_wired` 双层诚实模型一致：
     平台有原语 ≠ 本仓已强制执行。

- `ausec/mod.rs`：re-export 新类型；系统插件 `com.twinsearth.sys.ausec` 新增两个
  **只读** PMB 方法并在单一 dispatch 点接线（常量/解析/入口/字节桥/register 对称）：
  - `reclaim_stats`：入参
    `{records?:[ReclaimPlan], observations?:[SandboxIdleObservation], physical_bytes?,
    overcommit_times?|overcommit_permille?, sandboxes?:[...]}`；历史逐条入账校验，
    任一非法即报错；不给出 `physical_bytes` 时纯历史/观测口径（池字段为 null）。
  - `memory_primitive_status`：入参
    `{primitive?: "virtio_pmem"|"virtio-pmem"|"dax"|"damon"|"balloon", platform?:
    "linux"|"macos"|"windows"|"other"}`；缺省返回当前平台四原语，可注入 platform 做
    跨平台确定性核查；未知原语/平台 fail-closed。

## 三、诚实边界
- virtio-pmem / DAX / DAMON / virtio-balloon 都是 **Linux KVM/Firecracker guest**
  专有原语；本版在 Linux 也**只是声明/识别，执行器未接线**，`can_enforce=false`，
  不会真实共享宿主页缓存或回收 guest 空闲页；在 macOS/Windows 无原语，**具名拒绝**。
- 外部降幅（virtio-pmem+DAX 峰值内存降约 40.2%、DAMON+balloon 按时间累计内存再降
  约 21.2%、资源超卖 50×、约 90% 沙盒 CPU<5% 等）均来自 **aiwiki.ai /
  byteiota.com 对 DSEC 的报道，非本仓复测**；代码与输出中均以「外部报道、非本仓复测」
  标注，本版不声称在本仓复现。
- 回收/超卖统计是**记账口径的确定性重算**：累计回收量来自调用方提交并通过账实校验的
  历史计划，当前超卖/空闲占比来自调用方给出的池/观测，不读真实 OS 内存计数。
- 统计只证明"提交的记录自洽且与声明一致"，不证明底层物理页真的被回收——后者要等
  Linux-MicroVM 执行器接线（届时必须把对应原语的 `can_enforce` 改为 true 并附真实
  执行证据，现有回归锁会强制这一点显式发生）。
