# v2.8.4 — 重启恢复证据闸门/结果信封/信誉/质押（根治“重启即绕过”）

对应《v2.8.2 增量审计 / Gap Analysis》**§3.2【critical】**：
v2.8.2 的 `restore_tasks_from_store` 对快照未存字段用“安全默认值”硬编码补齐——
`verification_policy: None`、`winner_price: None`、`requester: 空`、`deadline: 0`。
结算闸门（`if !matches!(task.verification_policy, VerificationPolicy::None)` 才做
证据检查）对 `None` 豁免，且 `winner_price.unwrap_or(budget)` 按**满额预算**支付。
这使“**重启守护进程**”本身成为一条绕过路径：每个从磁盘恢复的任务自动豁免证据
闸门、按满额付款。同节另外三条：结果信封从不落盘、信誉与质押从不落盘、上游
持久化测试只断言“行又出现”，三条全部漏过。

## 根因

- 旧快照只存了任务的基础字段，**决定结算安全的字段（验证策略、中标价、
  结果信封、信誉、质押）根本没有落盘**；恢复时只能用“看起来安全”的默认值。
- 结算闸门把 `None` 当作“无需证据”，于是恢复任务默认回到最宽松策略；
  `winner_price.unwrap_or(budget)` 把“中标价缺失”直接放大成满额支付。
- 结果信封（`results`）在结算时被 `settle_task` 要求存在，但只活在内存——
  关机时处于“已验收未结算”的任务，重启后永远无法结算。
- 信誉与质押（`reputation_mgr`）只活在内存：重启后 `submit_bid` 对每个
  agent 因找不到 `Locked` 质押而失败，`arbitrate(guilty=true)` 报“无质押
  记录”，但质押资金仍在账上——罚没路径在重启后是死的。

## 修复

### 1. 任务快照补齐结算安全字段（§3.2 前半）

- `StoredTask` 加 4 字段：`winner_price: Option<i64>`、
  `verification_policy: String`、`requester: String`、`deadline: i64`。
- `snapshot_tasks_for_store` 完整填充；`tasks` 表加对应 4 列（含旧库
  `DEFAULT` 兼容）。
- 旧库迁移 `migrate_tasks_v284()`：`PRAGMA table_info` 检测
  `verification_policy` 列，缺失则 `execute_batch` 加 4 列；幂等。
- 恢复时：
  - 策略三分支——解析成功用值；**非空损坏回 `None` 并 `eprintln!`
    “持久化损坏…请人工核查”**；**v2.8.4 前遗留空值回 `None` 并
    `eprintln!` “遗留数据…请人工核查”**（不再静默）；
  - `winner_price` 用 `Option<i64> -> Money`，缺失即无中标价，不再
    满额兜底；
  - `deadline` 用 `.max(0) as u64`，`requester` 直接恢复。

### 2. 结果信封落盘（§3.2，已验收未结算任务重启后可结算）

- 新增 `result_envelopes(task_id PRIMARY KEY, payload TEXT)` 表。
- 新增 `snapshot_results_for_store()` / `restore_results_from_store()`
  （坏行跳过并 `eprintln!`，恢复计数打印）。
- 新增公共读取 `get_result(task_id) -> Option<&ResultEnvelope>`。

### 3. 信誉与质押落盘（§3.2，重启后仍可出价/罚没）

- 新增 `reputations(agent_id PRIMARY KEY, payload TEXT)`、
  `stakes(agent_id PRIMARY KEY, payload TEXT)` 两张表。
- `ReputationManager` 新增 `export_reputations/export_stakes` 与
  `import_reputations/import_stakes`（坏行跳过、恢复计数）。
- 新增 `snapshot_reputations_for_store/snapshot_stakes_for_store` 与
  `restore_reputation_state_from_store(reputations, stakes)`。
- 新增公共 `is_eligible(agent_id, min_reputation) -> bool`（委托
  reputation_mgr）。
- `spawn_with_store`：启动恢复在 load 任务后恢复结果信封/信誉/质押；
  写后快照在 upsert 任务后幂等覆盖这三组 JSON。

## 验证

- 新增 `tests/v284_test.rs` 的“关闭再打开”对抗测试
  `evidence_gate_survives_restart`：BftLite 任务走完
  deposit→register→publish→bid→match→submit_result，持久化全部快照后
  drop、重开、恢复，断言：
  1. 验证策略恢复为 `BftLite { n: 3, f: 1 }`（**不回 None 豁免闸门**）；
  2. `winner_price = Some(4000)`（**不付满额 5000**）；
  3. 结果信封存活（`get_result` 命中）；
  4. 质押恢复后 `is_eligible(agent, 0.3)` 仍为 true。
- **有效性验证（审计规则2）**：临时把恢复策略回退为旧的 `None`，该测试
  如期失败（“BftLite 策略应在重启后存活，实际 None”），随后恢复，证明
  它在旧代码上确实会失败、能抓住缺陷。
- `cargo test --lib`：167 passed / 0 failed；`cargo test --tests`：
  252 passed / 0 failed（含新增 v284 1）；`cargo clippy --all-targets`
  无 warning。
