# v3.2.2 — 业务化 swarm-emergence：群体智能涌现检测（detect）

v3.2.2 是 v3.2.1 之后的**小版本**。按版本语义，小版本只更新独立插件、对系统与其它插件
零影响。本版只做一件事：**把第 6 个官方插件 `swarm-emergence`（群体智能涌现检测）从
"通用 exec 承载"业务化为随插件承载真实算法的 `detect` entry**。

## 一、要解决的问题（根因）

插件化重构后，9 个官方插件中仍有 4 个（agent-skill / swarm-emergence / chain-anchor /
chain-bridge）是**通用 exec 承载**：清单在、插件能跑，但真实业务算法仍锁在单体
`swarm/emergence.rs` 里，插件本身没有任何可调用的业务方法。

这正是本项目批评上游 `agent-universe` 的核心模式之一——**「没有调用点的修复不算修复」**：
一个声称"群体智能涌现检测"的插件，若没有真实的 `detect` 方法，就没有兑现能力。

本版选定 swarm-emergence，因为它在单体中有一个**真实、独立、输入输出明确**的算法
（`swarm/emergence.rs::EmergenceDetector::detect`，110 行），适合作为只影响单插件的
小版本移植。

## 二、业务化：detect entry（plugin/official/mod.rs）

新增 `EMERGENCE_ENTRY`（Python），并在 `official_entry_source` 中把
`OFF_SWARM_EMERGENCE` 映射到该 entry。spawn 时 entry 被写入隔离工作目录，call 时在
隔离进程中 `import plugin` 并调用 `detect`——与 v3.1.0 起其它业务插件完全一致的承载方式。

entry 暴露两个方法：

| 方法 | 作用 |
|---|---|
| `status` | 返回插件 id、tier、方法清单（`["status","detect"]`） |
| `detect` | 移植 `EmergenceDetector::detect`，输出涌现信号 |

## 三、算法移植（与单体逐分支对齐）

`detect` 输入：

- `history`：每条 `[timestamp, throughput, latency]`；
- `threshold`：涌现阈值（默认 0.5）；
- `window_size`：检测窗口（默认 3）。

算法步骤（严格对齐 Rust 单体）：

1. `window_size <= 0` 或 `history` 长度不足一个窗口 → 返回空 `signals`；
2. `recent` = 最后 `window` 个点；`older` = 之前**最多** `window` 个点（可能不足
   `window`，与单体 `iter().rev().skip(window).take(window)` 等价）；
3. `older` 为空 → 返回空 `signals`（只有一个窗口、没有对比基线时不下结论）；
4. **吞吐量增长**：`recent`/`older` 平均吞吐，`older > 0` 时
   `growth = (recent − older) / older`，`growth > threshold` → 信号
   `collaboration`，描述「吞吐量增长 X%，检测到协同涌现」；
5. **延迟下降**：`recent`/`older` 平均延迟，`older > 0` 时
   `improvement = (older − recent) / older`，`improvement > threshold` → 信号
   `load_balancing`，描述「延迟下降 X%，检测到负载均衡涌现」。

判定条件用**严格大于**（与单体 `>` 一致），等于阈值不触发。`signal_type` 序列化为
snake_case 字符串（`collaboration` / `load_balancing`）。

> 关于 f64：`throughput`/`latency`/`strength` 是**性能指标**而非金额（Money），f64 是
> 合理且必要的；entry 从 JSON 取数，JSON 数字天然不含 NaN/Infinity，无需额外非有限校验。

## 四、测试

### process.rs（新增 3 个隔离测试，在隔离进程中真实加载 entry 并调用）

- `swarm_emergence_detects_throughput_growth`：更早窗口 throughput=100、最近窗口
  throughput=200（latency 不变）→ 恰好 1 个信号、`signal_type=collaboration`、
  `strength=1.0`（+100%）；
- `swarm_emergence_detects_latency_drop`：throughput 不变、latency 100→40
  → 恰好 1 个信号、`signal_type=load_balancing`、`strength=0.6`（−60%）；
- `swarm_emergence_insufficient_history`：不足一个窗口 → 0 个信号。

### official/mod.rs（更新单元测试）

`entry_source_for_business_plugins` 增加 `swarm-emergence` 的 `is_some()` 断言，
"其余 3 个"（agent-skill / chain-anchor / chain-bridge）断言 `is_none()`。
