# v3.8.1 — 面向 Agent 的资源市场（2/10）：注册容量账本（register/hold/release/deregister）+ 挂单容量闸门

## 一、交付了什么

v3.8.0 钉死了"账怎么记、单怎么走、能力谁有"的领域底座。v3.8.1 回答下一个不可回退的
问题：**一个供给方在挂单之前，必须先声明自己到底有多少资源可卖，撮合预留不得超卖。**
本版新增**纯确定性、内存态的注册容量账本**：零浮点、零 syscall、零 unsafe、无 panic
路径，金额/数量全部 `u128` checked 运算，越界与超卖一律具名拒绝（fail-closed）。

1. **容量注册类型**（`gsn-core/src/economy/resource/capacity.rs`，新增文件）
   - `CapacityRegistration { provider_did, kind, unit, capacity, held, stake_micro }`：
     某供给方在某资源形态 + 某计量维度下声明的可售容量；`new` 即做入场校验（非空 DID、
     正容量、`unit` 必须属于该形态的 [`catalog::default_units`] 目录，拒绝 Compute 配
     storage_gb_sec 这类越界组合），初始 `held = 0`。
   - `available() = capacity - held`（checked 减法），是后续挂单与撮合共用的"当前可售"。
   - `stake_micro` 为准入质押额：本版**只登记、不冻结、不罚没**；真正的质押冻结/罚没
     在 v3.8.4，本版不提前假装持有资金。
2. **容量注册表 `CapacityRegistry`（有序 Vec，确定遍历）**
   - 唯一键 `(provider_did, kind, unit)`；用有序 `Vec` 而非 `HashMap`，保证遍历/序列化
     顺序确定，便于单测与回放；规模为每节点供给条目数，线性查找足够。
   - `register`：校验 + 唯一性（同键重复 → `RESOURCE_DUPLICATE_REGISTRATION`，需先注销
     再改）；同形态不同维度（如 cpu_millis 与 gpu_millis）是不同键，可共存。
   - `available/get`：未注册具名 `RESOURCE_REGISTRATION_NOT_FOUND`（区别于"容量为 0"）。
3. **撮合预留 / 释放的守恒记账（对应状态机 matched → capacity_held）**
   - `hold(amount)`：把容量从可售转已持有；amount 为 0 / 未注册 / `held+amount >
     capacity` 一律拒绝，超卖报 `RESOURCE_CAPACITY_EXCEEDED { hold_requested,
     available }`，checked 加法报 `RESOURCE_ARITHMETIC_OVERFLOW`。**绝不超卖。**
   - `release(amount)`：取消/结算后把预留减回；amount 为 0 或 `amount > held` 报
     `RESOURCE_OVER_RELEASE { attempted, held }`，防重复释放/记账篡改（held 守恒）。
   - `deregister`：仅当 `held == 0` 才允许注销，防止带着未结订单撤供给
     （`RESOURCE_CAPACITY_STILL_HELD { held }`）。
   - `invariant_holds()`：全表自检恒有 `held <= capacity`，供宿主在关键边界 fail-closed。
4. **挂单入场容量闸门 `check_offer`（fail-closed）**
   - 挂单供给方**必须已注册**同形态/同维度容量，且挂单量不超过当前可售量；未注册直接
     `REGISTRATION_NOT_FOUND`，超量报 `RESOURCE_OFFER_EXCEEDS_REGISTERED_CAPACITY
     { offer_quantity, available }`。这是 v3.8.3 撮合器在
     `drafted → published` 受理挂单时复用的容量闸门，本版以纯函数形式先钉死规则。
5. **8 个新具名错误 + 状态诚实位更新**
   - `ResourceError` 新增：`EmptyProviderDid / UnitNotInCatalog / DuplicateRegistration /
     RegistrationNotFound / CapacityExceeded / OverRelease / CapacityStillHeld /
     OfferExceedsRegisteredCapacity`，全部补齐 `RESOURCE_*` Display 码。
   - PMB `resource_market_status` 诚实位更新：`enforceable.capacity_registration=true`、
     `provided.capacity_registry_persistence=false`（内存态、不持久化、非全局单例）；
     其余 metering/escrow/stake/onchain 仍为 false，不夸大边界。

## 二、测试（旧实现无法表达的断言，7 新增）

`economy/resource/capacity.rs` 7 个，全部针对"旧实现没有容量概念、会允许超卖/重复释放"：

1. `register_valid_starts_full_available`：合法注册 held=0、available=capacity、不变量成立。
2. `register_rejects_empty_did_zero_capacity_and_foreign_unit`：空白 DID、零容量、
   Compute 配 storage_gb_sec（越目录维度）三类入场拒绝。
3. `duplicate_registration_rejected_but_distinct_units_coexist`：同键重复注册拒绝；
   cpu_millis 与 gpu_millis 作为不同键共存。
4. `hold_respects_capacity_and_reports_available`：hold 600 后可售 400，再要 500
   `CAPACITY_EXCEEDED` 不超卖；hold 0 非法；未注册 NotFound；不变量恒成立。
5. `release_conserves_held_and_blocks_over_release`：释放 200 后 held=400、可售恢复 600；
   释放 500（>held 400）`OVER_RELEASE`；释放 0 非法。
6. `deregister_blocked_while_held_then_allowed`：有 300 预留时注销被
   `CAPACITY_STILL_HELD` 拦，全部释放后可注销，再注销 NotFound。
7. `offer_cannot_list_beyond_registered_available`：未注册挂单 fail-closed；注册 1000
   后挂 1000 合法，hold 600 后挂 1000 `OFFER_EXCEEDS_REGISTERED_CAPACITY`、挂 400 合法；
   别的供给方未注册同样拒绝。

- `cargo test --lib`：**gsn-core lib 472 passed / 0 failed**（较 v3.8.0 的 465 增 7；
  resource 子模块 16/0）；`cargo fmt --check`、`cargo clippy --all-targets
  -D warnings` 干净；check-no-panics 生产 panic=0；check-unsafe-containment 仍仅
  winjob.rs 3 unsafe/3 SAFETY，新增 capacity.rs 零 unsafe；`cargo metadata --locked`
  通过；`node js/test/test.js` 22 项通过；npm 3.8.1 ↔ gsn-core 0.3.81。

## 三、诚实边界

- 容量账本是**确定性内存记账面**：不持久化、不跨进程/跨节点共享、不是全局单例；宿主或
  后续 T1 市场门面持有它并在真实挂单/撮合时调用。跨节点容量发现、P2P 供给聚合不在本版。
- 本版**只登记** `stake_micro`，不冻结、不托管、不罚没任何资金；不接真实支付/链。资金
  守恒分账在 v3.8.5，质押罚没在 v3.8.4，BTC/ETH/稳定币结算与私钥隔离在 v3.9.x。
- `hold/release/check_offer` 是纯规则函数，本版**不自动**在订单状态转移时调用——真正的
  订单↔容量联动随 v3.8.3 撮合器接线；此处先保证规则本身可单测、不可超卖、守恒成立。
- 不新增能力令牌：容量注册/预留属于市场内核内部记账，不直接对外暴露新 PMB 写方法；
  `resource_market_status` 仍为只读，未接线的写方法继续不注册（NotFound）。
- 外部数字（90% 沙盒 CPU<5%、超卖 50×、内存 −40.2%/−21.2% 等）仍为第三方报道、非本仓
  复测，仅作机制动机，不写进代码或作为已验证结论。
