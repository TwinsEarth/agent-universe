# v3.9.10 — Mac mini（Apple Silicon）真机缺陷修复版：纠删码发起节点落地 + 分片放置限定协议子网 + 治理签名 CLI/基准对齐 + SIGTERM/SIGINT 可靠退出（真实三节点回归 + 签名经济闸门 + kill -9 持久化恢复）

## 一、定位

v3.9.10 是 **v3.9.x 小版本序列的「真机修复版」**，不是新功能大版本（资源市场 MVP
仍属 **v4.0.0**，该版本号为「一切面向智能体开发」架构预留，本版本不触碰）。

v3.9.9 在云端多节点测试网（3/5/10/20/50 节点）全绿，但在 Mac mini Apple Silicon
**真实跨进程 P2P 网络**上首次端到端跑通时，暴露了两类「内存测试总线通过、真机
libp2p 才暴露」的纠删码缺陷，以及一个监督进程下守护进程收不到 SIGTERM 的运维阻断。
本版本把这些真机问题逐条闭环，并让 CLI、基准脚本与 v3.9.9 引入的治理签名闸门对齐。

本版本工作在 Mac 本地完成：版本号 npm 3.9.10 ↔ gsn-core/gsn-daemon 0.3.100
（映射规则 0.X.(Y*10+Z)，9*10+10=100）。**密码学实现（Ed25519 治理签名、PoCV、
EVM 轻客户端等）仍标注「需外部审计」。**

## 二、修复清单（现象 → 根因 → 文件 → 验证）

### P1-1 纠删码：发起节点从不在本地落地，ingest 后立即 reconstruct 必 500

- **现象**：真机三节点 ingest 返回 200，但立刻 reconstruct 返回 500
  「无元数据，拒绝盲解码」；而云端内存测试总线单测全部通过。
- **根因**：旧 `ingest_blob` 只按 `responsible_peer` 把分片 `send` 出去，从不在
  发起节点本地写 `local`/`meta`。内存测试用的 `NetHandle` 存在「自发回投」
  （to==self 也回环），单测因此误绿；而真机 `GossipShardTransport` 基于
  rust-libp2p GossipSub，**不回环自发消息**，发起节点本地没有任何分片或元数据，
  立即重建必然失败。
- **修改文件**：`gsn-core/src/erasure/distributed.rs`
  - 归己分片走 `apply_store_shard` 本地落地，其余才 `send`；
  - `apply_seal` 本地落 `BlobMeta`，且仅对 `p != me` 广播；
  - 入站统一走 `apply_*` 并加护栏；
  - 新增 `NoLoopbackTransport` 测试，固化「GossipSub 不回环自发消息」这一真机前提。
- **验证**：`erasure::` 隔离 14 测试通过；真机 111B blob ingest→reconstruct 成功。

### P1-2 纠删码：分片放置集合未限定协议子网，真实大连接集合下命中 0/4

- **现象**：修完 P1-1 后真机 ingest 200，但立即 reconstruct 返回 409「0/4」。
- **根因**：节点驱动每约 2 秒把**全部 libp2p 连接**喂给 `set_peers`。真机上 n1 约有
  65 条连接，其中绝大多数是公共 IPFS/kubo 节点，它们并不订阅 `gsn/shards` 主题。
  FNV-1a 放置在这个大集合上散布 6 个分片，发起节点命中 0 个，属于协议子网的节点
  也可能一个都没分到。
- **修改文件**：
  - `gsn-core/src/erasure/distributed.rs`：`ShardEnvelope` 新增 `Hello{node:String}`
    成员发现消息。
  - `gsn-core/src/erasure/wire.rs`：`GossipShardTransport` 重写为
    `{self_id, observed, alive, inbound, outbound}`；放置集合 =
    observed ∩ connected ∪ {self}；`deliver` 认证真实 `from`（6 个测试）。
  - `gsn-core/src/node.rs`：分片通道改为 `(String, Vec<u8>)` 携带 GossipSub 认证的
    `msg.source`；入站 `try_send(source, bytes)`；驱动用认证 source 覆盖 `wire.from`
    防伪造；每 4 个 tick（约 2s）`set_peers` 后广播 `Hello`。
- **验证**：真机 111B 约 1s 达到 4/4 双 MATCH；4096B 三节点逐字节 ALL_MATCH。

### P2 CLI：`gsn market deposit` 与治理签名闸门脱节

- **现象**：真机 `gsn market deposit <did> 1` 返回 400
  「治理信封解析失败 missing field id」。
- **根因**：`src/bin/gsn.rs` 的 `build_market_request` 构造的是裸 `{amount}`，而
  v3.9.9 的 deposit 端点强制请求体为 `SignedGovernanceCommand`，两者脱节。
- **修改文件**：`gsn-core/src/bin/gsn.rs`
  - deposit 只接受单个参数（`@文件` 或内联 JSON 签名信封），本地校验 target 非空、
    `capability == "governance:credit"`，原样 POST；
  - **CLI 不持有治理私钥、绝不替签**；旧 `<account> <amount>` 用法返回迁移错误
    （exit=2）；
  - 删除死代码 `parse_amount` 与 3 个旧测试，新增 2 个测试；帮助文本同步。
- **验证**：真机 `gsn market deposit @/tmp/macfixture/deposit-cli.json` → 200，
  balance=50，exit=0。

### P2 基准：bench-e2e.mjs 未带治理集，两笔注资必 422

- **现象**：端到端基准 spawn 的 daemon 只设了 `REST_ALLOW_UNAUTHENTICATED=1`
  （仅绕 bearer，不绕治理签名），未设 `GSN_GOVERNANCE_FILE`，两笔 deposit 发裸
  `{amount}` 必然 422。
- **修改文件**：`scripts/bench-e2e.mjs`
  - 新增 `makeGovernance()`：Node `crypto` 生成 ed25519，SPKI DER 取 32B 公钥、
    pkcs8 取 seed，DID=`did:nau:`+sha256(pub)[0:8] hex；`canonical()` 递归排序键、
    数组保序、紧凑 JSON；signing_bytes 与 Rust 治理规范逐字节一致；
  - spawn env 增加 `GSN_GOVERNANCE_FILE`；两笔 deposit 改为签名信封。
- **验证**：`node --check` 通过；真机 n20/warmup5：exit 0，deposit_one_off 2.192ms，
  audit_passed=true（expected/actual_total=2350，replayed_records=78，mismatches=[]），
  conservation conserved=true（balance_sum=2350，total_paid=250，total_slashed=0）。

### P0 运维：SIGTERM/SIGINT 在继承的阻塞掩码+忽略处置下无法终止 daemon

- **现象**：历史上重启 n1 只能 `kill -9`；对旧 n3 实测 `kill -TERM` 返回 rc=0，但
  2 秒后进程仍存活、端口仍 LISTEN。全 src 检索无任何 OS 信号安装。
- **根因**（用最小独立 crate `/tmp/sigign-repro` 分层实证，共三层，后两层跨
  fork-exec 保留）：
  1. 监督 shell 在 fork-exec 前把 SIGTERM/SIGPIPE 处置位置为 `SIG_IGN`；
  2. **决定性层**：SIGTERM/SIGINT 同时处于继承的信号阻塞掩码（blocked mask）中——
     纯 libc 睡眠程序「仅 `signal(SIGTERM,SIG_DFL)` 而不 unblock」仍 SURVIVED；
     同 shell 启动的 `/bin/sleep` 收 SIGTERM 也 SURVIVED；而 main 最前
     `pthread_sigmask(SIG_UNBLOCK,{TERM,INT})` 后再置 DFL 的程序被立即 KILLED；
  3. tokio 1.53.1 的 `signal()` 经 signal-hook-registry 无条件 `sigaction` 覆盖
     handler（`Slot::new` 无 SIG_IGN 特判）。
  - 「unblock+DFL+tokio」组合下，worker 线程内 `libc::raise(SIGTERM)` 不触发
    （worker 继承阻塞、raise 定向调用线程），但真实外部 `kill -TERM <pid>` 是
    进程定向、由已 unblock 的主线程接收；`docker stop`/`kill` 均为进程定向外部信号，
    故修复对真实运维有效。
- **修改文件**：
  - `gsn-core/src/node.rs`：`install_shutdown_handler` 重写为
    「① `pthread_sigmask` UNBLOCK {SIGTERM,SIGINT,SIGHUP}（rc!=0 告警）→
    ② signal(TERM/INT)=SIG_DFL → ③ tokio signal(terminate/interrupt) spawn
    select! 收到即打印并 `std::process::exit(0)`；非 Unix 走 ctrl_c」。
  - `gsn-core/Cargo.toml`：新增直接依赖 `libc = "0.2"`（解析 0.2.189）。
- **验证**：真机 daemon `/health`=200 后 `kill -TERM` **25ms 退出**、
  `kill -INT` **280ms 退出**、端口释放；最小 crate 外部 kill 8/8 PASS。

- 新文件 `gsn-core/examples/mac_gov_fixture.rs`：`cargo run --release --example

## 五、诚实的未验证边界

- 50 节点规模、10 节点 20% 恶意节点、24h CRDT 增长、100 Sybil（云端 v3.9.9 已做，
  Mac 真机未复跑）；

- 链上真实交易 / EIP-3009 / Paymaster / x402 / 闪电网络真实结算（v3.9.x 为
  「只构造不广播」纯协议内核）；
- Docker build / docker-compose 实跑；全 workspace 测试（本机仅 lib 746 + gsn bin 8）；
- 密码学实现「需外部审计」；PoCV 只证明归属与未篡改，不证明计算正确性。
