# v3.7.4 — AUSec 内存共享（1/3）：配额池共享额度记账 + 两级超卖准入（patch）

## 一、交付了什么
- `gsn-core/src/ausec/memory.rs`（新增，含 9 个测试）：**跨平台、纯确定性**的
  内存配额池，把「内存共享 + 超卖」落成可复算的**额度记账与准入策略**，不依赖任何
  Linux-MicroVM 专有内核原语（那些原语按设计在 v3.7.6 声明、在无原语平台具名拒绝）。
  - 两级口径（均为 u64 字节，比例走 u128 中间运算，无浮点）：
    - **committed（宿主必须真实保住）** = 各沙盒 `private_bytes` 之和 +
      全机只读共享内容的**并集**：同一内容寻址 id（sha256）跨多少沙盒都只计一次；
      同一 id 声明不一致大小时并集取 **max**（确定性、不崩）。
    - **nominal（各沙盒名义申请）** = 各沙盒 `(private + 其 shared)` 之和，
      共享块按沙盒重复计入——这是超卖比实际作用的口径。
    - `shared_dedup_saving = nominal - committed`，刻画「同一只读内容只存一份」
      相对逐沙盒各存一份省下的额度。
  - **两级准入闸**（`MemoryPool::project` 纯决策、`admit` 原子落库）：
    1. **物理硬闸**：`projected_committed <= physical_bytes`，否则
       `RejectCommittedExceedsPhysical{projected_committed, physical}`——
       宿主承诺保住的内存绝不允许超过物理上限。
    2. **超卖上限闸**：`projected_nominal <= physical × ratio/1000`，否则
       `RejectOvercommitCeiling{projected_nominal, ceiling, physical, ratio_permille}`。
       `OvercommitRatio` 用千分点表达（`from_permille`/`times`），<1000（即 <1×）
       直接 `BadOvercommitRatio` 报错，拒绝「连名义都不能超过物理」的自相矛盾配置。
    - 被拒时池状态**不变**（project 通过才 admit 落库）；`release(id)` 自动重算共享
      并集（某内容最后一个引用消失后并集随之下降）。
  - 全类型化错误 `MemoryError`（thiserror）：`BadPhysical` /
    `BadOvercommitRatio` / `EmptySandboxId` / `DuplicateSandbox` / `UnknownSandbox` /
    `EmptyShareId{sandbox}` / `BadShareBytes{sandbox,id}` /
    `DuplicateShareRef{sandbox,id}` + 两级拒绝；无裸 panic/unwrap。
  - 输出 `Admission`（单次准入投影）与 `PoolStatus`（池快照：committed/nominal/
    去重节省/nominal 上限/committed 利用率千分点/观测超卖千分点/不同共享内容数）。
- `ausec/mod.rs`：导出 memory 类型；系统插件 `com.twinsearth.sys.ausec` 新增两个
  **只读、纯决策** PMB 方法：
  - `memory_status`：入参
    `{physical_bytes, overcommit_times?|overcommit_permille?, sandboxes?:[{sandbox_id,
    private_bytes, shared:[{id,bytes}]}]}`，返回 committed/nominal/去重/超卖口径快照。
  - `memory_admit`：同入参另加 `candidate`，返回候选准入后的 `Admission`；
    被任一闸拒绝返回错误字符串。**只做投影决策，不持久化任何全局状态**
    （每次调用从调用方给定的现状重算）。

## 二、测试（旧实现会失败的断言，11 新增）
- memory.rs 9 个：同一只读内容跨沙盒只计一次；不同内容全部计入（nominal=300）；
  物理硬闸拒绝；超卖上限闸拒绝（committed 未越界但 nominal 越界时精确命中超卖闸）；
  release 后共享并集自动重算；同 id 大小不一致取 max；构造与请求校验
  （physical=0、ratio=0、空 id、空 share id、0 字节、重复 share、重复沙盒）；
  大数值 u128 不溢出；空池 status 基线。
- mod.rs 2 个 PM 桥：`memory_status` 去重/超卖口径（committed=260、nominal=320、
  节省 60、观测超卖 1230‰）；`memory_admit` 物理闸/超卖闸分别 fail-closed +
  通过时返回完整投影。
- `cargo test --lib ausec` **55/0**（ausec 目录 52 个 + 路径命中的 3 个插件能力测试）；
  全量 gsn-core **33 组 0 failed**（lib 组 407 passed）；
  `cargo fmt --check`、`cargo clippy --all-targets -D warnings` 干净；
  check-no-panics 生产 panic=0；check-unsafe-containment 全收容；
  `cargo metadata --locked` 通过；npm 3.7.4 ↔ gsn-core 0.3.74。

## 三、诚实边界
- 本版交付的是**记账/准入纯模型**，**不是**跨 MicroVM 的真实物理页共享：没有调用
  virtio-pmem / DAX / DAMON / balloon / seccomp / landlock / AppArmor / eBPF，
  这些是 Linux-MicroVM 专有、在 macOS/Windows 无对应原语的能力，按 AUSEC-DESIGN
  在 **v3.7.6** 声明边界并在无原语平台**具名拒绝**（绝不静默声称已隔离/已共享）。
- 因此本版不读任何 OS 真实计数，所有 committed/nominal/超卖值都由调用方提供的
  沙盒申请**确定性重算**，便于策略层在真正接线前先做可复算、可测试的容量决策。
- 外部实测数字（约 90% 沙盒平均 CPU<5%、资源超卖 50×、virtio-pmem/DAX 使宿主峰值
  内存降 40.2%、DAMON+balloon 再降 21.2% 等）均来自 **aiwiki.ai / byteiota.com
  对 DSEC 的报道，非本仓复测**；本版不声称在本仓复现这些降幅，见
  `docs/ausec/AUSEC-DESIGN.md`。
- `memory_admit` 是**无副作用**的准入咨询：不代表内核已真正分配/锁定内存；真实
  分配、配额强制与空闲页回收在后续小版本接线。
