# v3.9.1 — 比特币/以太坊 Agent 经济体（2/9）：宿主签名服务与私钥隔离（HostSignerGate 闸门，wallet_sign_preview 只预览不碰密钥，wallet_sign 宿主受限，生产默认 SignerNotConfigured fail-closed，私钥/seed 绝不进沙盒）

## 一、交付了什么

v3.9.0 的结算路由只「决定走哪条轨道」，不碰钱。真正要把一笔支付/授权提交出去时，需要
对授权上下文**签名**——而 Agent 跑在沙盒里，私钥绝不能下发到沙盒，否则任何一个被攻破
的插件都能直接转走资金。v3.9.1 交付这道分界：**签名是宿主能力，不是沙盒能力**。

新增文件 `gsn-core/src/economy/payment/signer.rs`，并扩展 `payment/mod.rs`：

1. **签名意图 `SignIntent`**：`track`（闪电/EVM/BTC 三轨）、`domain`（签名域，不得空白）、
   `message_digest`（必须恰为 32 字节）、`spend_cap_micro`（内部整数 micro 授权上限）、
   `nonce`（防重放序号）、`auth_only`（纯认证不授权支付）。
   - `validate(&SignPolicy)` 在触碰任何密钥之前做确定性校验：空白域 →
     `EmptySigningDomain`；摘要长度 ≠ 32 → `InvalidDigestLength{expected,got}`；
     非认证却给 0 上限 → `NonPositiveSpendCap`；`auth_only` 却带非零上限 →
     `AuthOnlyWithSpendCap`；轨道被策略禁用 → `SigningTrackDisabled{required}`；
     上限超过该轨策略额度 → `SpendCapExceeded{requested,allowed}`。
   - `normalized_payload()` 对**完整授权上下文**而非裸摘要签名：
     `domain | track | spend_cap(BE u128) | nonce(BE u64) | auth_only | digest`
     （0x1f 分隔），防止签名被改域/改额/改轨后挪用。

2. **签名策略 `SignPolicy`/`TrackSignRule`**：每轨 `enabled` + 单笔 `spend_cap_micro`，
   默认 lightning=10_000 / evm=100_000_000 / btc=1_000_000_000 micro，与 v3.9.0 选路
   阈值呼应；`const validated()` 拒绝「启用却零额度」的矛盾策略
   （`SignPolicyInvalid{track}`）。

3. **宿主闸门 `HostSignerGate<B: SignatureBroker>`**：
   - `preview(intent)` → `SignPreview`：只校验+规范化，产出 digest/payload 十六进制与
     `signing_requires_host_key=true`、`host_key_configured`，**不接触密钥、不产出签名**，
     任何沙盒都可调用；
   - `request_sign(intent)` → `SignatureReceipt`：先做同一套确定性校验，再经宿主侧
     `SignatureBroker` 签发；回执只含 `public_key_hex`/`signature_hex`/
     `signed_normalized_payload_hex`，**绝不含私钥/seed**。

4. **fail-closed 后端与参考后端**：
   - `UnconfiguredBroker`（生产默认装配，`UnconfiguredSignerGate`）：`configured()=false`，
     任何签发一律返回 `SignerNotConfigured` 具名拒绝，**绝不返回伪造签名**；preview 仍
     可用（它本就不需要密钥）。
   - `InMemoryBroker`（宿主进程内参考实现/测试用）：三轨各一把 Ed25519 `Keypair`，密钥
     只活在宿主进程内存，经闸门签发后只外泄公钥与签名；不代表密钥进入沙盒。真实平台
     密钥后端（钥匙串/TEE/HSM）由宿主在装配处注入，不经沙盒 handler。

5. **PMB 字节桥**（同一系统插件 `com.twinsearth.sys.payment-router`，T0）：
   - 新注册 `wallet_sign_preview`（只读预览）与 `wallet_sign`（宿主受限；生产默认
     `PAYMENT_SIGNER_NOT_CONFIGURED` 具名失败）；空/坏负载类型化拒绝，不 panic。
   - `payment_router_status` 增加 `signing_introduced_in=v3.9.1` 与 `signing` 诚实块：
     `private_key_enters_sandbox=false`、`seed_enters_sandbox=false`、
     `production_default_host_key_configured=false`、`fail_closed_when_unconfigured=true`、
     `fabricated_signature_on_failure=false`；`enforceable` 新增
     `host_only_signing_private_key_isolation=true`、`sandbox_direct_transaction_signing=false`、
     `fail_closed_when_signer_unconfigured=true`；`capabilities_declared` 由 1 个
     （`pay:route:read`）增至 2 个（加 `wallet:sign:host-restricted`），`wallet:sign`
     从「后续保留」移除，`pay:execute`/`chain:anchor:write` 仍保留不授予。

内核仍零浮点、零 syscall、零 unsafe、无生产 panic；不连任何链/节点、不广播、不划转、
不兑换、不持久化。

版本映射：npm `@twinsearth/agent-universe` 3.9.1 ↔ Rust `gsn-core`/`gsn-daemon` 0.3.91。

## 三、诚实边界（做不到的具名拒绝）

- 本版本交付的是**签名闸门与私钥隔离边界**，不是真网资金面：不广播、不划转、不托管、
  不兑换、不连闪电/EVM/BTC 节点、不持久化；生产默认不持任何密钥，`wallet_sign` 一律
  具名拒签。要真实签发，宿主须在装配处注入平台密钥后端（`SignatureBroker` 实现），
  该注入是独立能力闸门，不经过沙盒。
- **重放/双花**：本版本只把 `nonce` 纳入被签规范化载荷，**不声称已完成链下重放拦截**
  ——拒绝重放需要有状态账本/持久 nonce，留给后续有状态宿主。
- EVM x402(USDC) 在 **v3.9.2**；闪电 L402 适配在 **v3.9.3**；ERC-8004 三注册表在
  **v3.9.4**；ERC-4337 Paymaster 在 **v3.9.5**；BTC HTLC/RGB 纯校验在 **v3.9.6**；
  链上锚定/跨链桥风控在 **v3.9.7**；ZK 支付意图/OWS/合规接口在 **v3.9.8**。在对应版本
  落地前这些方法不注册（NotFound）或只提供决策/校验面，不伪造真网可用。
- 默认三轨额度是整数策略分界，**不构成对法币或任何币价的承诺**，可由宿主经
  `SignPolicy`（须通过 `validated`）覆盖。
- 文档中涉及的外部协议采用量/性能数字（x402 交易量、BlackRock 模型占比、ERC-8004
  采用量、A402 性能等）均为**第三方报道口径，非本仓复测**，内核不内置这些数字作为事实。
