# v3.7.9 — AUSec CPU 调度（3/3）：突发涌入准入控制 + 统一 ausec status（后端/块/CPU/内存）

## 一、交付了什么
本版为 AUSEC-DESIGN §3.1 中 v3.7.9 的交付，也是 v3.7.7–3.7.9「CPU/资源调度」三连
的收尾。当创建请求**突然集中涌入**时，v3.7.7 只仲裁优先级、v3.7.8 只在仿真时钟里
分配竞争容量，二者都不回答"**这一整波到达，现在哪些能直接启动、哪些排队、哪些必须
拒绝**"。本版新增 `gsn-core/src/ausec/burst.rs`，在**有限 CPU 容量 + 内存配额池**
两个维度上对一批 arrival 做确定性的 `Admitted / Queued / Rejected` 裁决；并新增统一
只读入口 `ausec_status`，把后端/块/CPU/内存四个子域状态在一个调用里诚实汇总。全部
纯确定性、整数记账、零 syscall、零 unsafe、thiserror 无 panic——它是准入**决策面**，
不真正创建沙盒、不真正限速、不真正回收内存。

1. **CPU 软闸（容量不足先排队，不直接拒）**
   - 已在运行沙盒（`existing`）先占容量，剩余容量按 v3.7.7
     [`arbitrate_priority`] 裁定好的顺序（Sensitive 先、权重降、id 升）逐个容纳；
     已用 + 本申请超出 `capacity_millis` 时记 `CpuShortfall` 进队列。
   - 时延敏感核心任务在涌入竞争中确定性地排在时延容忍后台任务之前。
2. **内存双闸（复用 v3.7.4 `MemoryPool::project`，物理硬闸与超卖闸区分对待）**
   - 投影独占+共享已提交量 **committed > physical**：`physical_hard_limit`
     **直接拒绝**——排队也不会凭空产生物理内存。
   - 仅 **nominal > 名义超卖上限 ceiling**（共享按沙盒重复计、但 committed 仍在物理
     内）：记 `overcommit_ceiling` **排队**（等空闲回收腾出超卖空间后可进），与物理
     硬闸严格区分。
3. **突发整形 + 有界队列（不无界排队）**
   - `burst_max_admit`：本波直接准入数到顶后，其余即使此刻放得下也记
     `burst_capped` 排队（避免一次性把全部请求灌进调度器）。
   - `queue_capacity`：需要排队但队列已满时记 `queue_full` **拒绝**（fail-closed，
     绝不无界排队）。
   - 一个 arrival 可同时携带多个排队原因（如既 CPU 不足又触超卖闸），全部如实列出。
4. **fail-closed 信任与身份一致性**
   - `existing` 与 `arrivals` 合并后一次性 `arbitrate_priority`：黑名单、低信任级自报
     Sensitive、空/重复 id、权重/申请越界任一非法 → **整体拒绝**，不返回部分结果。
   - 每个 arrival 的 CPU 画像与内存申请**必须同一 `sandbox_id`**
     （`IdentityMismatch`），防止借两套 id 规避单一仲裁/记账。
5. **统一 `ausec_status`（一个只读调用汇总四子域）**
   - **后端段**始终实时探测平台（复用 v3.7.0 诚实就绪载荷，契约不变）。
   - **块/CPU/内存三段是调用方按需提供观测的确定性重算**：本插件不持有全局运行态；
     给了对应输入就算并做 fail-closed 校验，没给就如实 `provided=false`，**绝不伪造**
     配额占用或种子健康度。块段形态同 `seed_health`（manifest+replica_counts），CPU
     段给 capacity+sandboxes 出敏感/容忍人数与申请合计，内存段给 physical+sandboxes
     出 committed/nominal/超卖口径。

- 新增类型：`BurstError`（5 变体，含 `Cpu/Memory` 的 `#[from]` 透传、`NoArrivals`、
  `IdentityMismatch`、`Invariant`）、`QueueReason`/`RejectReason`/`BurstDecision`
  （snake_case 序列化）、`BurstLimits`、`BurstArrival`、`ArrivalDecision`、
  `BurstSummary`、`BurstAdmission`，纯函数
  `run_burst_admission(capacity, existing_cpu, pool, arrivals, limits)`；在
  `ausec/mod.rs` `pub mod burst` 并 re-export。
- PMB 方法：`METHOD_BURST_ADMIT="burst_admit"`、
  `METHOD_AUSEC_STATUS="ausec_status"`，各自字节桥
  （`handle_burst_admit` 空负载按缺字段错误；`handle_ausec_status` 负载可空等价 `{}`），
  单一 register 点各注册一行。

## 二、测试（旧实现无法表达的断言，7 新增）
- burst.rs 5 个：CPU 竞争下 system 敏感先入、third_party 容忍因剩余容量不足排队且
  summary 守恒（used 60/remaining 40）；**物理硬闸直接拒**（private 100 > physical 50）
  与**仅超卖闸排队**（physical 200/2× ceiling 400，三个共享同一 150 只读块的沙盒：
  committed 180 在物理内但 nominal 480 超 ceiling → 前 2 入、第 3 排队，committed
  落账 170）严格区分；`burst_max_admit=2` 下第 3 个放得下也 `burst_capped` 排队；
  `queue_capacity=1` 三人争 100 → 1 入、1 排队、1 `queue_full` 拒绝；空 arrivals /
  CPU-内存身份不一致 / 黑名单 / 认证级自报 Sensitive / 与 existing 重复 id 全部
  fail-closed。
- mod.rs 2 个 PM 桥：`burst_admit` 入口敏感先入/容忍排队的 summary 与裁决顺序、字节桥
  round-trip 的 `rejected/physical_hard_limit`、空与坏负载报错不 panic、身份不一致
  拒绝；`ausec_status` 无参时后端段有、块/CPU/内存三段 `provided=false`，空负载字节桥
  等价 `{}`，给全观测后三段 `provided=true` 且 committed=150、chunks_total=3 等数字
  确定性重算，坏观测（第三方自报 sensitive）在统一 status 里同样 fail-closed。
- `cargo test --lib ausec` **95/0**（较 v3.7.8 的 88 增 7）；全量 gsn-core
  **lib 450 passed / 0 failed**（较 443 增 7）；`cargo fmt --check`、
  `cargo clippy --all-targets -D warnings` 干净（复杂解析返回改为具名
  `ParsedBurstInput` 结构体，无 type_complexity；无 unwrap/expect/panic）；
  check-no-panics 生产 panic=0；check-unsafe-containment 仍仅 winjob.rs
  3 unsafe/3 SAFETY（本版新增 burst.rs **零 unsafe**）；`cargo metadata --locked` 通过；
  npm 3.7.9 ↔ gsn-core 0.3.79。

## 三、诚实边界
- 本版是准入**决策**，不是真实执行：**不创建**任何沙盒/进程/容器，**不调用** cgroup、
  seccomp、Landlock、sched_setaffinity 或任何 OS 隔离/调度原语，**不推进墙钟、不持久化
  全局运行态**。输出的 Admitted/Queued/Rejected 不能被解读为"内核已实际放行/挂起/拒绝
  这些沙盒"；它验证的是**准入策略在突发 + 双资源约束下的确定性正确性**，真实强制、
  真实排队唤醒、真实内存回收不在本版。
- `Queued` 只表示"按当前投影此刻不宜直接启动、应等待资源"；本版**不实现**队列的入队
  存储、超时、重试或唤醒调度（那是运行时/后续委员会调度域的职责），也不保证调用方
  之后一定能成功准入（池状态可能变化，需重新 project）。
- `burst_max_admit` / `queue_capacity` 是调用方按自身容量与可用性目标传入的整形参数，
  本版不提供"该设多少"的经验默认，也不从外部报道推断；未给即对应"不整形/不限排队
  （仅物理硬闸拒绝）"。
- `ausec_status` 的块/CPU/内存三段是**调用方申报观测的确定性重算**，不代表守护进程
  实时内部状态；本插件无全局单例池。后端段的平台就绪仍是 v3.7.0 起一贯的诚实口径
  （原语可用 ≠ 执行器已接线），virtio-pmem/DAX/DAMON/balloon 依旧 can_enforce=false。
- 外部报道的"创建请求突然集中涌入""约 90% 沙盒平均 CPU<5%""超卖 50×"等是
  aiwiki.ai/byteiota.com 对 DeepSeek DSEC 的报道、非本仓复测；本版仅将其作为**机制
  动机**，用自己的整数向量证明准入裁决行为，不复述其数值为已验证结论。
- 信任仲裁仍以"宿主已按插件清单前缀正确裁定 tier"为前提；tier 不由沙盒自填，PMB 入口
  缺省 third_party。下一阶段 v3.8.x 为 Agent 委员会 + pack_diff 增量快照 + 轨迹分叉。
