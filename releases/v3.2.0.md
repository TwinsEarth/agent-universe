# v3.2.0 — 业务插件化深化：再 3 个核心官方插件承载真实业务 entry

v3.2.0 是 v3.1.0 业务插件化之后的**中版本**。按版本语义，中版本是**新功能**：本版不修改
插件内核，而是继续把单体真实算法移植到插件 entry，使 9 个官方插件中 **5 个承载真实业务**
（settle 独立审计、scheduler 任务路由、agent-card 校验）。

## 一、要解决的问题（根因）

v3.1.0 只让 economy-reputation、market-match 两个插件承载真实业务，其余 7 个官方插件
仍是通用 `exec` 容器，真实算法仍留在单体：

- 独立审计（`independent_audit`）、任务路由（`assign_task`）、AgentCard 校验等核心算法
  没有进入插件，插件"有壳无业务"；
- 单体 `assign_task` 中 `budget / candidates.len()` 与 `load / max_concurrent` 存在
  除零隐患（空候选、零容量），缺少类型化处理。

v3.2.0 把这 3 个算法移植为插件 entry，并把除零隐患改为类型化结果。

## 二、新增 3 个内嵌 entry 业务模块（plugin/official/mod.rs）

| 插件 | entry 方法 | 移植来源 | 逻辑 |
|---|---|---|---|
| `com.twinsearth.official.market-settle` | `audit` | `marketplace/settlement.rs::independent_audit` | 只信任流水独立重放，逐账户比对，校验总额/聚合一致 |
| `com.twinsearth.official.scheduler-task` | `route` | `scheduler/router.rs::assign_task` | 按负载/延迟评分选最佳，估算成本 |
| `com.twinsearth.official.agent-card` | `validate` | `marketplace/agent_card.rs`（MarketAgentCard 字段） | 校验 DID/name/version/skills/分数/质押 |

### 1. market-settle `audit(payload)`

- 输入：`records`（每条 `{task_id, from_account, to_account, amount, reason, timestamp}`）、
  `balances`（`{account: 整数}`），可选 `total_deposits`/`total_slashed`；
- 独立重放：`Deposited`→to 加、`Slashed`→from 减、其余 reason 当 amount>0 时 from→to
  搬运；
- 逐账户比对（重放账户 ∪ 当前账户），不匹配进 `mismatches` 并按 account 排序；
- 校验 `expected_total = deposits - slashed == actual_total`；提供引擎聚合时校验
  `aggregate_matches`；
- 返回 `passed`、`replayed_*`、`expected_total`/`actual_total`、`mismatches`。

### 2. scheduler-task `route(payload)`

- 输入：`nodes`（每个 `{did, load, latency_ms}`）、`max_concurrent`、`budget`；
- 评分：跳过 `load >= max_concurrent`；
  `score = 1 - (load/max)*0.3 - min(latency/1000,1)*0.2`；
- 估算成本：`estimated_cost = budget // len(nodes)`；
- 类型化边界：空候选→`no_candidates`；`max_concurrent<=0`→`no_capacity`；
  全饱和→`all_saturated`。

### 3. agent-card `validate(payload)`

- 校验：agent_id 非空且以 `did:` 开头、name/version 非空、skills 为列表、
  reputation_score/success_rate ∈ [0,1]、stake 为非负整数；
- 返回 `{valid, errors[]}`。

新增 7 个 process runtime 隔离测试（复用 `unique_rt()` 独立 base 目录，避免并行共享）：

- settle：`settle_audit_passes_on_consistent_ledger`（一致通过）、
  `settle_audit_catches_tampered_balance`（B 余额 60 必败、报 expected 50/actual 60）；
- router：`scheduler_route_picks_low_latency_node`（选 b、estimated_cost=50）、
  `scheduler_route_empty_candidates`（no_candidates）、
  `scheduler_route_zero_capacity`（no_capacity）；
- card：`agent_card_validate_accepts_valid_card`（合法）、
  `agent_card_validate_rejects_invalid_card`（非法 ≥4 项错误）。

另新增 1 个 host 回归测试（见第七节）：`hot_reload_new_entry_remains_callable`
（热更新后新版本 entry 仍可调用）。

## 六、已知边界

- 9 个官方插件中 5 个已承载真实业务；其余 4 个（agent-skill / swarm-emergence /
  chain-anchor / chain-bridge）仍为通用 exec 承载，后续版本继续业务化；
- entry 为 Python，跨平台依赖运行环境的 Python3；

  而非中标价、Unix/macOS 进程后端部分边界无强制原语（需 waiver）。

## 七、热更新 / 并行竞态修复（治本）

**背景**：CI（run `36820096271`）在 macOS Test 平台上 `load_legacy_abi_2_plugin` 偶发失败
（`entry 写入失败: internal: No such file or directory (os error 2)`），其它平台全绿。

**根因**：沙箱工作目录名只含插件 id（`base/au-sandbox-{id}`），同一个 id 在两种情形会产生
多个并存实例——并行测试、`hot_reload` 双缓冲（新旧版本短暂并存）。它们共享目录，一个
`destroy`（`remove_dir_all`）会在另一个实例 `create_dir_all` 之后、写 entry 之前删掉目录，
于是写 entry 报 `os error 2`；混合负载压测（24 线程 × 4 轮，含 install/uninstall 交错）修复前
连跑 6 次中 3 次失败，修复后 8 次全绿。

**附带发现的生产 bug**：`hot_reload` 成功后旧实例 `destroy` 会删除新版本仍在使用的共享目录，
导致热更新后新版本 entry 无法 `import plugin`；原 `hot_reload_succeeds` 测试只断言清单版本、
从不调用新版本 entry，故未发现。

**修复**：
1. `sandbox/runtime/process.rs` 新增全局 `SANDBOX_SEQ: AtomicU64`，工作目录改为
   `base/au-sandbox-{id}-{pid}-{seq}`，每个实例独占目录，一个 `destroy` 只删自己的目录；
2. `sandbox/manager.rs::fork_from` 不再用固定公式 `au-sandbox-{new_id}` 计算目标目录，
   改为先 `create` 再从 `sb.work_dir()` 取实际目录后复制文件（唯一后缀改动曾使 fork 子沙箱
   读不到继承文件，v278 fork 两个测试已修复）。

**回归测试**：`hot_reload_new_entry_remains_callable`——临时还原旧目录命名时稳定失败 5/5
（`ModuleNotFoundError: No module named 'plugin'`），治本修复后通过。
