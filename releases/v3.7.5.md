# v3.7.5 — AUSec 内存共享（2/3）：等待期保内存 + 空闲优先回收规划（patch）

## 一、交付了什么
- `gsn-core/src/ausec/memory.rs` 新增一组**跨平台、纯确定性**的「等待期保内存 +
  空闲优先回收」类型与无状态规划器，只产出**回收建议**，不调用任何 OS 回收原语、
  不修改 v3.7.4 的配额账、不释放任何沙盒。
  - 输入建模：
    - `ActivityState{Running, Waiting}`：Agent 完成一次动作、等待模型生成下一步期间为
      `Waiting`——此时 CPU 基本空闲，但文件/进程状态必须保住（呼应外部观察：约 90%
      沙盒平均 CPU<申请资源的 5%）。
    - `LatencyClass{Sensitive, Tolerant}`：时延等级，作为回收排序的次级键
      （CPU 两级优先级调度在 v3.7.7 正式建模，本版仅预埋枚举）。
    - `SandboxIdleObservation{sandbox_id, state, idle_ms, latency, reserved_bytes,
      reclaimable_idle_bytes}`（serde 可序列化）：某时刻的空闲观测，纯输入，
      本模块不读任何 OS 计数。
      - `reserved_bytes` 是**等待期必须保住**的状态内存（匿名页/进程/文件状态），
        规划器**永不触碰**；
      - `reclaimable_idle_bytes` 是当前可安全丢弃、将来可经缺页重新取回的空闲/干净页，
        是**唯一**可回收来源。
  - `ReclaimPlan{target_bytes, reclaimed_bytes, shortfall_bytes, sufficient, steps}`
    + `ReclaimStep{sandbox_id, bytes, reason}`：确定性、可审计的回收计划。
  - `IdleReclaimer::plan(observations, target_bytes)` 规则：
    1. **保内存**：只从各沙盒申报的 `reclaimable_idle_bytes` 取，**绝不触碰
       reserved_bytes、绝不释放沙盒**（Waiting 沙盒状态槽位始终保留）。即使 target
       超过全部空闲页，缺口记为 `shortfall_bytes`，也不向保留内存伸手。
    2. **空闲优先排序**（键序，全部确定性）：`Waiting` 早于 `Running`；同为
       `Tolerant` 早于 `Sensitive`；`idle_ms` 大者优先；仍并列按 `sandbox_id`
       字典序。
    3. 贪心取 `min(剩余缺口, 该沙盒可回收)`，达到 target 即停（不多收）；`target=0`
       为合法空操作，返回空计划。
  - 校验（全类型化，复用并扩展 v3.7.4 `MemoryError`）：空 `sandbox_id` →
    `EmptySandboxId`；重复 id → 新增 `DuplicateIdleObservation(String)`。
- `ausec/mod.rs`：re-export 新类型；系统插件 `com.twinsearth.sys.ausec` 新增一个
  **只读、纯建议** PMB 方法：
  - `idle_reclaim_plan`：入参
    `{target_bytes, observations?:[SandboxIdleObservation]}`，返回 `ReclaimPlan`。
    `target_bytes` 缺失或非 u64 → 报错（fail-closed）；`observations` 缺省按空数组，
    空观测时安全返回 `sufficient=false / reclaimed=0 / shortfall=target`（无沙盒可回收，
    本身即安全结果，不报错）。
  - 配套字节桥 `handle_idle_reclaim` 与 `register` 注册，单一 dispatch 点接线。

## 二、测试（旧实现会失败的断言，8 新增）
- memory.rs 7 个：Waiting/空闲久者先于 Running/刚活动者回收；只回收申报空闲页、
  **绝不触碰保留内存**且不足额如实报 shortfall；target 达到即停、不多收；
  同状态/同类/同 idle 并列时按 id 字典序且两次计划逐字节相等（确定性）；
  跳过 0 空闲页且 target=0 为空操作；同状态下 Tolerant 先于 Sensitive；
  空 id / 重复 id 校验 fail-closed。
- mod.rs 1 个 PM 桥：`idle_reclaim_plan` 先收 Waiting/Tolerant 的 30 再从 Running
  收 90 足额、顺序与字节正确；保留内存场景只回收 30、缺口 70、`sufficient=false`；
  空观测返回不足额+全额缺口（不报错），缺 `target_bytes` 才报错。
- `cargo test --lib ausec` **63/0**；全量 gsn-core **33 组 0 failed**（lib 组
  415 passed）；`cargo fmt --check`、`cargo clippy --all-targets -D warnings` 干净；
  check-no-panics 生产 panic=0；check-unsafe-containment 全收容（仅 winjob.rs
  3 unsafe/3 SAFETY）；`cargo metadata --locked` 通过；npm 3.7.5 ↔ gsn-core 0.3.75。

## 三、诚实边界
- 本版交付的是**回收顺序/额度的纯决策**，**不是**真实的页回收：没有调用
  DAMON / balloon / virtio-mem / madvise(MADV_*) / cgroup memory.reclaim 等
  Linux-MicroVM 专有原语。这些原语按 AUSEC-DESIGN 在 **v3.7.6** 声明边界，并在
  macOS/Windows 等无对应原语平台**具名拒绝**（绝不静默声称已回收/已隔离）。
- 「等待期保内存」在本版的含义是：规划器**永不把 reserved_bytes 计入可回收、永不
  释放 Waiting 沙盒的槽位**；它是一条由代码强制执行的决策不变量，**不代表**内核在
  本版已经真正 pin 住这些物理页（真实锁定在后续小版本接线）。
- 所有 idle_ms / reserved / reclaimable 数值都由调用方提供，本模块据此确定性重算，
  不读 OS、不读时钟（注入式输入），便于在真正接线前做可复算、可测试的回收策略。
- 外部实测数字（约 90% 沙盒平均 CPU<5%、DAMON+balloon 使按时间累计内存再降 21.2%、
  资源超卖 50× 等）均来自 **aiwiki.ai / byteiota.com 对 DSEC 的报道，非本仓复测**；
  本版不声称在本仓复现这些降幅，见 `docs/ausec/AUSEC-DESIGN.md`。
- `idle_reclaim_plan` 是**无副作用建议**：返回的 steps 不代表内存已被回收；是否执行、
  如何执行由后续具备真实原语的版本决定。
