# v3.4.5 — A 类接地修复 + B1 主数据面编排接管 + B3 系统插件接线

v3.4.5 是 v3.4.2「全局审核版本」之后的**小版本（patch）**。本版按「先 A 类、再 B 类」推进：
先接地核实并修复 A 类（patch 接线），再把审计 §4 判定为 major 的三项核心架构性 gap 中的
**B1（主数据面接管）** 与 **B3（系统插件接线）** 落地；**B2（插件主动通信）** 留待 v3.5.0。

## 一、A 类接地核实：v3.4.2 §7「已知未修项」全部过时（更正）

接地核实（逐项 grep/读码）的结论：v3.4.2 审计 §7 所列三项**均已不适用**，本版据实更正：

| v3.4.2 §7 原称 | 接地核实结果 |
|---|---|
| node.rs/api.rs 约 8 处 `let _ = node.persist()` 丢弃持久化错误 | 整个 `gsn-core/src` **不存在任何 `persist` 方法或 `.persist(` 调用**（grep 零命中）。现存 `let _ =` 均为 relay 后台维护 fire-and-forget 与 oneshot reply。 |
| 结算仍按托管总额付款而非中标价 | **实际已在 v2.9.1（commit `6f6b842`，git blame 确认）修复**：`marketplace/mod.rs` 按 `winner_price.unwrap_or(budget)` 取 pay、`price.min(budget)`，从托管付 pay，预算超出部分退款。 |
| API token 无法表达标准 DID（冒号分隔冲突） | 现 REST 认证用单一 `REST_BEARER_TOKEN`，主体标识由 `extract_caller` 从 Bearer token 的 sha256 前 16 hex 派生 `sub:<hex>`，无多 token 列表，无该问题。 |

仍真实存在的项（属设计选择/诚实标注，非缺陷）：消息签名为对称 HMAC（不提供非对称来源证明）；
chain-anchor/bridge 为离线构造、无 RPC。

## 二、A 类实际修复（patch 接线）

- `marketplace/mod.rs` 顶部 import 区新增 `use serde_json::{json, Value};`，修复半成品遗留的
  8 个编译错误（集中在 `bids_for_plugin`/`routing_candidates_for_plugin` 等数据方法）。
- `api/market_actor.rs` 补齐 3 个公开 async 方法（仿 `ledger_snapshot` 的
  `self.call(|reply| MarketCommand::X{...})` 模式）：`bids_for_plugin`、
  `match_task_with_winner`、`reputation_dimensions`。

## 三、B1：主数据面编排接管（核心）

编排器从「只持有 PluginHost 的纯插件调用器」重写为**持有 market handle 的完整业务网关**：

- `PluginOrchestratorHandle { host: Arc<std::sync::Mutex<PluginHost>>, market: MarketActorHandle }`，
  `new(host, market)`，`#[derive(Clone)]`。
- 私有 `call_plugin`：全部工作在 `spawn_blocking` 闭包内完成（持 std Mutex，锁毒化
  `into_inner()` 并告警），`guard.call(...)` 后同闭包内 `serde_json` 解析。
- **6 个纯插件决策方法**：validate_card、discover_skill、route_task、match_bids、
  audit_ledger、reputation_overall。
- **3 个 gated 业务闸门（主数据面）**：
  - `register_agent_gated`：先 validate_card，valid 才 `market.register_agent`，否则 BAD_REQUEST。
  - `match_task_gated`：先 `market.bids_for_plugin` 取真实投标 → match_bids 取 winner →
    `market.match_task_with_winner`，winner None 时 CONFLICT。
  - `settle_task_gated`：先 `market.ledger_snapshot` → audit_ledger，passed 才
    `market.settle_task`，否则 CONFLICT。

**接线**：`rest.rs` 的 register/match/settle 三点改走
`Some(o) => o.<gated>` / `None => market.<old>`（Option 以便未构造编排器时优雅降级到单体
market，向后兼容）；`node.rs run_api_server` 在 listener 前构造编排器、每连接 clone 并传
`Some(&orchestrator)`；两处集成测试 route 调用补 `None`。

## 四、B3：系统插件接线

`system/mod.rs` 新增 `SystemHandles { store: Option<Arc<PersistentStore>>, peer_cmd_tx:
Option<PeerCmdTx> }`（`with_store`/`with_peer` 构造），以及 `block_on_net`（在同步处理器
中阻塞等待异步网络查询；handler 经 spawn_blocking 线程执行，不驱动 runtime，不会自死锁）。
4 个 T0 系统插件真实接线：

| 系统插件 | 真实方法（句柄存在时注册） |
|---|---|
| SYS_IDENTITY | 保持现有 mint_did / parse_did / fingerprint |
| SYS_NET | status + **peer_info（GetInfo）、list_peers（ListPeers）、nat_status（NatStatus，不猜测）** |
| SYS_STORAGE | status + **stats（各表计数）、list_agents、list_tasks** |
| SYS_CHAIN | status（`rpc:"offline"` 诚实标注）+ **record_anchor、list_anchors（kv_meta: chain_anchors）** |

`host.boot_system(handles)` 改签名接收 SystemHandles；`run_daemon` 在 PluginHost 创建前
构造真实句柄（`with_store(store).with_peer(peer_cmd_tx)`）；所有测试调用点同步。

## 五、版本语义偏离说明

v3.4.2 审计版本语义规定「大版本=架构重构、中版本=新功能插件化、小版本=只更新独立插件」，
B 类（尤其 B1/B3）被显式判为 major、应走 v4.0.0。经明确指令，本版选择在 **v3.4.5（patch）**
推进 B1/B3、在 v3.5.0（minor）推进 B2。**指令优先于审计判定**；本版据此说明偏离，并保留
B1/B3 在 v3.4.2 报告中的 major 判定记录，不抹除。

## 八、诚实边界与后续

- B2（进程插件主动通信）尚未实现，v3.5.0 以 outbox 模式落地。
- 消息签名为对称 HMAC；chain-anchor/bridge 为离线构造（无 RPC）。
- 编排器以 Option 接线，未构造时降级到单体 market（保留向后兼容）。

## 九、结论

v3.4.5 让插件从「并行承载」走向**接管主数据面**：register/match/settle 三个核心业务动作
已由「插件决策 → 宿主应用」的编排器把关；SYS_NET/STORAGE/CHAIN 三个系统插件真实接线。
v3.5.0 将补齐进程插件的主动通信能力。
