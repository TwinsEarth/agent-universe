# v2.8.2 — macOS CI 修复（Rust 原生超时，去外部 timeout/gtimeout）

修复 main 分支 `.github/workflows/ci.yml` 中 `rust-test` 的 `macos-latest`
Test step 失败：`gsn-core/tests/v277_test.rs` 6 个 exec 类测试在 macOS FAILED。

## 根因

- **macOS runner 无 GNU `timeout`**（只有 coreutils 的 `gtimeout`），而
  `process.rs` 硬编码 `timeout -k 1 N bash -c ...`；
  命令找不到 → exec 失败 → 6 个测试 FAILED：
  - `v277_run_python_hello`、`v277_run_javascript_hello`、
    `v277_python_compute_result`、`v277_nonzero_exit_reported`、
    `v277_shell_allowed_when_configured`（bash 内找不到 `timeout`）；
  - `v277_timeout_kills_long_running`（无 timeout 强杀 → 返回 Ok，
    断言期望 `Err(ResourceLimitExceeded)` 失败）。
- Ubuntu runner 自带 GNU coreutils 的 `timeout`，故 Ubuntu 全绿——
  这是典型的平台差异，不是逻辑错误。

## 修复：Rust 原生超时（不依赖任何外部 timeout/gtimeout）

- `exec` 改为 `spawn`：
  - `stdout` / `stderr` 各 `Stdio::piped()`，用两个独立线程
    `read_to_end`（防止管道写满后子进程阻塞）；
  - 主线程 `try_wait` 轮询（10ms）；
  - 超时则 `child.kill()` + `child.wait()` + join 两个读线程后返回
    `Err(SandboxError::ResourceLimitExceeded{kind:"timeout",limit,actual})`；
  - 正常退出 join 读线程，取 stdout/stderr，`exit_code=status.code().unwrap_or(-1)`。
- `build_platform_command` 拆为两版：
  - `#[cfg(not(windows))]`（Linux/macOS）：保留
    `bash -c 'ulimit -u N; ulimit -n N; exec <prog> <args>'`
    （bash 与 ulimit 内建 macOS 均有），`exec` 替换 bash 为目标程序后
    最终只有一个进程（pid 即 bash），Rust 侧 kill 该 pid 无孤儿；
  - `#[cfg(target_os="windows")]`：直接 spawn 解释器，不套 shell。
- 该方案同时包含 v2.8.1 的 Windows 修复（直接 spawn，Python 解释器
  按平台选 `python`/`python3`）。

## 版本一致性补强

- `scripts/check-version.sh` 新增 `ci.yml 版本断言`：
  断言 ci.yml 里 js-test 硬编码的 `au.version!=='X.Y.Z'` 与 VERSION 一致，
  防止 bump 时漏改导致 js-test 红。
- `scripts/bump-version.sh` 已含 ci.yml 的 sed 规则（`au.version!=='$V'`）。

  - `cargo test` 全量 ✅，v277 17 项全过（含 6 个原 macOS 失败的 exec 测试、
