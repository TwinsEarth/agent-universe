# v2.8.3 — 账本日志哈希链（tamper-evident）+ 水位/吞错/恢复失败修复

对应《v2.8.2 增量审计 / Gap Analysis》**§3.1【critical】、§3.6**：
v2.8.2 的 `ledger_entries` 表只有 `(seq, payload)`，**没有哈希链、没有签名、
没有校验和、没有约束**。任何能写数据库文件的人（或未来的 bug）插入一条
`Deposited`，`SettlementEngine::restore` 与 `independent_audit` 都会报告
`passed / conserved = true`——凭空的货币被判定为守恒，使「守恒」与「独立审计」
同时失效。同时 §3.6 指出水位用物理 `COUNT(*)`（含损坏行）、写入失败被
`let _ =` 吞掉、恢复失败永久关闭持久化三个缺陷。

## 根因

- 审计信任根是「只追加、不可变的日志」，但旧表的不可变性只建立在
  「假设文件没被动过」上，没有任何密码学手段能检测对存量行的篡改。
- 旧 `load_ledger_records` 对解析失败的行**静默跳过**，而初始水位
  `ledger_water = ledger_count()`（物理 `COUNT(*)`，含损坏行）。一行损坏
  就让水位永久超前于可解析列表 → 之后的写入落在错误切片或不写 →
  账本出现静默、永久空洞，而 API 一直返回 200。
- 旧写后持久化 `let _ = store.append_ledger_record(r)` 吞掉磁盘/锁错误，
  紧接着 `ledger_water = records.len()` 照涨 → 该笔资金变动永久丢失。

## 修复

### 1. 哈希链 + 锚定 head（§3.1，只声称 tamper-evident，非 tamper-proof）

- `ledger_entries` 加两列：`prev_hash TEXT`、`record_hash TEXT`。
- `record_hash = SHA256(prev_hash || "|" || payload)`，首条 `prev_hash`
  为创世空串；每条的 `prev_hash` 指向上一条 `record_hash`。
- head 同时锚定到 `kv_meta`（键 `ledger_head_hash`）。
- 新增 `verify_ledger_chain() -> Result<head, u64>`：按序重算，报**首个
  断链 seq**；锚定 head 与链末不符用 `u64::MAX`。
- 旧库迁移 `migrate_ledger_chain()`：检测 `record_hash` 列，缺失则
  `ALTER TABLE ADD COLUMN` 并按 seq 重算存量行；幂等。
- 启动时 `spawn_with_store` 先校验链，断链即打印 `🚨 CRITICAL`（容错
  加载并提示人工核查）。

### 2. 水位 / 吞错 / 恢复失败（§3.6）

- 新增 `load_ledger_records_checked() -> LedgerLoad { records, corrupt }`，
  损坏行 `(seq, payload, reason)` 显式返回，**不再静默跳过**；启动恢复时
  逐条 `eprintln!` 报告。
- 初始水位 = 成功恢复的**逻辑记录数** `restored`，不再用物理 `COUNT(*)`。
- 写后持久化改为**逐条** append：成功才 `ledger_water += 1`；失败
  `eprintln!` 并停在该水位，下轮重试（不会重复已成功的行、不丢该笔）。
- 账本读取失败时明确进入持久化降级路径，避免水位错位。

> 边界说明：能重写整份数据库文件的人仍可重算整条链并更新锚定 head，
> 本方案只保证 **tamper-evident（篡改可被发现）**，不保证
> tamper-proof。

## 验证

- 新增对抗测试（旧无哈希链代码上无法通过 / 方法不存在）：
  - `ledger_hash_chain_verifies_after_appends_and_reopen`：3 条 append 链
    通过、重开后 head 一致；
  - `ledger_chain_detects_payload_tampering`：UPDATE 第 1 条 payload →
    `verify = Err(1)`；
  - `ledger_chain_detects_head_anchor_tampering`：篡改 kv_meta head →
    `verify = Err(u64::MAX)`；
  - `ledger_append_load_and_reports_corrupt`：坏行进入 `corrupt` 且让
    链校验失败。
- `cargo test --lib ledger`：6 passed / 0 failed。
