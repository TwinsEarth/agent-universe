# v3.9.3 — 比特币/以太坊 Agent 经济体（4/9）：L402 / 比特币闪电网络纯协议内核（402 challenge 头解析 + BOLT11 人类可读金额前缀整数解析 + preimage/payment_hash SHA256 关系与精确金额守恒；只校验不连节点，生产默认 L402_LIGHTNING_NOT_CONFIGURED fail-closed，不持钥 / 不签 HTLC / 不解 bech32 数据段 / 不校 macaroon 签名）

## 一、交付了什么

v3.9.0 决定「即时高频微支付走闪电 L402 轨道」，v3.9.1 立好「签名是宿主能力」的边界，
v3.9.2 落地了 EVM x402 纯协议面。v3.9.3 把**闪电 L402 上沙盒可以安全做的纯协议部分**
落地：解析 HTTP 402 `WWW-Authenticate: L402 …` 挑战头、解析 BOLT11 发票**人类可读金额
前缀**为整数 msat、校验客户端提交的 preimage 与受信任 payment_hash 的 SHA256 关系、做
精确金额守恒，并据此生成重放用的 `Authorization` 头。本版本**不引入任何新 crate**
（仅复用仓内已有的 `sha2 0.10` 与 `hex 0.4`，仓内无 lightning/ldk/secp/bech32 依赖）；
不连接任何闪电节点、不发起或结算 HTLC、不持私钥、不签名、不广播、不划转、不解码
BOLT11 的 bech32 数据段、不校验 macaroon 签名。

新增文件 `gsn-core/src/economy/payment/l402.rs`，并扩展 `payment/mod.rs` 与
`plugin/system/mod.rs`。复用 v3.9.0 的 `PaymentTrack::LightningL402` 轨道枚举，不改
router.rs；复用 v3.9.1 的宿主签名闸门，不改 signer.rs；与 v3.9.2 的 x402.rs 并列、互不
改动。

1. **挑战头解析 `L402Challenge::parse_www_authenticate`**：解析
   `L402 macaroon="…", invoice="lnbc…"`（RFC 7235 auth-scheme 大小写不敏感）；
   `macaroon` / `invoice` 参数顺序允许互换；值必须双引号包裹；**尊重引号内逗号**
   （不会在 base64url/发票串里的逗号处误切）；容忍多余空白；忽略未知参数；缺参数、
   值未加引号、空 macaroon/invoice、scheme 不符一律具名拒绝。macaroon 作为**不透明
   字符串**原样透传，不解释 caveat、不校验其 HMAC 签名（那需要服务端 root key）。

2. **BOLT11 金额前缀整数解析 `parse_bolt11_amount_msat`**：只解析
   `ln(bc|tb|bcrt)<amount><multiplier?>` 的**人类可读前缀，绝不触碰 bech32 数据段**
   （数据段含节点签名与真正的 payment_hash）。支持 `lightning:` URI 前缀（大小写不敏感）
   与 lnbc/lntb/lnbcrt 三网络。以 1 BTC = 100 000 000 000 msat 为基准的整数乘数：
   省略或数字后紧跟 m/u/n/p 之外任意字符（典型为 bech32 数据段字符 p/q/x）按**整 BTC**
   计；`m`=1e8、`u`=1e5、`n`=1e2、`p`=amount/10（pico-BTC 必须为 10 的整数倍，否则
   `L402_SUB_MSAT_AMOUNT`，不产生亚 msat）。全程 u128 中间运算再 `try_into` u64，溢出
   具名 `L402_AMOUNT_OVERFLOW`；省略金额的发票（无法精确守恒）具名
   `L402_INVALID_AMOUNT`。零浮点。

3. **原像/哈希值类型 `PaymentHash([u8;32])` / `Preimage([u8;32])`**：`0x` 可选前缀
   hex 解析严格校验长度与字符（坏输入返回 `None`，生产路径不 panic）；
   `Preimage::payment_hash()` 按 BOLT 用**标准 SHA-256（非 keccak）**求哈希。

4. **凭证构造与校验 `L402Credential`**：`new(challenge, preimage_hex)` 校验 preimage
   为 32 字节 hex；`to_authorization_header()` 生成
   `L402 <macaroon>:<preimage_hex>` 重放头；`verify(challenge, expected_hash, paid_msat)`
   三重校验——① macaroon 与挑战一致（防票据替换 `L402_MACAROON_MISMATCH`）；
   ② `SHA256(preimage) == expected_hash`（未支付/伪造原像
   `L402_PREIMAGE_HASH_MISMATCH`）；③ 发票金额与实付**精确相等**
   （`verify_settlement`，多付/少付一律 `L402_SETTLEMENT_MISMATCH`，不静默接受差额）。

5. **L402 错误枚举 `L402Error`（10 变体）**：全部实现稳定 `L402_*` Display 码与
   `std::error::Error`，生产路径无 panic：MALFORMED_CHALLENGE / MISSING_PARAM /
   MACAROON_MISMATCH / UNSUPPORTED_INVOICE_NETWORK / INVALID_AMOUNT / SUB_MSAT_AMOUNT /
   AMOUNT_OVERFLOW / INVALID_PREIMAGE / PREIMAGE_HASH_MISMATCH / SETTLEMENT_MISMATCH。

6. **闪电执行 fail-closed**：本版本不内置任何闪电节点后端，`l402_pay` 对任何请求
   （含空/坏负载）一律返回 `L402_LIGHTNING_NOT_CONFIGURED` 具名拒绝，**绝不伪造支付、
   绝不构造或广播 HTLC**。真实支付需宿主在装配处注入受信任闪电节点/发票解码后端
   （独立能力闸门，与 v3.9.1/v3.9.2 同一隔离原则）。

7. **PMB 字节桥**（同一 T0 系统插件 `com.twinsearth.sys.payment-router`）：新注册
   `l402_parse_challenge` / `l402_verify`（只读）与 `l402_pay`（fail-closed），连原
   v3.9.0–v3.9.2 共 10 个 handler；`payment_router_status` 增 `l402_introduced_in=v3.9.3`
   与 `l402` 诚实块（`payment_hash=标准 SHA256 非 keccak`、
   `bolt11_bech32_data_decoded=false`、`macaroon_signature_verified=false`、
   `l402_pay_fail_closed=true`、`exact_settlement_conservation=true`、
   `lightning_node_connection=false`、`htlc_creation_or_settlement=false`、
   `live_settlement=false`），`enforceable` 增 `l402_exact_amount_conservation=true` 与
   `fail_closed_when_lightning_not_configured=true`，`provided` 增三个 l402 位；
   `capabilities_declared` 由 3 增至 4（加 `l402:protocol:read`）。

8. **黑名单环境变量测试 flake 根治**（`plugin/host.rs`，仅测试代码）：两个都读写进程级
   `GSN_BLACKLIST_FILE` 环境变量的测试此前在 cargo 默认多线程下可能交叉调度产生时序
   flake（CI 已观测）。新增进程内 `static BLACKLIST_ENV_LOCK: Mutex<()>`，两用例各自在
   操作环境变量前取锁、用完显式 `drop`，把它们串行化。**生产函数
   `seed_blacklist_from_env` 未做任何改动**（生产启动时单线程只读一次环境变量）。

内核仍零浮点、零 syscall、零 unsafe、无生产 panic；不连任何闪电节点、不持钥、不签
HTLC、不广播、不划转、不持久化、不解码 bech32 数据段。

版本映射：npm `@twinsearth/agent-universe` 3.9.3 ↔ Rust `gsn-core`/`gsn-daemon` 0.3.93。

## 三、诚实边界（做不到的具名拒绝）

- 本版本交付的是 **L402 纯协议内核（头解析 / 金额前缀 / 原像哈希 / 守恒）**，不是真网
  资金面：不连闪电节点、不发起或结算 HTLC、不持私钥、不签名、不广播、不划转；
  `l402_pay` 因无闪电后端一律具名 `L402_LIGHTNING_NOT_CONFIGURED` 拒，绝不伪造支付。
- **payment_hash 必须来自受信任来源**：BOLT11 的 bech32 数据段（内含节点签名与真实
  payment_hash）本版本**不解码**。调用方须经受信任闪电节点/发票解码服务取得 32 字节
  payment_hash 后传入 `l402_verify`；内核只在「给定可信 hash」前提下校验 preimage 关系。
- **不校验 macaroon 签名**：macaroon 是不透明串，其 caveat/有效期/HMAC 需服务端 root
  key，本版本只做「凭证 macaroon 与挑战一致」的票据替换检查，不声称已授权 caveat。
- preimage 校验是**本地密码学关系判定**，不代表 HTLC 已在闪电路由层最终确认/上链；
  本版本不做链上/路由回执查询。
- ERC-8004 三注册表在 **v3.9.4**；ERC-4337 Paymaster 在 **v3.9.5**；BTC HTLC/RGB
  纯校验在 **v3.9.6**；链上锚定/跨链桥风控在 **v3.9.7**；ZK 支付意图/OWS/合规接口在
  **v3.9.8**。在对应版本落地前这些方法不注册（NotFound）或只提供决策/校验面，不伪造
  真网可用。
- 文档中涉及的外部协议采用量/费率数字（闪电网络采用、x402/L402 交易量、BlackRock
  模型占比等）均为**第三方报道口径，非本仓复测**，内核不内置这些数字作为事实。
