# v3.9.8 — 比特币/以太坊 Agent 经济体（9/9）：ZK 隐私支付意图 + OWS 统一钱包轨道路由 + 合规筛查的纯链下确定性决策（承诺/空值符 32B hex 形状 + u128 checked 信用额度 + 披露标签白名单 + 宿主取证双花；stable→evm_x402_stable、btc 即时→闪电再 RGB、btc 非即时→RGB 再闪电的确定性选轨 + 配置/隐私/跨链约束 fail-closed；调用方名单/辖区/整数阈值 allow/report_required/blocked；只做链下 fail-closed 决策，不验 SNARK/zkML、不持钥不签名、不连名单/链/合规 API、不冻结不上报不广播）

## 一、交付了什么

v3.9.0–v3.9.7 已立「只决策不动钱」的结算路由、宿主签名闸门、EVM x402、闪电 L402、
ERC-8004、ERC-4337 Paymaster、BTC HTLC/RGB 纯校验面，以及链上锚定最终性与跨链桥风控。
v3.9.8 作为 v3.9.x 小版本序列的收尾，补齐 Agent 经济体在「把支付真正推向隐私化、多轨道
统一钱包化、合规化」时必须先在链下回答的三个确定性问题：**一笔隐私支付意图在结构/额度/
双花/披露层面是否自洽（ZK 意图）**、**一笔归一化支付该选哪条已配置且满足隐私与跨链要求
的钱包轨道（OWS 选轨）**、**一笔面向某地址/辖区/金额的支付在调用方名单与阈值下应放行、
上报还是阻断（合规筛查）**。

三者都是**只对调用方取证后传入的策略与快照做整数/结构决策**的独立纯函数：不联网、不读
时钟、不持久化、不持钥、不签名、不广播、不真转资产；任何门槛不满足都具名 fail-closed，
绝不返回「带警告的通过」。本版本**不引入任何新 crate**（仅 std + 仓内既有 serde）；零
浮点、零 syscall、零 unsafe、无 IO、无生产 panic；金额全部 u128、checked 整数运算。

新增文件 `gsn-core/src/economy/payment/zkwallet.rs`，并扩展 `payment/mod.rs` 与
`plugin/system/mod.rs`。不改 router.rs（3.9.0）、signer.rs（3.9.1）、x402.rs（3.9.2）、
l402.rs（3.9.3）、erc8004.rs（3.9.4）、paymaster.rs（3.9.5）、htlc.rs/rgb.rs（3.9.6）、
anchorguard.rs（3.9.7），与它们并列、互不改动。

1. **ZK 隐私支付意图决策 `verify_zk_payment_intent(policy, intent)`**：严格短路顺序——
   - `chain` 非空（`ZK_BAD_CHAIN`）、`asset` 非空（`ZK_BAD_ASSET`）、`spend_micro > 0`
     （`ZK_NON_POSITIVE_SPEND`）。
   - 承诺与空值符按 `norm_hex32` 规范化：剥除可选 `0x`/`0X`，须恰好 32 字节（64 hex），
     非法 `ZK_BAD_HEX`；回执回显小写规范形式。
   - 选择性披露标签逐项必须在确定性白名单
     `["none","payee","amount_range","jurisdiction"]` 内，否则
     `ZK_DISCLOSURE_TAG_NOT_ALLOWED`。
   - **双花优先于额度**：`block_seen_nullifier=true` 且宿主取证 `nullifier_seen=true`
     一律 `ZK_NULLIFIER_DOUBLE_SPEND`（是否已见过同一空值符由受信任宿主取证，内核不自行
     查重）。
   - u128 信用额度 `credit_used_prior + spend` 走 checked_add（溢出
     `ZK_ARITHMETIC_OVERFLOW`），投影后 `> credit_line` 即 `ZK_EXCEEDS_CREDIT_LINE`，
     **恰好花完允许**。
   - 策略 `require_proof_present=true` 时要求 `proof_present=true`，否则
     `ZK_PROOF_REQUIRED_BUT_ABSENT`（**只看证明是否随附，绝不验证其密码学有效性**）。
   - 回执 `ZkReceipt` 恒 `proof_verified=false`、`zk_proof_verification_implemented=false`、
     `key_or_proof_materialized_in_kernel=false`、`external_verifier_connection=false`；
     `privacy_ready=true` 仅表结构/额度/空值符/披露标签自洽且按需随附证明，**不代表零
     知识证明在密码学上成立**。
   - `verify_zk_proof()` 本版本无任何 SNARK/zkML 验证后端，恒
     `ZK_PROOF_VERIFICATION_NOT_IMPLEMENTED`，且**不注册为 PMB handler**。

2. **OWS 统一钱包选轨决策 `route_ows_wallet(policy, caps, intent)`**：确定性优先序——
   - 总开关 `enabled=false` → `OWS_DISABLED`；`amount_micro=0` → `OWS_NON_POSITIVE_AMOUNT`。
   - `allowed_tracks` **为空默认全拒** `OWS_NO_TRACK_ALLOWED`；白名单或能力快照中出现
     未知轨道名 → `OWS_BAD_POLICY`（脏数据具名拒，不放行）。
   - 资产族 → 优先序：`stable` → [`evm_x402_stable`]；`btc` 且 `instant` →
     [`btc_lightning`,`btc_rgb_htlc`]；`btc` 非即时 → [`btc_rgb_htlc`,`btc_lightning`]；
     未知资产族 `OWS_UNKNOWN_ASSET_FAMILY`。
   - 在「宿主白名单 ∩ 已声明能力快照」交集中，按优先序取首个同时满足 `require_configured`
     下 `configured`、`privacy_required` 下 `privacy`、`cross_chain_required` 下
     `cross_chain` 的轨道；缺能力快照或任一约束不满足即跳过，全部不满足
     `OWS_NO_AVAILABLE_TRACK`（fail-closed）。
   - 回执 `OwsRoute` 回显选中轨道及其配置/隐私/跨链快照，恒
     `key_held_in_sandbox=false`、`wallet_execute_executed=false`。
   - `execute_ows_payment()` 本版本无统一钱包后端，恒 `OWS_WALLET_NOT_CONFIGURED`，
     **不持私钥、不签名、不连接钱包/节点、不广播**，且不注册为 PMB handler。

3. **合规筛查决策 `screen_compliance(policy, subject)`**：仅依据**调用方显式提供**的名单
   与整数阈值——
   - `enabled=false` → `COMPLIANCE_SCREENING_DISABLED`；辖区非空
     （`COMPLIANCE_BAD_JURISDICTION`）；`amount_micro>0`（`COMPLIANCE_NON_POSITIVE_AMOUNT`）。
   - 地址按族归一化：`evm` 去空白与 `0x`/`0X` 后须恰好 20 字节（40 hex）小写
     （`COMPLIANCE_BAD_EVM_ADDRESS`）；`other` 去首尾空白且非空（`COMPLIANCE_BAD_ADDRESS`）；
     未知 kind `COMPLIANCE_BAD_ADDRESS_KIND`。策略里的阻断地址按同一规则归一化，**策略自身
     脏数据也具名拒绝而非放行**。
   - 裁决短路：地址名单命中 → `blocked`（address_blocklisted）；阻断辖区精确命中 →
     `blocked`；`require_allowed_jurisdiction=true` 时辖区不在允许名单 → `blocked`
     （jurisdiction_not_allowed，**允许名单为空默认全拒**）；金额 ≥ 硬阻断阈值（含边界，
     0 关闭）→ `blocked`；金额 ≥ 上报阈值（含边界，0 关闭）→ `report_required`；否则
     `allow`。
   - 回执 `ScreeningDecision` 恒 `enforcement_executed=false`、
     `external_list_connection=false`、`list_provided_by_caller=true`。
   - `enforce_compliance_decision()` 不冻结、不上报、不执行任何外部动作，恒
     `COMPLIANCE_ENFORCEMENT_NOT_CONFIGURED`，且不注册为 PMB handler。

4. **PMB 字节桥**（同一 T0 系统插件 `com.twinsearth.sys.payment-router`）：新注册
   `zk_payment_intent_check` / `ows_wallet_route` / `compliance_screen` 三个**决策类**
   handler；三个执行/验证类方法（`zk_proof_verify`、`ows_wallet_execute`、
   `compliance_enforce`）本版本**有意不注册**（NotFound），不伪造真网可用。三个请求体
   `ZkIntentRequest{policy,intent}`、`OwsRouteRequest{policy,capabilities,intent}`、
   `ComplianceScreenRequest{policy,subject}` 均 serde 反序列化，空/坏负载一律运行时拒绝不
   panic。`payment_router_status` 增 `zk_payment` / `ows_wallet` / `compliance` 三段完整
   诚实块与 `zk_payment_introduced_in` / `ows_wallet_introduced_in` /
   `compliance_introduced_in = v3.9.8`；`enforceable` 增 zk_integer_checked_credit_line /
   zk_nullifier_double_spend_enforced / zk_disclosure_tag_whitelist /
   zk_snark_verification_honestly_not_claimed / ows_deterministic_track_routing /
   ows_fail_closed_when_no_configured_track / ows_privacy_crosschain_constraints_enforced /
   compliance_integer_thresholds / compliance_lists_caller_provided_fail_closed /
   compliance_allowed_jurisdiction_empty_denies /
   compliance_enforcement_not_configured_fail_closed 等布尔位；`provided` 增
   zk_payment_intent_check / ows_wallet_route / compliance_screen 三 true，与
   zk_proof_verify / ows_wallet_execute / compliance_enforce 三 false，以及
   zk_external_verifier_connection / zk_recursive_snark_verify /
   ows_wallet_or_node_connection / compliance_external_list_connection 等 false 诚实位。
   `capabilities_declared` 由 10 增至 **13**（加 `zk:payment-intent:decide`、
   `ows:wallet:route`、`compliance:screen:decide`），`capabilities_reserved_later` 由 10
   增至 **14**（追加 `zk:proof:verify`、`ows:wallet:execute`、`compliance:list:fetch`、
   `compliance:enforce`）。

内核仍零浮点、零 syscall、零 unsafe、无生产 panic、无 IO；不连任何 ZK 验证器/钱包/节点/
名单或合规 API；承诺/空值符 hex、信用额度、双花标志、轨道能力快照、地址/辖区名单与阈值
全部由调用方取证后显式传入，保持纯函数可复算、可审计。

版本映射：npm `@twinsearth/agent-universe` 3.9.8 ↔ Rust `gsn-core`/`gsn-daemon` 0.3.98。

## 三、诚实边界（做不到的具名拒绝）

- 本版本交付的是 **ZK 隐私意图 / OWS 统一钱包选轨 / 合规筛查的纯链下确定性整数与结构决策
  内核**，不是 ZK 证明系统、钱包后端或合规定阅服务：不验证递归 SNARK / zkML 证明，不连接
  任何外部证明器，不持有或接触私钥/证明材料，不连接钱包/节点/链，不连接制裁或合规名单
  API。
- `privacy_ready=true` 只表示**调用方提供的意图在结构/额度/空值符/披露标签上自洽且按策略
  随附了证明字节**，绝不表示零知识证明在密码学上成立；`proof_verified` 与
  `zk_proof_verification_implemented` 恒为 false，`verify_zk_proof` 永远
  ZK_PROOF_VERIFICATION_NOT_IMPLEMENTED。
- **双花与轨道能力均靠宿主取证**：空值符是否已出现、某轨道是否真已配置/具备隐私与跨链
  能力，由受信任宿主以布尔标志与能力快照传入；内核不查重、不探测真实钱包、不持久化。
- **OWS 选轨只是决策**：`selected_track` 不代表钱包已执行；`execute_ows_payment` 一律
  OWS_WALLET_NOT_CONFIGURED。真实支付须由宿主在后续版本经独立闸门授权并持钥签名。
- **合规名单完全由调用方提供**：内核不内置任何国家/地址黑名单，不联网拉取名单，不解释
  法律含义；阈值只是宿主策略整数常量。筛查通过不代表合法，阻断/上报也不构成法律意见。
  `enforce_compliance_decision` 不冻结、不上报，恒 COMPLIANCE_ENFORCEMENT_NOT_CONFIGURED。
- 三个执行/外部类方法（zk_proof_verify / ows_wallet_execute / compliance_enforce）本版本
  **不注册**（PMB NotFound），落地前不伪造真网可用。
- 文档涉及的外部协议/生态数字（Vitalik ZK 支付标准、OWS 与 20 家机构贡献、x402/L402
  规模、BlackRock 79.1%/53.2%/20%、ERC-8004 采用量、稳定币规模、GENIUS Act 时点等）均
  为 **第三方报道口径，非本仓复测**，内核不内置这些数字作为事实。
