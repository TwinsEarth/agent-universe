# v3.8.8 — 面向 Agent 的资源市场（9/10）：BFT-lite QA 抽样验证（n≥3f+1、2f+1 诚实超多数、equivocation 整轮作废，把入参评分升级为可验证信誉）

## 一、交付了什么

资源市场到 v3.8.7 已有「容量→计量→撮合→质押→托管结算→快照版税→四维信誉」的完整
记账链，但 v3.8.7 的信誉分**仍是买方的入参**——刷好评、女巫号堆量、供需合谋抬分都
能污染信誉，进而污染撮合优先级与后续定价权。v3.8.8 在「结算 / 信誉」之前加一道
**可验证质量门**：对（抽样到的）订单结果组织一轮 BFT-lite 验证，只有拿到诚实超多数
背书的结果才允许进入结算与信誉；出现 equivocation（同一验证者为不同结果背书）则
**整轮作废**，不结算、不记信誉，只留下证据供 v3.8.4 质押罚没后续联动。

新增文件 `gsn-core/src/economy/resource/qa.rs`。纯确定性内存裁决面：零浮点、零
syscall、零 unsafe、无 panic 路径，全整数计数。

容错与阈值（经典 BFT-lite 参数，整数恒等式）：

- 验证者总数必须满足 `n ≥ 3f+1`（`QaRound::required_validators`），`f` 为可容忍的最大
  拜占庭（恶意/失效）验证者数；
- 结果确认与否决都需要 `2f+1` 的诚实超多数（`QaRound::approval_threshold`）。当
  `n≥3f+1` 时赞成与否决不可能同时达到 `2f+1`，超多数唯一，裁决无歧义；
- `3f+1`/`2f+1` 全部 checked 计算，使阈值溢出的 `f`（如 `u64::MAX`）fail-closed。

投票模型（`QaVote{validator_did, observed_digest}`）：每个验证者提交自己本地重算得到
的结果摘要，摘要 == 被验证答案 `claimed_digest` 计赞成，否则计异议。

- 同一验证者重复提交**相同**摘要：幂等，只计一票（防重复堆票，`cast` 返回 `false`）；
- 同一验证者提交**不同**摘要（同时为不同结果背书，典型双签 equivocation）：登记为
  equivocator（保序去重），该轮立即作废；之后该验证者再投任何票都不改变作废结果；
- 空轮 id / 空被验证摘要 / 空验证者 / 空观察摘要全部 fail-closed，拒绝且不计票。

裁决 `QaRound::adjudicate`（可重复调用、不改状态）返回五种之一：

1. 存在任一 equivocator → `EquivocationVoid{equivocators}`：**整轮丢弃**，不结算不记信誉；
2. 有效验证者 `n < 3f+1` → `Pending{n,required}`：样本不足不能确认（全赞成也不行）；
3. 赞成 `≥ 2f+1` → `Verified{approvals,dissents,threshold}`；
4. 异议 `≥ 2f+1` → `Rejected{..}`；
5. 两者都不足 → `NoSupermajority{..}`（分裂，本轮无结论，需补样/重抽）。

核心 API：`QaRound::new(round_id, claimed_digest, f)`、`cast(QaVote)`、
`validator_count/approvals/dissents/equivocators/is_void`、`adjudicate`、
`required_validators/approval_threshold`、`invariant_holds`。`ResourceError` 新增 4 变体
（`EmptyQaRoundId`/`EmptyQaDigest`/`EmptyQaValidator`/`QaFaultToleranceOverflow{f}`），
复用既有 `ArithmeticOverflow`（不新增溢出变体），并在手写 `fmt::Display` 中补对应
`RESOURCE_*` 文案。

系统插件状态 `resource_market_status` 增加诚实位：`enforceable.bft_lite_qa = true`，
`provided.qa_round_persistence = false`；不新增能力令牌、不经 PMB 受理外部写。
`plugin/system/mod.rs` 快照测试断言 `bft_lite_qa == true`。

## 二、测试

`qa.rs` 新增 **8** 个单元测试（全量 `cargo test --lib` = **526 passed / 0 failed**，
518→526）：

1. `honest_supermajority_verifies`：f=1、n=4，3 赞成 1 异议 → Verified（阈值 3）。
2. `insufficient_validators_stays_pending`：f=1 需 4，仅 3 票全赞成仍 Pending。
3. `exact_threshold_split_no_supermajority`：f=1、n=4，恰 2:2 → NoSupermajority。
4. `equivocation_vectors_entire_round`：一验证者先投 claimed 再投另一摘要 → 整轮作废，
   即便其余 3 票全赞成；作废后再投不改变，equivocator 去重。
5. `duplicate_same_vote_is_idempotent`：同验证者同摘要重复不堆票（计数恒为 1）。
6. `dissenting_supermajority_rejects`：f=1、n=4，1 赞成 3 异议 → Rejected。
7. `f_zero_single_validator_and_empty_round`：f=0 需 1、阈值 1，单验证者即可确认/否决；
   空轮 Pending。
8. `empty_fields_rejected_and_threshold_math_checked`：空字段三类 fail-closed 不落票；
   逐点核对 (f→3f+1,2f+1)=(0→1,1)(1→4,3)(2→7,5)(3→10,7)；f=2、n=7 恰 5 赞成
   Verified；致阈值溢出的 `u64::MAX` 返回 `QaFaultToleranceOverflow`。

`invariant_holds` 独立复核：投票验证者唯一、赞成+异议==去重验证者数、equivocator
去重，且裁决与一条独立重算路径逐态一致。

## 三、诚实边界（做不到的具名拒绝）

- **只是确定性裁决内核，不是真实抽样/验证网络**：本轮不选举验证者、不抽样子集、不发起
  重算任务、不接入 PMB 调度，调用方传入的投票即事实；防刷分/女巫/合谋只是**规则面**——
  规则保证「诚实超多数才确认、equivocation 整轮作废」，但验证者从哪来、是否真独立、
  是否真重算，属后续版本（验证者采样与身份去 Sybil）范围。
- **不自动罚没、不联动 v3.8.4 质押**：`EquivocationVoid` 只产出 equivocator 证据名单，
  不调用 StakeLedger 扣质押；证据→罚没的闭环在后续小版本接线，本轮不伪造已生效。
- **不自动驱动结算/信誉**：Verified 只是「允许进入」的判定结果，不修改 EscrowLedger /
  ReputationLedger，不自动结算或写信誉分。
- **内存态、不持久化、不连链**：QA 轮不入库、进程结束即失；不上链、不锚定、不做
  BFT-lite 之外的密码学验证（TEE/zkML 验证器属 v3.9.x 及以后）。
- 阈值参数 `f` 由调用方提供，本轮不校验验证者身份是否与信誉/质押绑定。
